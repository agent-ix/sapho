# FR-088: Translate typed Ask readings to Claude Messages

## Description

When a checked `ModelRequest` uses a Claude binding, the adapter SHALL send one nonstreaming structured-output Messages request and decode the response into the unchanged core `ModelResponse` semantics.

## Inputs

A core request with Record state, explicit nonempty host-selected model, 1..16 ordered named Boolean, Choice or Score questions, at most 16 options or levels per question, and explicit DistributionPolicy. Request validation and size checks precede transport. The adapter does not maintain a version-stale list of structured-output-capable model IDs: if the provider rejects a valid nonempty model or `output_config.format` with HTTP 400, FR-089 returns `ServiceValidation` after one attempt and never falls back to prose parsing. No image envelope is recognized; all state is ordinary deterministic compact `state.to_plain_json()` with sorted object keys and preserved list order.

## Outputs

One core response with returned actual model, answers keyed by exact question IDs, available usage and bounded raw UTF-8 request/response bodies, or a typed refusal with safe in-memory raw exchange for a successful HTTP body.

## Behavior

The adapter SHALL POST JSON with `model` from the request, finite host-configured `max_tokens` in 1..4096, `messages:[{"role":"user","content":...}]`, `stream:false`, and `output_config.format:{"type":"json_schema","schema":...}`. The user content is deterministic text containing the state JSON and all ordered question IDs, wording, true/false criteria, choice labels/descriptions or indexed score-level descriptions. It SHALL exclude source sidecars, graph identity, credentials and DistributionPolicy. No temperature, tools, thinking, citations, metadata or remote image URLs are sent. The schema has a fixed root object with required `answers` array and `additionalProperties:false`; each item is `anyOf` three required-field closed objects: Boolean `{id,kind:"boolean",probability}`, Choice `{id,kind:"choice",selected,confidence,probabilities:[{label,probability}]}`, and Score `{id,kind:"score",expected,confidence,probabilities:[{label,probability}]}`. Every object sets `additionalProperties:false`. The schema includes no case text, question IDs, option labels or other data-derived property names or enum values, because provider schema grammars are cached. Numerical range, answer cardinality and membership checks occur locally; no unsupported JSON Schema numeric constraints are relied on.

The decoder SHALL accept only a 200 JSON Message with `type:"message"`, nonempty `id`, `role:"assistant"`, nonempty `model`, `stop_reason:"end_turn"`, no refusal stop detail, and exactly one text content block containing the closed output JSON. It SHALL require one answer per requested ID, no duplicates, exact variant, no unknown fields, and complete option/level labels matching the question exactly; order of the array does not change the keyed core result. Boolean probability and Choice selected/confidence and Score expected/confidence map without renormalization or recomputation. Every number is finite; probabilities/confidence are in [0,1], Score expected is in the zero-based level range. Core `validate_response` enforces DistributionPolicy mass and optional `expected_model`; the adapter does not equate requested alias with returned model or invent a weights digest. Provider schema `const` or `enum` casing is never trusted as a validation substitute.

`stop_reason:"refusal"` or refusal stop detail SHALL refuse the entire Ask as `InvalidAnswer` with `reason=provider_refusal`.

`max_tokens` or another non-end stop SHALL refuse as `InvalidAnswer` with a stable stop reason and no partial answers.

Missing, duplicated, wrong-kind, unknown-label or malformed output SHALL refuse as `MissingAnswer` or `InvalidAnswer`.

The adapter SHALL map nonnegative reported `usage.input_tokens` and `usage.output_tokens` to core Usage with `billing_units:None`; optional cache/reasoning fields remain only in raw evidence, with no fabricated aggregate. Missing/invalid required usage refuses. Successful-body failures retain bounded raw exchange only in memory/partial Trace and never printable diagnostics.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-088-AC-1 | One three-question synthetic request captures exact Messages fields, ordered state/question content and fixed closed JSON Schema with no data-derived schema labels; a binding swap changes no graph source or operation. | Test (IT-019) |
| FR-088-AC-2 | Boolean, Choice and Score fixture values map exactly to core Answers, actual reported model and input/output usage; raw probabilities remain unchanged under core Strict/Approximate policy. | Test (IT-019) |
| FR-088-AC-3 | Refusal, cutoff, malformed/extra blocks, missing/duplicate/extra IDs, wrong kind/label, incomplete mass, nonfinite/out-of-range values and invalid usage yield typed whole-Ask refusal without partial Answers. | Test (IT-019) |
| FR-088-AC-4 | More than 16 questions/options or invalid state refuses before transport; a valid Record containing image-shaped text serializes as ordinary Record JSON, with no implicit image mode or URL fetch. | Test (IT-019) |
| FR-088-AC-5 | A syntactically valid but structured-output-incompatible model receives one provider HTTP 400 and returns `ServiceValidation`, without fallback or a claimed live reading. | Test (IT-019) |
