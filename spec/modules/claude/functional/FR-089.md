# FR-089: Bound and protect Claude Messages transport

## Description

When a host prepares a live Claude backend, the adapter SHALL authenticate one bounded Messages POST and classify failure without exposing credentials or private content.

## Inputs

Checked FR-088 request; redacted host credential of 1..8192 bytes with no HTTP control characters; host endpoint and limits. Stock CLI uses `https://api.anthropic.com/v1/messages` without endpoint override. An embedding host may inject a different remote HTTPS endpoint or loopback HTTP endpoint for tests. Limits default to and cannot exceed 30 seconds total, 1 MiB request bytes, 8 MiB response bytes and four simultaneous calls per adapter; all minima are one. `max_tokens` is separately 1..4096.

## Outputs

A complete bounded 200 body or `SaphoError` with stable ErrorCode and safe status/reason context only. No credential, endpoint, header, request content or response body appears in serialized, Display or Debug diagnostics.

## Behavior

The adapter SHALL require validated remote HTTPS or loopback HTTP with exact path `/v1/messages`, verify TLS certificates, reject URL userinfo/query/fragment and unsupported schemes, and send `Authorization: Bearer <secret>`, `anthropic-version: 2023-06-01`, and `Content-Type: application/json`.

When a host supplies an optional workspace ID, the adapter SHALL require the `wrkspc_` prefix followed by at least one ASCII letter or digit, accept only ASCII letters, digits, `_` and `-`, cap the entire value at 128 bytes, and send it as `anthropic-workspace-id`; it is never in graph/binding/recording/argv. Workspace-scoped keys need no ID; multi-workspace or identity-linked keys require an ID under Anthropic's current auth contract. If such a key is used without an ID, the provider's 400 is a typed `ServiceValidation` after one attempt with no sensitive body in diagnostics.

The adapter SHALL reject blank/header-invalid credentials, zero/above-cap limits and invalid endpoints before transport.

It SHALL disable redirect and automatic retry, issue one POST attempt, and apply the deadline across permit wait, connection, send, streamed body and decode. A semaphore limits concurrent calls and cancellation releases capacity. Serialized request and collected response are checked against byte limits independent of Content-Length.

HTTP 401/403 map to `Unauthorized`, 429 to `RateLimited`, 400/422 to `ServiceValidation`, timeout to `DeadlineExceeded`, byte overflow to `LimitExceeded`, and other HTTP/transport errors to `BackendFailed`. Non-200 bodies are discarded without decoding or raw evidence because they can echo private input. Malformed UTF-8/JSON and invalid 200 schema map to `InvalidAnswer`. Only 200 responses retain exact bounded UTF-8 body and sent JSON body as RawExchange, excluding URL and all headers. A scripted transport and ephemeral loopback server SHALL exercise the real codec and limits without external API access.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-089-AC-1 | Capture observes one POST to `/v1/messages` with bearer, version and JSON headers, no redirect/retry; remote HTTP, malformed URL/header/credential and a credential over 8192 bytes refuse before send. | Test (IT-019) |
| FR-089-AC-2 | Zero, exact-maximum and above-maximum limits; request/response boundaries, false Content-Length, waits/stalls and cancellation enforce ceilings and at most four in-flight calls. | Test (IT-019) |
| FR-089-AC-3 | Status 400/401/403/422/429/500, malformed 200 and transport failure map to declared codes; sentinel key, URL, input and body are absent from all printable errors and non-200 raw evidence. | Test (IT-019) |
| FR-089-AC-4 | Successful response retains exact bounded request/response bodies and replays offline; a host-supplied workspace ID appears only in the outbound header, never raw evidence. Empty, malformed and 129-byte IDs refuse before send while a 128-byte valid ID is accepted; absent required ID yields one 400 mapped to `ServiceValidation`. | Test (IT-019) |
