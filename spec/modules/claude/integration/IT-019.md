# IT-019: Exercise Claude Messages and offline replay with synthetic services

## Objective

Prove typed independent Claude readings, exact core recording/replay, bounded private transport and required-only stock CLI preparation without a live account.

## Target Integration

`sapho-claude` codec and ModelBackend through a scripted transport and ephemeral loopback HTTP capture; core response validation, runtime Ask/Trace, recording/replay, and CLI binding/secret seams.

## Preconditions

A synthetic graph has one Ask binding `independent_reader` with a Record state and ordered questions: Boolean `relevant`, Choice `route` with two labels, Score `severity` with three indexed levels. Host metadata requests a documented Claude model ID; response reports its actual model explicitly. A second registry binding uses a different backend without changing graph source. No fixture asserts model quality.

## Inputs

Synthetic 200 body with `answers` containing Boolean 0.8, Choice selected second label/confidence 0.4/probabilities 0.1 and 0.9, Score expected 1.1/confidence 0.55/level probabilities 0.1, 0.7 and 0.2; usage input_tokens 42/output_tokens 7. Scripted malformed/refusal/status responses, fake credential store, and exact recording.

## Test Procedure

1. IT-019-SC-01: Capture the full POST and assert fixed closed schema, no data-derived schema names/enums, exact ordered Record/question prompt content, requested model, `max_tokens`, stream false, and exactly one call. Decode the fixture to exact typed answers, reported actual model and usage. Switch only host binding/model metadata and assert graph source/operation unchanged. Attach FR-088-AC-1/2 and FR-090-AC-2 tags.
2. IT-019-SC-02: Mutate one 200 field at a time: refusal stop, refusal detail, max_tokens, extra/non-text block, missing/duplicate/extra answer ID, wrong kind, unknown/incomplete/duplicate option, nonfinite/out-of-range probability or expected score, wrong/missing/negative usage, duplicate JSON key. Assert whole-Ask `MissingAnswer` or `InvalidAnswer`, safe printable context and bounded in-memory raw evidence. Exercise Strict and Approximate mass policies without rewriting raw provider values. Check >16 questions/options, malformed state and image-shaped ordinary Record behavior before transport. Return a synthetic 400 for a structured-output-incompatible model and assert one `ServiceValidation` without fallback. Attach FR-088-AC-2/3/4/5 tags.
3. IT-019-SC-03: Loopback server captures bearer, version, JSON and path. Exercise remote HTTP refusal, malformed URL/credential/workspace header, credential lengths 8192/8193 bytes, no redirects/retries, zero/exact-max/above-max limits, exact/overflow bytes, lying Content-Length, stalled permit/send/body and cancellation. Assert <=4 in flight, deadline covers all phases and capacity returns. Exercise 400/401/403/422/429/500, malformed 200 and transport failure with secret/input/URL/body sentinels absent from error serialization, Display, Debug and non-200 raw evidence. Attach FR-089-AC-1/2/3 tags.
4. IT-019-SC-04: Fake secret storage checks explicit > environment > OS for only required live binding. A configured `ANTHROPIC_WORKSPACE_ID` appears in the outbound header only; empty, malformed/prefix-invalid and 129-byte values refuse before send, while a valid 128-byte value reaches the fake service. A scripted multi-workspace-key 400 with the ID absent maps to `ServiceValidation` after one call without body disclosure. Unused binding, absent compiled feature and validate/inspect/replay/replay-backed measure/tune access no secret/workspace environment or network. Refuse missing model/key and endpoint/credential/workspace metadata. Record successful synthetic call, then replay offline without feature/key/service and assert exact core request, answers, actual model, usage and raw bytes; mismatched explicit replay metadata refuses. Attach FR-089-AC-4 and FR-090-AC-1/2/3 tags.
5. IT-019-SC-05: Run current Jev/CLM/Decisions/generic replay and core/Dataset serde/validate checks; inspect that EARS annotation/review-queue code is absent. Document a separate one-case live smoke command and evidence fields (model, status, latency, answer types, redacted usage) when an authorized account is available; absent access is an explicit pending live check, never synthetic success. Attach FR-090-AC-4 tag.
