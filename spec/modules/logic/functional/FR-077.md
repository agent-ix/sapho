# FR-077: Merge exactly one present guarded value

## Description

When a graph contains mutually exclusive guarded branches, the `merge_present` operation SHALL return their one present value without executing an unguarded default backend.

## Inputs

Between 2 and 32 named operands, each of declared type `Optional(T)` with the same exact inner `ValueType` T. Names use the existing graph port-name rule. The operation has no configuration fields, backend binding or evaluation guard requirement; inputs are graph bindings to guarded ports or other typed Optional values.

## Outputs

One `result: T` port on exactly one present operand, or a structured `SaphoError` with code `InvalidValue` and merge node path plus `present_count` when zero or multiple operands are present. The error context lists present operand names in canonical lexicographic order, bounded by the 32-input ceiling; it contains no model response or credential content.

## Behavior

The graph compiler SHALL reject fewer than two or more than 32 operands, duplicate names, non-Optional operands, unequal inner types and unknown operation fields before execution. The type check uses exact `ValueType` equality, including Answers, Text and nested record/list types; it does not coerce Probability, Degree or Number. The output type is unwrapped T. Operand names are not backend names and impose no allowlist: any valid configured BackendId works through a guarded Ask.

The runtime SHALL resolve every declared operand and count `Some` values without short-circuiting. It SHALL return the inner value unchanged when the count is exactly one, including `false`, zero, empty text or an empty collection. It SHALL fail with `InvalidValue` on count zero or greater than one; no first-wins order, implicit default, missing-answer fabrication or model call is allowed. The merge node has ordinary trace inputs and a failed status/error on refusal. The result Datum inherits the resolved operands' SourceRefs under the existing node-output attribution rule, while its value is exactly the selected inner value. A guarded Ask's false branch remains `Skipped` and produces `None` on both Answers and model Text ports; the merge does not evaluate the skipped node's state/questions bindings.

For a routed answer, separate `merge_present` nodes on the guarded Ask `answers` and `model` ports SHALL select the same branch because one Ask guard wraps both ports together. A downstream `probability` node receives plain Answers. This routing pattern does not replace the existing fast-always-called, slow-guarded `coalesce` escalation behavior in [FR-024](FR-024-coalesce-explicit-optional-values.md).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-077-AC-1 | A three-branch graph compiles with Optional(Answers) and Optional(Text) merge nodes; each of three replayed inputs calls exactly its selected backend, marks the other two Ask nodes Skipped and feeds merged Answers to `probability`. | Test (IT-015) |
| FR-077-AC-2 | Zero present operands yields `InvalidValue` with merge node path and `present_count=0`; no default backend is called or answer emitted. | Test (IT-015) |
| FR-077-AC-3 | Two present operands yield `InvalidValue` with merge node path, `present_count=2` and both names; no first-wins output is emitted. | Test (IT-015) |
| FR-077-AC-4 | Every N from 2 through 32 Optional operands of one exact inner type compiles; one and 33, mixed inner types, an unguarded Ask's plain Answers/Text ports and unknown fields refuse before execution. Valid BackendIds need no operator-specific names. | Test (IT-015) |
| FR-077-AC-5 | One present `Some(false)`, `Some(0)`, `Some("")` or empty collection stays present and unchanged; the output's SourceRefs follow existing node-output attribution. | Test (IT-015) |
| FR-077-AC-6 | The existing fast Ask plus guarded slow Ask with `coalesce` still compiles and replays both escalated and non-escalated cases with the prior call counts, outputs and trace statuses. | Test (IT-015) |
