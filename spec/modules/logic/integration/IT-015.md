# IT-015: Route three guarded backends and preserve escalation

## Objective

Verify the exact-one Optional merge, three-way guarded routing, typed refusal on gap/overlap, bounded arbitrary candidate names, documented graphs and existing fast/expert escalation.

## Target Integration

Public GraphSpec parse/compile, sapho-runtime Engine and trace, RecordingBackend/ReplayBackend, stock CLI validation, docs link check and CI `docs-examples`. Scripted ModelBackend instances stand in for three model bindings; no live service, credentials or dataset source is used.

## Preconditions

Three unique BackendIds with distinct actual-model Text values and validated Boolean Answers to the same question ID. Synthetic typed inputs select low, middle or high risk. A recording has one exchange per selected request; each replay invocation has its own item input and uses the same graph. RunLimits allow one selected call per invocation.

## Inputs

The router and escalation example graphs, three exclusive routing inputs, all-false and overlapping-true guard fixtures, type/count-invalid merge graphs, Boolean/Number/Text/list Optional values and existing guarded escalation replay fixtures.

## Test Procedure

1. IT-015-SC-01: Parse YAML/JSON graphs with `merge_present` on Optional(Answers) and Optional(Text), iterating every candidate count N=2..32 and arbitrary BackendIds. Assert output T and compile refusal for 1/33 ports, an unguarded Ask's plain Answers/Text port, mixed inner types, duplicate port names and unknown operation fields. The unguarded Ask fixture never reaches runtime or makes a default call.
2. IT-015-SC-02: Replay three synthetic item inputs through `examples/graphs/router.yaml`. For each, assert exactly one backend request and response, two Ask nodes `Skipped` with Optional(None) on both ports, matched merged Answers/model Text from the selected Ask, and a downstream `probability` value from those Answers. Change BackendIds only in graph/bindings and confirm the same operation compiles and runs.
3. IT-015-SC-03: Force all three guards false. Assert `InvalidValue`, merge node path and `present_count=0`, no model call or output answer, and three skipped traces. Force two guards true; assert two backend calls, `InvalidValue`, `present_count=2`, lexicographically listed present operand names and no first-wins answer. Both refusal traces identify the merge node.
4. IT-015-SC-04: Merge optional false, zero, empty Text and empty list in separate synthetic graphs; assert presence is distinct from absence and the selected value stays exact. Give selected/skipped operands distinct SourceRefs and assert the merged output follows the existing all-resolved-input source attribution rule.
5. IT-015-SC-05: Replay `examples/graphs/escalation.yaml` with confident and escalated synthetic items. Assert respectively one fast call and two fast/expert calls, slow Ask Skipped/Completed, and the existing `coalesce` Answers/model Text outputs. Compare with current guarded escalation fixture values, errors and trace shape.
6. IT-015-SC-06: Run the CI-backed `sapho validate` command for both graphs and the docs link checker. Assert the user-guide links resolve and both graph validations require no bindings, credentials or model calls. Verify CI invokes this check via `make docs-examples` or an explicit equivalent step.

## Expected Results

Every scenario asserts a concrete type, value, call count, trace state, error code/context or documentation/CI command result. These are synthetic acceptance fixtures; no model-quality or deployment result is claimed. Dataset JSON/serde/validate and EARS export interfaces remain unchanged.
