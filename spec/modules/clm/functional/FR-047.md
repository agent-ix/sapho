# FR-047: Require a verified Decisions API contract

## Description

When specifying the OpenAI Decisions backend, Sapho SHALL establish its official preview request, response, model and authentication contract.

## Inputs

Checked core requests or host-selected configuration; untrusted bytes are bounded and validated.

## Outputs

Typed responses or a structured refusal; private contents are excluded from diagnostics.

## Behavior

The authorized target is the official Decisions API for finite predefined answers using Luna with text/image context. On 2026-10-10 the [official guide](https://developers.openai.com/api/docs/guides/decisions) and [create reference](https://developers.openai.com/api/reference/resources/decisions/methods/create) identify public beta `POST https://api.openai.com/v1/decisions`, `gpt-6-luna`, bearer authorization, `model`/`input`/ordered `questions`, and `answers`/`model`/`usage`. The verified contract permits a dedicated adapter under [sapho-decisions](../../decisions/spec.md), with typed and bounded details in FR-085 through FR-087. No Responses/Chat Completions substitution, inferred endpoint, stub adapter or model installation is delivered as Decisions support. Credentials use the shared store boundary and never enter decision documents. The beta contract is rechecked before implementation and on upstream schema change. Account quota/access and live model behavior remain unverified; a previous minimal call with the available session key returned HTTP 429 `insufficient_quota`/`credit_balance_exhausted`, so synthetic tests do not claim live acceptance.
