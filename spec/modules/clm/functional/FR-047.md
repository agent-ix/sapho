# FR-047: Require a verified Decisions API contract

## Description

When specifying the OpenAI Decisions backend, Sapho SHALL establish its official preview request, response, model and authentication contract.

## Inputs

Checked core requests or host-selected configuration; untrusted bytes are bounded and validated.

## Outputs

Typed responses or a structured refusal; private contents are excluded from diagnostics.

## Behavior

The authorized target is the new Decisions API for finite predefined answers using Luna with text/image context. The launch announcement establishes intent and limited preview, but does not establish endpoint/schema. Implementation is dependent on actual official contract/access documentation. No Responses/Chat Completions substitution, inferred endpoint, stub adapter or model installation is delivered as Decisions support. Once documentation is available, its owning provider module and executable acceptance criteria are specified and reviewed before code. Credentials use the same shared store boundary and never enter decision documents. Lack of documentation does not block independent CLM/CLI work.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-047-AC-1 | The dependency assessment identifies which official endpoint/request/response/model/auth details are available and which prevent implementation. | Inspection |
| FR-047-AC-2 | The delivered provider registry contains no Decisions substitute or stub while the official wire contract is unavailable. | Inspection |

See frontmatter and the [workspace](../../../spec.md); shared core contracts remain independent of transport.
