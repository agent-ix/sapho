# FR-031: Assemble ordered identified lists

## Description

The Sapho executor SHALL assemble an identified List from explicit ordered input ports.

## Inputs

The explicit typed inputs, options and limits named in Behavior. External files and JSON/YAML are validated before evaluation.

## Outputs

The declared typed result, or a structured refusal. Execution failures retain available partial evidence; absence of a result is never interpreted as a passing evaluation.

## Behavior

The list operation declares item_type and an order vector of distinct port names. The order names exactly equal the input binding names; every operand has item_type. result is List(item_type), including an explicitly typed empty list. Each occurrence receives a deterministic scoped identity derived from the node path and port name, retains that operand's sources, and is emitted in order. Reusing a value through two named ports creates two distinct occurrences. Normal collection-item and byte ceilings apply.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-031-AC-1 | A configured reversed order is preserved, including distinct IDs when the same source value is bound twice. | Test (TC-031) |
| FR-031-AC-2 | An empty typed list executes; missing/duplicate order names and mixed types fail compilation. | Test (TC-031) |
| FR-031-AC-3 | Nested list construction shares runtime item/byte limits and preserves source attribution. | Test (TC-031) |
