# FR-076: Execute and score repeated ask samples

## Description

When a compiled Ask requests `k > 1` samples, the runtime SHALL execute and retain all indexed calls and emit a reproducible Degree of answer disagreement.

## Inputs

A validated compiled Ask, finite RunLimits, one state Record, one ordered Questions block, and one registered backend.

## Outputs

Sample-index-ordered identified Answers and actual-model lists, a Degree disagreement in `[0,1]`, and per-sample request/response trace evidence; or a partial trace with the existing structured error. `k=1` retains the current singular outputs and trace shape.

## Behavior

For `k>1`, the runtime SHALL construct requests with indices `0..k-1`, dispatch them subject to the existing concurrency and deadline limits, and place results in index order regardless of completion order. It SHALL validate every response against its corresponding request. Each serialized dispatched request, returned response and produced list payload counts toward the existing data-byte limit.

One admission ledger and one model-call permit pool SHALL be shared by every Ask in the whole Engine::run, including ready sibling nodes and nested Map subgraphs. The runtime SHALL atomically reserve all `k` model-request slots from that ledger prior to the first dispatch. The admission check uses `dispatched + outstanding reservations + k <= RunLimits.model_requests`; an Ask that cannot reserve fails with LimitExceeded and sends no sample. Ready sibling Asks seek admission in the graph's deterministic stage/declaration order, and mapped children in their existing item order; independent per-Ask prechecks do not bypass this ledger. Immediately before each actual infer call, the scheduler SHALL consume one of that Ask's reserved slots and increment `dispatched`. It SHALL release unused reservations when an Ask stops after a failed wave or the run ends. Thus both active reservations and actual dispatched calls remain under the run-wide request ceiling, without charging an unsent sample.

Every model call, including a one-sample Ask, SHALL acquire one permit from the same run-wide pool before infer and release it after success, structured failure or deadline timeout. Pending calls that have not acquired a permit are not dispatched or charged. At every instant, active model calls across all ready Ask nodes and mapped work SHALL be at most `RunLimits.concurrency`. The pool is not recreated by a graph node or Map child. Admission and permit accounting are separate: an admitted sample can wait for a permit, and its reservation still counts against admission. A shared deadline while waiting for a permit fails the Ask with DeadlineExceeded; no request is recorded for an un-dispatched sample.

Samples SHALL run in ascending fixed waves of at most `RunLimits.concurrency` eligible calls: start one wave, then await each dispatched call's success, structured error or shared-deadline timeout before starting the next wave. A wave's calls acquire permits from the shared pool; a sibling Ask can occupy permits, so an eligible call waits for a permit without being dispatched. Completion or permit-acquisition order within a wave SHALL NOT affect result or trace order. If one or more dispatched samples in a wave fail, the Ask SHALL stop before the next wave, select the structured failure at the lowest failing sample index in that wave as its node error, and retain every dispatched sample's terminal status and request/response/error evidence in ascending index order. If the deadline prevents an eligible sample from acquiring a permit, the Ask SHALL fail with DeadlineExceeded after dispatched peers settle or time out; an earlier-index dispatched failure takes precedence if present. Other failures in that wave remain visible only as sample evidence. A timed-out in-flight future is cancelled by dropping its timeout wrapper at the shared deadline; no further wave is dispatched. Un-dispatched samples have no request, status or exchange in the trace. The failed Ask exposes no partial successful output list. For `k=1`, the existing singular `NodeTrace.model` and failure behavior are unchanged; for `k>1`, the trace carries a separate ordered indexed sample-evidence collection rather than overwriting the singular field.

Disagreement SHALL use a categorical signature for each complete answer block in ordered question order: Boolean is `true` when probability is at least 0.5 and `false` otherwise; Choice is its selected label; Score is the nearest declared integer level to `expected`, with an exact half-way tie resolved to the lower level. The signature includes each question ID and answer kind, so equal labels in different questions or kinds do not collide. Let `m` be the largest count of one identical signature among `k` samples. The disagreement is exactly `(k-m)/k`, converted to Degree without Probability semantics. A modal tie does not affect `m`. This metric compares predicted answers, not confidence; individual probabilities remain in the Answers list. It is distinct from SAPHO-33's held-out per-case disagreement across whole-graph runs. Sample zero is the primary sample and indices one and two are the additional runs when a caller chooses `k=3`; the held-out gate does not depend on this feature being implemented.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-076-AC-1 | Three scripted responses with categorical signatures A, B, A produce index-ordered answers/models and Degree `1/3`; three different signatures produce `2/3`, and three equal signatures produce zero. | Test (IT-014) |
| FR-076-AC-2 | Boolean probability 0.5 selects true, Score half-way selects the lower level, and a two-question answer block compares the whole ordered signature; confidence changes alone do not change disagreement. | Test (IT-014) |
| FR-076-AC-3 | A limit of two remaining model requests refuses `k=3` before dispatch; a limit of three succeeds and charges three, including inside Map; completion order cannot reorder outputs. | Test (IT-014) |
| FR-076-AC-4 | A k=4 replay of indices 0..2 selects ReplayMiss at index 3 with no live fallback; completed indices and the failed index are retained in order, subject to the declared wave width. | Test (IT-014) |
| FR-076-AC-5 | `k=1` preserves current output values, public types, request bytes and trace shape. | Test (IT-014) |
| FR-076-AC-6 | With concurrency two, indices 0 and 1 fail in reverse completion order: index 0's error wins, both errors appear in ordered sample evidence, and indices 2 and 3 are neither dispatched nor charged; an in-flight peer at the shared deadline is marked timed out before return. | Test (IT-014) |
| FR-076-AC-7 | Two ready k=3 Asks with run-wide concurrency two and model-request limit six never exceed two active calls or six dispatched calls, regardless of response order; with limit four, atomic admission rejects the second Ask before any of its calls, and a nested mapped Ask uses the same ledger and permits. | Test (IT-014) |
