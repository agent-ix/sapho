# FR-076: Execute and score repeated ask samples

## Description

When a compiled Ask requests `k > 1` samples, the runtime SHALL execute and retain all indexed calls and emit a reproducible Degree of answer disagreement.

## Inputs

A validated compiled Ask, finite RunLimits, one state Record, one ordered Questions block, and one registered backend.

## Outputs

Sample-index-ordered identified Answers and actual-model lists, a Degree disagreement in `[0,1]`, and per-sample request/response trace evidence; or a partial trace with the existing structured error. `k=1` retains the current singular outputs and trace shape.

## Behavior

For `k>1`, the runtime SHALL construct requests with indices `0..k-1`, dispatch them subject to the existing concurrency and deadline limits, and place results in index order regardless of completion order. It SHALL validate every response against its corresponding request. It SHALL check before dispatch that the remaining cumulative `model_requests` budget can cover all `k` samples, including nested graph work; otherwise it fails with no sample sent. It SHALL charge one model request immediately before each actual sample dispatch. An un-dispatched sample after a failed wave is not charged. Each serialized dispatched request, returned response and produced list payload counts toward the existing data-byte limit.

Samples SHALL run in ascending fixed waves of at most `RunLimits.concurrency` calls: launch every call in a wave, then await each call's success, structured error or shared-deadline timeout before launching the next wave. Completion order within a wave SHALL NOT affect result or trace order. If one or more samples in a wave fail, the Ask SHALL stop before the next wave, select the structured failure at the lowest failing sample index in that wave as the node/run error, and retain every dispatched sample's terminal status and request/response/error evidence in ascending index order. Other failures in that wave remain visible only as sample evidence. A timed-out future is cancelled by dropping its timeout wrapper at the shared deadline; no further wave is dispatched. Already dispatched peers settle or time out by that deadline, so no in-flight sample is silently discarded. Un-dispatched samples have no request, status or exchange in the trace. The failed Ask exposes no partial successful output list. For `k=1`, the existing singular `NodeTrace.model` and failure behavior are unchanged; for `k>1`, the trace carries a separate ordered indexed sample-evidence collection rather than overwriting the singular field.

Disagreement SHALL use a categorical signature for each complete answer block in ordered question order: Boolean is `true` when probability is at least 0.5 and `false` otherwise; Choice is its selected label; Score is the nearest declared integer level to `expected`, with an exact half-way tie resolved to the lower level. The signature includes each question ID and answer kind, so equal labels in different questions or kinds do not collide. Let `m` be the largest count of one identical signature among `k` samples. The disagreement is exactly `(k-m)/k`, converted to Degree without Probability semantics. A modal tie does not affect `m`. This metric compares predicted answers, not confidence; individual probabilities remain in the Answers list. It is distinct from SAPHO-33's held-out per-case disagreement across whole-graph runs. Sample zero is the primary sample and indices one and two are the additional runs when a caller chooses `k=3`; the held-out gate does not depend on this feature being implemented.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-076-AC-1 | Three scripted responses with categorical signatures A, B, A produce index-ordered answers/models and Degree `1/3`; three different signatures produce `2/3`, and three equal signatures produce zero. | Test (IT-014) |
| FR-076-AC-2 | Boolean probability 0.5 selects true, Score half-way selects the lower level, and a two-question answer block compares the whole ordered signature; confidence changes alone do not change disagreement. | Test (IT-014) |
| FR-076-AC-3 | A limit of two remaining model requests refuses `k=3` before dispatch; a limit of three succeeds and charges three, including inside Map; completion order cannot reorder outputs. | Test (IT-014) |
| FR-076-AC-4 | A k=4 replay of indices 0..2 selects ReplayMiss at index 3 with no live fallback; completed indices and the failed index are retained in order, subject to the declared wave width. | Test (IT-014) |
| FR-076-AC-5 | `k=1` preserves current output values, public types, request bytes and trace shape. | Test (IT-014) |
| FR-076-AC-6 | With concurrency two, indices 0 and 1 fail in reverse completion order: index 0's error wins, both errors appear in ordered sample evidence, and indices 2 and 3 are neither dispatched nor charged; an in-flight peer at the shared deadline is marked timed out before return. | Test (IT-014) |
