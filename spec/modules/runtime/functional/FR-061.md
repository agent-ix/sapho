# FR-061: Observe model calls for measured rosters

## Description

When roster measurement is requested, the runtime SHALL report model-call observations for every attempted backend call without changing the deterministic Trace contract.

## Inputs

A compiled graph, backend registry, RunLimits and an explicit live or replay execution mode. A clock seam supplies monotonic elapsed time for live calls.

## Outputs

An ordered sidecar of model-call observations keyed by trace node path, with binding ID, requested model, reported actual model when present, completion status, provider Usage when present, and optional live elapsed duration. Existing Trace and RunResult fields remain available.

## Behavior

The runtime SHALL make one call observation for each trace node that attempted ModelBackend inference, including failed calls with a known request.

It SHALL not count a skipped ask or a node that failed before inference as a model call.

When a validated response is available, the observation SHALL take actual model identity and Usage from it.

When the backend gives no response, the observation SHALL leave actual model identity and Usage absent.

The runtime SHALL measure live elapsed duration around the backend call with a monotonic clock.

The runtime SHALL keep that duration separate from Trace equality and recording bytes.

Replay-only calls SHALL have absent duration even though replay execution consumes wall-clock time.

The host SHALL attach optional provider metadata by binding ID in the observation sidecar without adding it to ModelRequest, credentials, recordings or raw trace bodies.

Every backend implementing the public ModelBackend port SHALL be observable through the same seam; no stock adapter name is required.

The existing run deadline, byte and call ceilings remain authoritative.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-061-AC-1 | A two-binding live fixture produces one observation per attempted model node in Trace, keyed to its node path and binding; a false-guarded ask produces none. | Test |
| FR-061-AC-2 | A scripted live clock yields elapsed durations for completed and failed backend calls; replay of the same recording yields absent durations, never zero. | Test |
| FR-061-AC-3 | Missing Usage and an error without a response retain absent usage and actual model instead of invented zeros or the requested model. | Test |
| FR-061-AC-4 | A custom host's ModelBackend produces the same observation shape as a stock adapter and no credential or endpoint enters Trace or recording. | Test |
