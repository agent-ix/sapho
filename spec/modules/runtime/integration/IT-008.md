# IT-008: Shadow decision isolation across graph, runtime, recording and evidence

## Objective

Verify that a shadow model can be recorded and compared against one curated label per case without changing the champion decision or failure policy.

## Target Integration

The public graph compiler, runtime, recording and evidence APIs through the CLI host. Scripted ModelBackend doubles are injected at the existing inference seam; no network service or private dataset is used.

## Preconditions

Rust 1.98.1 and the checked-in synthetic fixture. A champion recording is fixed before adding a shadow node. The same fixture includes development and held-out cases, two label kinds, a shadow success, timeout and ReplayMiss.

## Inputs

A graph with one decision ask and one shadow ask mapped to the same named output; a Dataset with one label per output and case; finite RunLimits; a declared comparison metric, count floor and margin.

## Test Procedure

1. Compile the original and shadow graphs, including a shared ask-free question producer also mapped to a decision output; then compile a variant whose shadow questions read champion Answers.
   - IT-008-SC-01: the shared ask-free producer compiles despite its decision-output mapping, while the champion-dependent shadow is refused before inference with the shadow and producer named.
2. Run and record the accepted graphs against scripted backends.
   - IT-008-SC-02: decision output bytes and decision exit status agree, and the shadow recording contains only successful exchanges.
3. Replay the shadow graph with success and missing shadow exchange variants.
   - IT-008-SC-03: success is offline and exact; a shadow ReplayMiss leaves the decision intact and is visible in the trace.
4. Run a shadow timeout and a run with no remaining model-call credit after the decision.
   - IT-008-SC-04: both retain the decision; timeout is failed, exhausted credit is skipped, and no excess model call occurs.
5. Measure both roles on development and held-out cases using one label per case/output, including a zero-margin tie, a positive zero-margin gain and an exact positive-margin boundary.
   - IT-008-SC-05: counts, case sets, label-kind partitions, margin verdicts and split marker equal hand-computed expectations; absent shared ECE is explicitly not-computed and cannot win.
6. Swap champion and challenger graph/binding declarations.
   - IT-008-SC-06: the swapped graph compiles and runs without a provider-specific source change.
7. Add an ask-free native producer used only by shadow questions, and a shared ask-free producer used by a public decision output.
   - IT-008-SC-07: inspection places the first producer in the shadow plan and the shared one in decision stages. Force the shadow-only producer to fail, then exhaust node/data/time limits immediately after decision; each run retains the original decision bytes/exit, makes zero dependent shadow backend calls and records a typed shadow producer failure or skip. The shared producer executes exactly once and its value is reused by the shadow.
8. Use a case whose model-source label matches the shadow response model but not the champion response model.
   - IT-008-SC-08: compare the decision-only CaseOutcome model list directly; the serialized ordinary `Measurement` value, champion scored count and exit remain equal before and after adding shadow. Graph identity and run-document bytes may differ. Comparison lists the case as shadow self-source excluded, preserves champion scoring, and does not claim a win from an unequal or empty matched case set.

## Expected Results

Every success criterion passes through public interfaces. A missing or failed shadow never changes a completed decision, and no report claims a promotion from development cases.
