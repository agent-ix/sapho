# IT-008: Shadow decision isolation across graph, runtime, recording and evidence

## Objective

Verify that a shadow model can be recorded and compared against one curated label per case without changing the champion decision or failure policy.

## Target Integration

The public graph compiler, runtime, recording and evidence APIs through the CLI host. Scripted ModelBackend doubles are injected at the existing inference seam; no network service or private dataset is used.

## Preconditions

Rust 1.98.1 and the checked-in synthetic fixture. A champion recording is fixed before adding a shadow node. The same fixture includes development and held-out cases, two label kinds, a shadow success, timeout and ReplayMiss.

## Inputs

A graph with one decision ask and one shadow ask mapped to the same named output; a Dataset with one label per output and case; finite RunLimits; a declared comparison metric, count floor and margin.

## Test Procedure

1. Compile the original and shadow graphs, then run and record both against scripted backends.
   - IT-008-SC-01: decision output bytes and decision exit status agree, and the shadow recording contains only successful exchanges.
2. Replay the shadow graph with success and missing shadow exchange variants.
   - IT-008-SC-02: success is offline and exact; a shadow ReplayMiss leaves the decision intact and is visible in the trace.
3. Run a shadow timeout and a run with no remaining model-call credit after the decision.
   - IT-008-SC-03: both retain the decision; timeout is failed, exhausted credit is skipped, and no excess model call occurs.
4. Measure both roles on development and held-out cases using one label per case/output.
   - IT-008-SC-04: counts, metrics, case sets, label-kind partitions, declared margin and split promotion marker equal hand-computed expectations.
5. Swap champion and challenger graph/binding declarations.
   - IT-008-SC-05: the swapped graph compiles and runs without a provider-specific source change.

## Expected Results

Every success criterion passes through public interfaces. A missing or failed shadow never changes a completed decision, and no report claims a promotion from development cases.
