# IT-014: Capture and replay indexed repeated asks

## Objective

Prove exact repeated-ask capture/replay, unchanged provider bytes, typed disagreement and cumulative call accounting through public core, graph, runtime and recording interfaces.

## Target Integration

Compile a synthetic YAML/JSON graph, execute it with RecordingBackend over a scripted fake ModelBackend, export and reload Recording, then execute with ReplayBackend. A fake loopback transport captures provider body and application header bytes to verify the adapter projection. No dataset source or live model is needed.

## Preconditions

Rust toolchain and existing workspace crates. A fixed Record and ordered Boolean, Choice and Score questions; scripted distinct validated responses; bounded RunLimits. The k=1 baseline uses the current main implementation's JSON, provider capture, output and trace fixtures, retained as fixed expected artifacts.

## Inputs

Ask graphs at omitted/explicit one, three and four samples; responses with signatures A/B/A, A/B/C and A/A/A; a fourth-index replay miss; timeout/error doubles; exact and one-below model-request ceilings; invalid count and binding graphs.

## Test Procedure

1. IT-014-SC-01: Compile YAML/JSON `samples: 3`; assert repeated port types and refusal of singular-port binding. Compile omitted/explicit one and invalid counts/fields; compare one-sample serialized operation to the fixed legacy bytes.
2. IT-014-SC-02: Run k=3 through the recording decorator and capture transport. Assert exactly indices 0, 1, 2 in Recording, identical provider bodies/application headers, no index in provider bytes or state, and distinct indexed request keys. Export, reload and replay each answer exactly. A same-index answer conflict refuses loading; raw-only differences retain the existing first-raw rule.
3. IT-014-SC-03: Replay the same recording with k=4 at concurrency two. Assert wave zero completes indices 0 and 1; wave one completes index 2 and fails index 3 with ReplayMiss. The selected node/run error is index 3's ReplayMiss, no live transport is called, and ordered partial evidence contains terminal statuses for all four dispatched indices. Repeat at concurrency one to verify the same error and order across wave widths.
4. IT-014-SC-04: Assert A/B/A yields Degree 1/3, A/B/C yields 2/3 and A/A/A yields zero. Test Boolean 0.5, Choice selected label, Score half-way tie and multi-question signature. Change only confidence while preserving signatures and assert the Degree is unchanged.
5. IT-014-SC-05: Give a k=3 Ask two remaining model-call slots and assert pre-dispatch LimitExceeded with zero calls; give three and assert three calls, also under a mapped subgraph. Complete fake calls out of order and assert ordered outputs/evidence. At concurrency two, make index 1 fail first and index 0 fail later with a different error; assert index 0's code is the node/run error, both failures remain in index-ordered evidence, indices 2 and 3 are never called or charged, and no partial output is emitted. In a separate case, let index 0 fail while index 1 stalls to the shared deadline; assert index 1 is recorded as timed out before return and no later wave starts.
6. IT-014-SC-06: Run k=1 and compare provider bytes, request/recording JSON, output values/types and trace shape to fixed legacy fixtures. Assert Dataset JSON/serde/validate and EARS export interface are unchanged by this feature.
7. IT-014-SC-07: For k=3, assert both output lists have ItemIds exactly `"0"`, `"1"`, `"2"` in order, each pair carries one response's answer and actual model, and each item's SourceRefs equal the sorted deduplicated union of state and question input sources. Typed JSON export/import preserves IDs, order, values and sources. A downstream join on ItemId pairs the correct answers/models; plain JSON arrays preserve order without identity claims.

## Expected Results

Each scenario has a value, byte, type, error-code or call-count assertion. The test uses synthetic data only. SAPHO-33's held-out gate may use independently repeated full-graph runs and does not depend on IT-014 completion.
