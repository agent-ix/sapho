# IT-009: Measure and consume a two-binding model roster

## Objective

Verify that call evidence from two backends becomes an attributable, split-specific roster and a usable typed graph literal without inventing replay latency or model identities.

## Target Integration

The public runtime, evidence, graph and CLI APIs, with two scripted ModelBackend doubles and an injected monotonic clock. No external service, credential or private Dataset is required.

## Preconditions

The public Sapho workspace builds with synthetic graph, Dataset and backend fixtures. The Dataset has development and held-out cases, two label kinds and one Boolean and one Probability output, each mapped to one binding.

## Inputs

Two bindings with distinct actual reported models, one binding also returning a second actual model on another case, fixed Usage and durations, a failing response-less attempt, a guarded skip, a multi-binding ambiguous output, a replay recording, a validated descriptor and an endpoint-bearing invalid descriptor, and an explicit profile mapping.

## Test Procedure

1. Run the development fixture live with the injected clock and write the roster.
   - IT-009-SC-01: binding call counts equal attempted model nodes in Trace; the skipped ask is absent; both actual model IDs of one binding have separate call counts, usage denominators and latency percentiles; the response-less call stays in the unknown-actual-model bucket.
2. Score each mapped output by label kind and inspect the unattributed output.
   - IT-009-SC-02: each actual-model entry receives only case IDs and metric denominators backed by its own contributing response; the response-less bucket receives no scored cases; per-kind agreement and Brier equal ordinary `measure` on those same case sets, while multi-binding lineage is explicitly unattributed.
3. Replay the recording with live transports disabled and write a held-out roster.
   - IT-009-SC-03: no transport or credential lookup occurs; the split is `held_out`, latency is absent with `replay_only`, and calls remain attributable by recorded actual model.
4. Project two roster entries as named fields in a typed Record literal, validate a graph comparing numeric fields, then change one field.
   - IT-009-SC-04: the graph compiles and compares as expected; changing the literal changes `graph_semantic_identity`, while equivalent YAML/JSON typed graphs with reordered named maps and equivalent numeric spellings share it; reordered graph sequences change it; `GraphArtifact.source` and ordinary `measure` source fields retain their path/raw-byte behavior.
5. Repeat measurement with a custom-host ModelBackend absent from the stock provider enum and with a pre-existing output file.
   - IT-009-SC-05: the custom binding appears with only whitelisted, bounded provider and adapter names; an endpoint- or credential-bearing descriptor is refused before inference and cannot enter sidecar, roster or literal; the prior output file remains unchanged after refusal.

## Expected Results

Every per-step criterion passes. The roster states its measurement scope and metric availability, and its literal is ordinary checked graph data rather than a runtime model adapter.
