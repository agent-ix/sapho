# NFR-002: Bounded deterministic execution

## Statement

The Sapho executor SHALL retain deterministic output identity and ordering while respecting explicit work limits.

## Scope

All runtime operations share the same counters/deadline. Native code cooperation is an assumption, not a preemption guarantee. Execution duration is a work budget; model answers are not assumed deterministic. Concurrency is bounded and failures are visible. No wall-clock performance claim is made for arbitrary host primitives or model servers.

## Measurement and Evaluation

| Metric | Target | Threshold | Method |
|--------|--------|-----------|--------|
| Unbounded runtime fan-out and silently reordered items | 0 | 0 | Test and inspection |

## Verification

Run the scoped crate tests and inspect the dependency/serialization surfaces. At handoff run format, all-target/all-feature clippy, full workspace tests, documentation and supply-chain gates; no live calls are needed.
