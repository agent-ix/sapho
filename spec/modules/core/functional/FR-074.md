# FR-074: Identify repeated model samples without changing provider payloads

## Description

When a graph asks for multiple samples of one request, the core and recording ports SHALL distinguish each sample by a zero-based index while sending identical inference content to the provider.

## Inputs

The existing validated ModelRequest and an optional `u32` sample index. The index is absent for the legacy one-call path and present as `0..k-1` for a repeated ask, including sample zero.

## Outputs

Successful exchanges keyed by the exact ModelRequest including its sample index, or the existing structured recording/replay refusal.

## Behavior

The optional index is request metadata in the public core port. Serialization omits it when absent, preserving existing recording JSON and exact replay keys. When present, it participates in the exact recording/replay identity along with all existing request fields. RecordingBackend appends every successful validated exchange in invocation order. ReplayBackend may therefore load different answers at distinct indices and replay each exactly; two exchanges with the same indexed request still follow [FR-027](../../recording/functional/FR-027-record-successful-backend-exchanges.md)'s duplicate conflict rule, ignoring only raw exchange bytes.

Provider adapters SHALL project the same existing model, state, ordered questions and distribution policy into their wire request for every sample. They SHALL omit sample index from body, headers, URL, query and provider option fields. The index does not supply seed, temperature or another provider control. The transport capture compares complete outbound request bytes excluding transport-generated connection details; every repeated sample has an identical body and application headers. The raw exchange records those provider bytes, which also omit the index.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-074-AC-1 | A three-sample ask records three successful exchanges with request indices 0, 1 and 2; the captured provider request bodies and application headers are byte-identical and contain no sample-index member. | Test (IT-014) |
| FR-074-AC-2 | A recording with distinct validated answers at indices 0, 1 and 2 loads and replays each exact answer; an index-3 request returns ReplayMiss, and same-index conflicting answers still return RecordingMismatch. | Test (IT-014) |
| FR-074-AC-3 | A one-sample ask leaves the index absent, retains legacy ModelRequest/recording JSON bytes and exact replay key, and returns the existing answer. | Test (IT-014) |
