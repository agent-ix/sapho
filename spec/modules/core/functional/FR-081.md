# FR-081: Represent calibrated probability and a checked calibration map

## Description

When a graph uses a fitted calibration map, the Sapho core SHALL represent its output as a calibrated probability quantity distinct from raw model Probability and represent the map as a checked typed value.

## Inputs

Two new closed `ValueType`/`Value` variants: `calibrated_probability` contains a finite unit-range scalar, and `calibration_map` contains a versioned CalibrationMap. The map fields are `format: "sapho-calibration-v1"`, `dataset_id`, `fit_cases_digest`, `fit_observation_digest`, `split: "development"`, `fit_graph_semantic_identity`, `raw_output`, `fit_binding`, `fit_actual_model`, `method: "isotonic-pava-linear-v1"`, `case_count`, ordered `knots` of `{raw, calibrated}` unit-range numbers, and `map_id`.

## Outputs

Validated values with exact type checks and stable JSON serde, or structured `InvalidValue`/`TypeMismatch` refusals. Existing Probability and Degree variants remain unchanged.

## Behavior

`CalibratedProbability` SHALL use the same finite `[0,1]` numeric invariant as Probability but remain a distinct Rust type, Value variant and ValueType variant. Neither type SHALL coerce implicitly to the other, Degree or Number at any checked port. `decode_plain` for an explicitly declared `calibrated_probability` schema accepts a unit-range number; it does not infer calibrated provenance from an untyped number. The declared type marks quantity semantics, not certification that a caller-supplied value came from a fitted map. Ordinary raw Probability decoding and serialization remain byte-compatible.

`CalibrationMap::validate` SHALL require the exact version/method/split strings above, nonblank dataset/output IDs, `case_count >= 20`, 2–4096 knots, strictly increasing raw knots in `[0,1]`, nondecreasing calibrated knots in `[0,1]`, and finite values. Repeated raw knots, descending fitted values, nonfinite values, malformed digests and unknown fields refuse. `fit_binding` is a checked BackendId; `fit_actual_model` is the nonblank model name reported by ModelResponse, at most 256 UTF-8 bytes with no control characters. It is data, not a hard-coded allowlist or requested-model alias. The map records reported name identity only because the current ModelResponse has no weights digest; consumers SHALL label a match as `reported_name_match`, never as proof of unchanged weights. `fit_graph_semantic_identity` uses the `graph-v1:sha256:` form of draft FR-063 (SAPHO-25 PR #33). `fit_cases_digest` uses `dataset-development-v1:sha256:` and `fit_observation_digest` uses `calibration-observations-v1:sha256:`, each followed by lowercase SHA-256. The map's `map_id` is `calibration-v1:sha256:` plus SHA-256 of UTF-8 `sapho.calibration.v1\n` followed by canonical JSON of all map fields except `map_id`, under FR-063's named-map, array, numeric and string canonicalization rules. The map validator recomputes it; path, timestamps and raw file formatting are excluded. The fit graph identity names the raw graph used for fitting, not the later graph that embeds the map, avoiding a self-referential digest.

The core ValueType checker SHALL accept `CalibrationMap` as the `value` of an existing typed `Binding::Literal` with `value_type: {kind: calibration_map}`. It is not loaded by path during graph execution and contains no dataset cases, labels, credentials or provider endpoint. The literal's Datum ID and SourceRefs remain ordinary caller-owned attribution. Existing Dataset JSON/serde/validate and EARS export types are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-081-AC-1 | Raw Probability, CalibratedProbability, Degree and Number are distinct checked port types; calibrated plain decoding requires an explicitly declared schema, while legacy Probability JSON round-trips unchanged. | Test (IT-017) |
| FR-081-AC-2 | A generated map literal round-trips as `CalibrationMap`, validates its version/IDs/knot order and digest, and embeds in GraphSpec without a path field. | Test (IT-017) |
| FR-081-AC-3 | Duplicate/descending/nonfinite/out-of-range knots, fewer than two or more than 4096 knots, invalid count/split/method/digest and unknown map fields refuse before graph execution. | Test (IT-017) |
| FR-081-AC-4 | The map contains no selected case inputs, labels, credentials or endpoint, and existing Dataset serde/validate results are byte-compatible. | Test (IT-017) |
| FR-081-AC-5 | The map round-trip retains a validated arbitrary BackendId, bounded reported actual model name and observation digest; a changed model name changes map ID, while the map never claims a weights digest the provider did not report. | Test (IT-017) |

## Dependencies

[FR-001](FR-001-validate-typed-values.md) owns typed values; [FR-005](FR-005-validate-model-answers.md) keeps raw model answers and Probability distinct. The graph identity form and canonicalization come from draft FR-063 (SAPHO-25 PR #33), an explicit implementation dependency before this map validator can ship.
