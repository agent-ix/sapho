# FR-032: Decode plain data by a declared type

## Description

The Sapho data decoder SHALL convert plain JSON values according to an explicit ValueType.

## Inputs

The explicit typed inputs, options and limits named in Behavior. External files and JSON/YAML are validated before evaluation.

## Outputs

The declared typed result, or a structured refusal. Execution failures retain available partial evidence; absence of a result is never interpreted as a passing evaluation.

## Behavior

A pure decoder creates Datum values from a caller-supplied identity and declared ValueType. Boolean, finite Number, Text, Probability and Degree are distinct schema-directed conversions. Records require exactly their declared fields; lists recursively retain ordered occurrence identities derived from structured index paths. Optional null means None; non-null means Some of the declared inner type. Questions and Answers use their existing typed JSON representations and validation. No probability/degree conversion is inferred from a bare number without a declared type. Nesting remains bounded by the core contract. The caller supplies source sidecars separately.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-032-AC-1 | The same numeric JSON value decodes as Number, Probability or Degree only according to its declared schema. | Test (TC-032) |
| FR-032-AC-2 | Record extras/missing fields, wrong scalar kinds, non-finite/out-of-range values and over-depth input are refused. | Test (TC-032) |
| FR-032-AC-3 | Ordered nested list IDs are deterministic, unique per occurrence and unaffected by delimiter-like field text. | Test (TC-032) |
