# FR-048: Define a one-call structured extraction port

## Description

The Sapho core SHALL define an asynchronous Extractor port that turns one ExtractRequest into one schema-checked ExtractResponse or a typed ExtractError.

## Inputs

- `ExtractRequest.model`: the requested model identity, nonempty.
- `ExtractRequest.instructions`: the fixed task text, identical for every item of a task, nonempty.
- `ExtractRequest.input`: the text of one item and the data that task declares for it, nonempty. It never contains another item or an earlier exchange of the run.
- `ExtractRequest.schema`: a JSON Schema (draft 2020-12) object that the answer must match.

## Outputs

- `ExtractResponse.value`: the parsed JSON answer, already checked against `schema`.
- `ExtractResponse.usage`: `input_tokens` and `output_tokens` as the provider reported them (each absent when not reported), and elapsed milliseconds.
- `ExtractResponse.raw`: a RawExchange, the exact request body sent and the exact response body received, so a caller can store them by content hash. A RawExchange holds body bytes only, never HTTP headers, URLs or credentials. Its JSON form is an object with members `request` and `response`, each a JSON string holding that body as UTF-8 text.
- `ExtractResponse.model`: the model name reported by the response.
- `ExtractError`: an ErrorCode; a reason string from a closed per-adapter list; a message free of request and response content; for `TooLarge`, a `too_large` detail with `reported_input_tokens` (the provider's count, when it gave one), `context_tokens` and `reserved_output_tokens`; and, when an exchange took place, the raw exchange and usage.

## Behavior

ModelBackend answers typed closed questions; Extractor returns one structured record in one call. Keeping them as two ports keeps each contract small and lets any backend offer extraction without transport code in core.

- The core SHALL expose one call path, `sapho_core::extract(&dyn Extractor, &ExtractRequest)`, which checks the request, invokes the implementation's single exchange method, and checks the answer; an implementation cannot hand a value to a caller without passing through it.
- The Extractor port SHALL carry no conversation, session or state between calls; two calls with equal requests are independent exchanges.
- When a request has an empty model, empty instructions, empty input, or a schema that is not a JSON object or does not compile, the core SHALL refuse it with code `Config` before any implementation is invoked.
- When a schema contains a `$ref` that does not point inside the same schema document, the core SHALL refuse it with code `Config`; the core never reads a file or URL to resolve a schema.
- When an implementation returns a value, the core SHALL check it against the request schema before the caller receives an ExtractResponse. Schema checking lives in the core, so every Extractor implementation gets the same validation.
- If the returned bytes are not JSON or the value violates the schema, then the core SHALL return an ExtractError with code `InvalidAnswer`, reason `schema_violation` or `not_json`, the JSON Pointer of the first violation, and the retained raw exchange and usage.
- If the input does not fit the model's context, then the implementation SHALL return an ExtractError with code `TooLarge` and its `too_large` detail. `TooLarge` is a distinct ErrorCode so that a caller can record the item as too large, with the numbers, and continue, separately from transport failures (`BackendFailed`, `DeadlineExceeded`, `LimitExceeded`).
- When an ExtractError is converted into a SaphoError, the conversion SHALL keep its raw exchange and usage ([FR-006](FR-006-define-replaceable-model-backend.md)).
- An implementation SHALL judge the response status before its body. A non-success status is a transport failure, `BackendFailed`, so that a gateway or proxy outage and a binary 404 page stay transport failures and the retry and halt rules that key on `BackendFailed` keep working.
- The single exception is a size refusal that an adapter recognises from the status and the body together, which is `TooLarge` (for Ollama, [FR-050](../../ollama/functional/FR-050.md) and [FR-053](../../ollama/functional/FR-053.md)). A non-success body is read only for that recognition: when it cannot be decoded or is not a recognised refusal, the response stays `BackendFailed`. A non-success response never carries a raw exchange, and its usage holds only the elapsed time.
- If a response with a success status has a body that is not valid UTF-8, then the implementation SHALL return `InvalidAnswer` with reason `malformed_response`. The error carries no raw exchange, because a RawExchange holds bodies as text, and its usage holds only the elapsed time, because no token counts can be read from the body.
- The core SHALL leave a token count absent rather than invent one the provider did not report.
- The core crate SHALL gain no runtime, transport or file-access dependency from this port, the same boundary as ModelBackend.
- The core SHALL offer a scripted Extractor double that downstream crates can use in their own tests; it returns configured values or errors in order and records the requests it received.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-048-AC-1 | A host-defined Extractor returns a schema-valid value through `extract`; the caller receives value, usage, raw bytes and model identity unchanged. | Test |
| FR-048-AC-2 | A returned value that violates the schema, and returned bytes that are not JSON, produce `InvalidAnswer` with reasons `schema_violation` and `not_json`, the violation pointer and the retained raw exchange, never a panic. | Test |
| FR-048-AC-3 | An implementation's `TooLarge` error reaches the caller with code `TooLarge` and every `too_large` detail field readable without parsing the message, and a test tells it apart from `BackendFailed`, `DeadlineExceeded` and `LimitExceeded`. | Test |
| FR-048-AC-4 | Empty model, instructions or input, a non-object schema, a schema that fails to compile, and a schema with a `$ref` to another document or a URL are refused with `Config` before the implementation is called (the double records zero requests, and no file or network access occurs). | Test |
| FR-048-AC-5 | The scripted double is usable from another crate's tests and records each received request in order. | Test |
| FR-048-AC-6 | The core crate's dependency list contains no async runtime, HTTP, file-access or other transport crate after the port is added, and the schema validator is configured without remote or file reference resolution. | Test |
| FR-048-AC-7 | A RawExchange serializes as `{"request": "<body text>", "response": "<body text>"}` with JSON string members and round-trips byte-exactly, including non-ASCII text; a non-UTF-8 body under status 200 yields `InvalidAnswer` with reason `malformed_response`, no raw exchange and usage with elapsed time only; the same body under status 502 yields `BackendFailed` with reason `http_status`, and under status 404 `BackendFailed` with reason `model_not_found`, each with no raw exchange and usage with elapsed time only. | Test |
