# FR-048: Define a one-call structured extraction port

## Description

The Sapho core SHALL define an asynchronous Extractor port that turns one ExtractRequest into one schema-checked ExtractResponse or a typed ExtractError.

## Inputs

- `ExtractRequest.model`: the requested model identity, nonempty.
- `ExtractRequest.instructions`: the fixed task text, identical for every item of a task, nonempty.
- `ExtractRequest.input`: the text of one item and its context, nonempty. It never contains another item or an earlier answer.
- `ExtractRequest.schema`: a JSON Schema (draft 2020-12) object that the answer must match.

## Outputs

- `ExtractResponse.value`: the parsed JSON answer, already checked against `schema`.
- `ExtractResponse.usage`: provider-reported input tokens, output tokens and elapsed milliseconds, plus the adapter's input-token estimate when it made one.
- `ExtractResponse.raw`: the exact request bytes sent and the exact response bytes received, so a caller can store them by content hash.
- `ExtractResponse.model`: the actual model name and, when the provider reports one, its content digest.
- `ExtractError`: an ErrorCode, a message free of request and response content, and, when an exchange took place, the raw exchange and usage.

## Behavior

ModelBackend answers typed closed questions; Extractor returns one structured record in one call. Keeping them as two ports keeps each contract small and lets any backend offer extraction without transport code in core.

- The Extractor port SHALL take one ExtractRequest per call and carry no conversation, session or state between calls; two calls with equal requests are independent exchanges.
- When a request has an empty model, empty instructions, empty input, or a schema that is not a JSON object or does not compile, the core SHALL refuse it with code `Config` before any implementation is invoked.
- When an implementation returns a value, the core SHALL check the returned value against the request schema before the caller receives an ExtractResponse. Schema checking lives in the core, so every Extractor implementation gets the same validation.
- If the returned bytes are not JSON or the value violates the schema, then the core SHALL return an ExtractError with code `InvalidAnswer`, the JSON Pointer of the first violation, and the retained raw exchange and usage.
- If the input does not fit the model's context, then the implementation SHALL return an ExtractError with code `TooLarge`. `TooLarge` is a distinct ErrorCode so that a caller can record the item as too large and continue, separately from transport failures (`BackendFailed`, `DeadlineExceeded`, `LimitExceeded`).
- The core SHALL leave usage absent rather than invent token counts that the provider did not report.
- The core crate SHALL gain no runtime or transport dependency from this port, the same boundary as ModelBackend.
- The core SHALL offer a scripted Extractor double that downstream crates can use in their own tests; it returns configured values or errors in order and records the requests it received.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-048-AC-1 | A host-defined Extractor returns a schema-valid value; the caller receives value, usage, raw bytes and model identity unchanged. | Test |
| FR-048-AC-2 | A returned value that violates the schema, and returned bytes that are not JSON, each produce `InvalidAnswer` with the violation pointer and the retained raw exchange, never a panic. | Test |
| FR-048-AC-3 | An implementation's `TooLarge` error reaches the caller with code `TooLarge`, and a test tells it apart from `BackendFailed`, `DeadlineExceeded` and `LimitExceeded`. | Test |
| FR-048-AC-4 | Empty model, instructions or input, a non-object schema, and a schema that fails to compile are refused with `Config` before the implementation is called (the double records zero requests). | Test |
| FR-048-AC-5 | The scripted double is usable from another crate's tests and records each received request in order. | Test |
| FR-048-AC-6 | The core crate's dependency list contains no async runtime, HTTP or other transport crate after the port is added. | Inspection |
