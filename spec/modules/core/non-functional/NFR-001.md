# NFR-001: Crate boundaries

## Statement

The Sapho workspace SHALL maintain an acyclic crate dependency graph.

## Scope

core has no sibling dependency; graph depends on core; runtime depends on graph/core; recording, systemone and ollama depend on core only; jev and clm depend on core/systemone. Runtime logic lives in runtime rather than a transport or domain crate. Public APIs use typed IDs, exhaustive enums, Result and documented traits. Unsafe code is forbidden. No duplicated upstream code or compatibility layer is introduced.

## Measurement and Evaluation

| Metric | Target | Threshold | Method |
|--------|--------|-----------|--------|
| Forbidden sibling dependencies or unsafe blocks | 0 | 0 | Inspection |

## Verification

Run the scoped crate tests and inspect the dependency/serialization surfaces. At handoff run format, all-target/all-feature clippy, full workspace tests, documentation and supply-chain gates; no live calls are needed.
