# FR-048: Local Ollama typed inference

## Description

The Ollama adapter SHALL submit complete typed question/state requests to an explicitly configured loopback service and retain bounded raw exchange evidence independently of answer validity.

Context preflight refusal diagnostics SHALL contain only numeric prompt-byte,
output-token, template-reserve and context-token bounds, with the conservative
one-byte-per-token assumption identified. They SHALL disclose no state, source,
questions or model output, and SHALL not cause truncation or dispatch.

## Behavior

The host supplies model, loopback URL, timeout, request/response/context/output bounds. No service installation/download/training or domain questions. One asynchronous request per infer, redirects/retries disabled, concurrency one. Native /api/generate stream false with structured JSON answer output. Reported confidence is model self-report, not calibrated probability evidence; the declared local output contract requires null probability maps, and any returned violating map remains in raw evidence with a typed refusal. No synthesized confidence or mass, no repairing labels, no arbitrary JSON completion fallback. Truncation/end-of-budget responses refuse. Model response identity comes from service, not the requested alias. Complete core validation remains authoritative. Raw request/response and HTTP status are captured with made-call status even when JSON/span validation fails. Preflight oversize has no made call. Combined capture capacity is bounded and insufficient capacity refuses before dispatch. All time bounds include queue and body. Endpoint credentials/query/fragments/non-loopback redirects are prohibited. Model/context truncation is prevented by conservative byte/token upper bound and output reserve; no owner shortening. Prompt instructions are source-untrusted data, not tool authority.

The declared Ollama choice/score output schema requires probabilities=null. A
nonnull probability map violates that provider schema and is refused, retaining
the actual raw response and usage. Native Sapho distribution support is unchanged.

An explicit caller model pin is immutable for that backend session and must be
bound before its first invocation; invocation and first-time binding share a
short lock so concurrent startup cannot bypass the pin. The provider
rechecks the installed digest and completion capability while holding shared
capacity before each generation, retaining the source-free observation even when
drift causes zero dispatch. Metadata inspection is not generation. This binds the
reported alias identity; it does not make an atomic alias-to-served-weight claim.

## Shared local capacity

Hosts running competing workers SHALL supply one shared capacity-lock path for the
local model service. A new explicit constructor prepares this file synchronously
before execution. Each inference acquires an operating-system exclusive lease by
nonblocking lock attempts with asynchronous bounded waiting, before HTTP dispatch.
The lease remains held through response capture and decode. Cancellation and
process exit release the lease; no application mutex or database transaction is
held across await. The existing process-local constructor does not claim to
coordinate independent processes. Campaign CLIs require the shared path for live
Ollama work and disclose it separately from model correctness evidence.

The path names a stable regular file in an operator-owned directory. Refuse
symlinks, missing parent directories and failed lock acquisition; never delete or
replace the lock inode during operation. Every worker for the service must use the
same file, including workers using different model names. This coordinates these
clients; it cannot control unrelated clients that bypass the lease or guarantee
that a remote server has stopped generation after transport cancellation.
Queue waiting consumes the existing inference timeout and has no made-call receipt.


## Dependencies

sapho-core only among workspace crates. Provider confidence is explicitly self-reported heuristic. [Ollama generate contract](https://docs.ollama.com/api/generate).

## Explicit lossless framing

An operator may select framed_state_v1 instead of the historical complete-request
JSON format as a new recipe. Text state fields retain exact UTF8 bytes behind
byte-length/type headers; other values and all metadata/questions remain complete
typed JSON. No string is guessed to be JSON, no semantic sidecar is dropped, and
no question/source/limit is changed. Receipts identify the encoding and decompose
actual rendered instruction/question/state/envelope bytes. Legacy remains default.


## Pure request admission measurement

Hosts may measure one complete planned request without service inspection, capacity
acquisition or HTTP. RequestBudget uses the same typed prompt and HTTP body encoder
as dispatch and reports prompt components, typed request bytes and wire request
bytes under the explicit context/output/reserve and request byte caps. Measurement
does not establish whole-graph feasibility, transport dispatch or model quality.

## Lossless shared question catalogs

The explicit framed_catalog_v1 recipe retains V1 state framing and uses a typed question catalog. Instructions are ordered references to exact newline-inclusive text fragments; concatenating them reconstructs the complete original instruction. Equal answer spaces share a typed definition, preserving option/level order and all meanings. Each question retains its exact ID, kind and ordered instruction references. Boolean, Choice and Score are exhaustive. No hashing, shortening, omitted fragments or change to response schemas occurs. Typed request and raw wire receipts preserve the full original request and actual encoded prompt. Hosts must provide separate typed-question and catalog-prompt bounds; a typed JSON bound alone cannot establish catalog feasibility.
