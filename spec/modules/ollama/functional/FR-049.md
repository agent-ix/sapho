# FR-049: Send one stateless generate request per extraction

## Description

When a caller extracts through an Ollama binding, the Ollama adapter SHALL send exactly one non-streaming generate request built only from that call's ExtractRequest and the binding's settings.

## Inputs

- One ExtractRequest (model, instructions, input, schema).
- The binding: base URL, model, `think` (true or false, always explicit), `num_ctx`, `num_predict`, `max_bytes_per_token`, timeout and byte ceilings.

## Outputs

- The parsed answer value, usage, model identity and raw exchange, handed to the core port for schema checking.
- A typed ExtractError for a refused, failed or unusable exchange.

## Behavior

A request that holds only fixed instructions, one input and one schema gives the model the same small, complete question every time, so its context limit concerns one item rather than a whole run.

- The adapter SHALL POST to `<base>/api/generate` a JSON body with exactly these members: `model`, `system` (the instructions), `prompt` (the input), `format` (the schema), `think` (the binding's explicit Boolean), `stream: false`, `truncate: false`, `shift: false`, and `options` holding `temperature: 0`, `num_ctx` and `num_predict` from the binding. With `truncate: false` the server refuses a prompt longer than `num_ctx` instead of shortening it, and with `shift: false` it stops generation at the context limit instead of discarding earlier tokens ([FR-050](FR-050.md)).
- The adapter SHALL NOT send `context`, `messages`, `images`, `template`, `raw` or `suffix`.
- The adapter SHALL NOT keep conversation or token context between calls; it ignores the `context` member that Ollama returns.
- When a binding is constructed, the adapter SHALL refuse it with `Config` if `num_ctx` or `num_predict` is zero, if `num_predict` is not smaller than `num_ctx`, if `max_bytes_per_token` is not finite and positive, or if the model name is empty.
- When the response is complete (`done: true` and `done_reason` other than `length`), the adapter SHALL parse its `response` text as JSON and return it as the answer value.
- If `done_reason` is `length`, then the adapter SHALL return `InvalidAnswer` with reason `output_truncated` and the retained raw exchange, because the answer stopped at the output limit.
- If the `response` text is empty, then the adapter SHALL return `InvalidAnswer` with reason `empty_response` and the retained raw exchange.
- If the `response` text is not JSON, then the adapter SHALL return `InvalidAnswer` with reason `not_json` and the retained raw exchange.
- The adapter SHALL exclude the returned `thinking` text from the answer value in every case; the text stays only in the raw response bytes.

Measured on Ollama 0.32.14 with `qwen3:30b`: with `think: true` and a `format` schema, the server returns the schema-constrained JSON in `thinking` and an empty `response`, with no separate reasoning. Such a binding therefore yields `empty_response` on that server; whether thinking helps a task is decided by measurement against the task's reference set, and the outcome is visible in the run's failure reasons.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-049-AC-1 | A capturing loopback server receives one POST to `/api/generate` whose body has exactly the listed members with `system`, `prompt` and `format` equal to the request's instructions, input and schema, `stream: false`, `truncate: false`, `shift: false`, `temperature: 0` and the binding's `think`, `num_ctx` and `num_predict` (checked for `think` true and false). | Test |
| FR-049-AC-2 | After a first extraction whose input carries sentinel string S1 and whose scripted response carries sentinel S2 and a `context` array, the second captured request body contains neither S1, S2 nor any number of that `context` array, and has no `context`, `messages`, `images`, `template`, `raw` or `suffix` member. | Test |
| FR-049-AC-3 | A response with `done_reason: length` gives `InvalidAnswer` with reason `output_truncated`; an empty `response` with non-empty `thinking` gives reason `empty_response`; a non-JSON `response` gives reason `not_json`; each retains the raw exchange. | Test |
| FR-049-AC-4 | Zero `num_ctx`, zero `num_predict`, `num_predict` not below `num_ctx`, a non-finite or non-positive `max_bytes_per_token` and an empty model are refused at binding construction, and no request is sent. | Test |
| FR-049-AC-5 | A response carrying both a JSON `response` and `thinking` text yields an answer value equal to the parsed `response` only, while the raw response bytes still contain the thinking text. | Test |
