# FR-049: Send one stateless generate request per extraction

## Description

When a caller extracts through an Ollama binding, the Ollama adapter SHALL send exactly one non-streaming generate request built only from that call's ExtractRequest and the binding's settings.

## Inputs

- One ExtractRequest (model, instructions, input, schema).
- The binding: base URL, model, `think` (true or false, always explicit), `num_ctx`, `num_predict`, bytes-per-token ratio, timeout and byte ceilings.

## Outputs

- The parsed answer value, usage, model identity and raw exchange, handed to the core port for schema checking.
- A typed ExtractError for a refused, failed or unusable exchange.

## Behavior

A request that holds only fixed instructions, one input and one schema gives the model the same small, complete question every time, so its context limit concerns one item rather than a whole run.

- The adapter SHALL POST to `<base>/api/generate` a JSON body with exactly these members: `model`, `system` (the instructions), `prompt` (the input), `format` (the schema), `think` (the binding's explicit Boolean), `stream: false`, and `options` holding `temperature: 0`, `num_ctx` and `num_predict` from the binding.
- The adapter SHALL NOT send `context`, `messages`, `images`, `template`, `raw` or `suffix`.
- The adapter SHALL NOT keep conversation or token context between calls.
- When a binding is constructed, the adapter SHALL refuse it with `Config` if `num_ctx` or `num_predict` is zero, when `num_predict` is not smaller than `num_ctx`, when the bytes-per-token ratio is not finite and positive, or when the model name is empty.
- When the response is complete (`done: true` and `done_reason` other than `length`), the adapter SHALL parse its `response` text as JSON and return it as the answer value.
- If `done_reason` is `length`, then the adapter SHALL return `InvalidAnswer` with reason `output_truncated` and the retained raw exchange, because the answer stopped at the output limit.
- If the `response` text is not JSON, then the adapter SHALL return `InvalidAnswer` with the retained raw exchange.
- While thinking is on, the adapter SHALL exclude the returned `thinking` text from the answer value; the text stays only in the raw response bytes.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-049-AC-1 | A capturing loopback server receives one POST to `/api/generate` whose body has exactly the listed members with `system`, `prompt` and `format` equal to the request's instructions, input and schema, `stream: false`, `temperature: 0` and the binding's `think`, `num_ctx` and `num_predict` (checked for `think` true and false). | Test |
| FR-049-AC-2 | After two consecutive extractions with different inputs, the second captured body contains no byte sequence from the first input or first response and has no `context`, `messages`, `images`, `template`, `raw` or `suffix` member. | Test |
| FR-049-AC-3 | A response with `done_reason: length` gives `InvalidAnswer` with reason `output_truncated`; a non-JSON `response` gives `InvalidAnswer`; both retain the raw exchange. | Test |
| FR-049-AC-4 | Zero `num_ctx`, zero `num_predict`, `num_predict` not below `num_ctx`, a non-finite or non-positive ratio and an empty model are refused at binding construction, and no request is sent. | Test |
| FR-049-AC-5 | With thinking on, a response carrying `thinking` text yields an answer value equal to the parsed `response` only, while the raw response bytes still contain the thinking text. | Test |
