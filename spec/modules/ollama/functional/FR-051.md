# FR-051: Serialize and bound Ollama HTTP calls

## Description

The Ollama adapter SHALL keep at most one Ollama HTTP request in flight per process, each bounded by the binding's timeout and byte ceilings.

## Inputs

- Host configuration: base URL (default `http://127.0.0.1:11434`), timeout (default 600 seconds), request ceiling (default 4 MiB) and response ceiling (default 16 MiB).
- Optional request headers, set with `Server::with_header(name, value)` and sent with every request, for example to authenticate at a gateway in front of the server. Their values are sensitive: they never appear in a raw exchange, an error, a trace, a recording, `Debug` output or a log.

## Outputs

- One exchange at a time across every binding, extraction and embedding in the process.
- Typed errors for configuration, transport, timeout and size failures.

## Behavior

A local server runs one large model on one GPU; sending one request at a time keeps latency measurements meaningful and avoids the server queueing or swapping models under load.

- The adapter SHALL hold one process-wide permit for the full duration of each HTTP exchange, shared by all Ollama bindings and embedding calls, so that at most one request is in flight.
- When a call is cancelled, the adapter SHALL release its permit.
- The adapter SHALL refuse with `Config`, before sending, a base URL whose scheme is not `http` or `https` or that carries userinfo, a query or a fragment, and zero timeout or ceiling values.
- If the timeout expires while waiting for the permit, sending, or reading the response, then the adapter SHALL return `DeadlineExceeded`.
- If a serialized request exceeds the request ceiling, then the adapter SHALL refuse it with `LimitExceeded` before sending.
- If a response exceeds the response ceiling, then the adapter SHALL stop reading at the ceiling and return `LimitExceeded`, independent of `Content-Length`.
- The adapter SHALL make exactly one attempt per call, with redirects and retries disabled.
- The adapter SHALL check the HTTP status before decoding the body.
- The adapter SHALL map HTTP 404 to `BackendFailed` with reason `model_not_found`, other non-success statuses to `BackendFailed` with reason `http_status`, and connection failures to `BackendFailed`, except the two size refusals that it recognises from a 400 status and a decodable body naming the refusal, which are `TooLarge` ([FR-050](FR-050.md), [FR-053](FR-053.md)); every non-success response carries no raw exchange and only the elapsed time as usage ([FR-048](../../core/functional/FR-048.md)).
- Error messages SHALL NOT contain request or response bodies; the raw bytes travel only in the error's raw exchange field.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-051-AC-1 | Two concurrent callers on different bindings against a loopback server that records overlap observe zero overlapping requests, and a cancelled waiting call lets the next call proceed. | Test |
| FR-051-AC-2 | URLs with an unsupported scheme, userinfo, query or fragment, and zero limits, are refused with `Config` and nothing is sent. | Test |
| FR-051-AC-3 | A stalled server yields `DeadlineExceeded` at the configured timeout; a request over its ceiling is refused before sending; a response over its ceiling stops with `LimitExceeded`. | Test |
| FR-051-AC-4 | A 404 yields `BackendFailed` with reason `model_not_found` and a 500 with reason `http_status`, also when their bodies are not UTF-8, each with no raw exchange; a 500 and a redirect each yield `BackendFailed` after exactly one attempt; no error message contains a sentinel string placed in the request or response body. | Test |
| FR-051-AC-5 | A header set with `Server::with_header` reaches the loopback server on every request, while its sentinel value is absent from the raw exchange, from every error and from the `Debug` output of the server configuration. | Test |
| FR-051-AC-6 | A 400 whose UTF-8 body carries `exceed_context_size_error` yields `TooLarge`; a 400 with a body that is not UTF-8 yields `BackendFailed` with reason `http_status`; a 400 with a readable body naming another error yields `BackendFailed` with reason `http_status`; none carries a raw exchange. | Test |
