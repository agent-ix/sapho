# FR-053: Embed text through the same serialized client

## Description

When a caller requests embeddings, the Ollama adapter SHALL send one `POST <base>/api/embed` request with an ordered list of input texts and return one vector per input in the same order.

## Inputs

- An embedding binding: base URL, model and maximum inputs per request (default 32).
- An ordered, nonempty list of input texts no longer than that maximum.

## Outputs

- One finite vector per input, in input order, all of equal length.
- The response model name, `prompt_eval_count` when reported, and the raw exchange.

## Behavior

Near-duplicate detection needs embeddings from the same local server. Routing them through this client keeps the one-request-at-a-time rule for the whole process.

- The adapter SHALL send `model`, `input` (the ordered list) and `truncate: false`, so that the server refuses an over-long input instead of silently shortening it.
- If the server answers HTTP 400 with the error text `the input length exceeds the context length` (the refusal Ollama 0.32.14 gives with `truncate: false`), then the adapter SHALL return `TooLarge` with reason `input_exceeds_context`, no raw exchange and only the elapsed time as usage; any other 400 is `BackendFailed` with reason `http_status` ([FR-051](FR-051.md)).
- If the response holds a different number of vectors than inputs, vectors of unequal length, or a non-finite component, then the adapter SHALL return `InvalidAnswer` with the retained raw exchange.
- The adapter SHALL refuse an empty list or a list longer than the binding's maximum with `Config` before sending.
- Embedding requests SHALL use the process-wide permit and bounds of [FR-051](FR-051.md) and the model availability check of [FR-052](FR-052.md).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-053-AC-1 | A capturing loopback server receives `model`, the ordered `input` list and `truncate: false`; three inputs return three vectors in input order with the response model name. | Test |
| FR-053-AC-2 | A scripted HTTP 400 with that error text yields `TooLarge` with reason `input_exceeds_context`, while a 400 with another text, or with a body that is not UTF-8, yields `BackendFailed` with reason `http_status`; a vector count mismatch, unequal lengths and a non-finite component each yield `InvalidAnswer`. | Test |
| FR-053-AC-3 | An empty list and a list over the maximum are refused with `Config` and nothing is sent. | Test |
| FR-053-AC-4 | An embedding call and an extraction call issued concurrently never overlap at the server. | Test |
