# FR-050: Count prompt size in tokens and report inputs that do not fit

## Description

The Ollama adapter SHALL measure prompt size in model tokens, estimated before a call and checked against the server's reported `prompt_eval_count` after it, returning `TooLarge` for an input that does not fit the binding's context.

## Inputs

- The UTF-8 bytes of `system`, `prompt` and the serialized `format` schema of one request.
- The binding's `num_ctx`, `num_predict` and bytes-per-token ratio (default 3.0).
- The response's `prompt_eval_count`.

## Outputs

- `usage.estimated_input_tokens` and `usage.input_tokens` on every completed exchange.
- An `estimate_exceeded` flag when the reported count exceeds the estimate by more than the tolerance.
- `TooLarge` for an input that does not fit.

## Behavior

Context limits are counted in the model's tokens, not in bytes. A model such as Qwen3 averages about 3.5 bytes of English text per token, so the default ratio of 3.0 overestimates slightly and leaves a margin. The server reports the real count after each call, and the difference is kept so that the ratio can be corrected from evidence.

- When a request is about to be sent, the adapter SHALL compute `estimated_input_tokens` as the combined UTF-8 byte length of `system`, `prompt` and the serialized schema divided by the binding's bytes-per-token ratio, rounded up.
- If `estimated_input_tokens + num_predict` exceeds `num_ctx`, then the adapter SHALL return `TooLarge` without sending a request, reporting the estimate and the limit.
- If a response reports `prompt_eval_count + num_predict` above `num_ctx`, then the adapter SHALL return `TooLarge` with the retained raw exchange and usage, because the server can shorten a prompt to fit its context.
- If the response lacks `prompt_eval_count` or `eval_count`, then the adapter SHALL return `InvalidAnswer` with the retained raw exchange instead of inventing counts.
- When `prompt_eval_count` exceeds `estimated_input_tokens` by more than 15 percent of the estimate, the adapter SHALL set `estimate_exceeded` on the response's usage; both numbers are always kept.
- The adapter SHALL NOT shorten, compress or re-encode any part of a request to make it fit.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-050-AC-1 | With `num_ctx` 1000, `num_predict` 200 and ratio 3.0, an input whose estimate is 801 tokens is refused with `TooLarge` and the loopback server records zero requests; an input estimated at 800 tokens is sent. | Test |
| FR-050-AC-2 | A sent request whose response reports `prompt_eval_count` 900 with `num_ctx` 1000 and `num_predict` 200 yields `TooLarge` with raw exchange and usage retained, and the caller can continue with its next item. | Test |
| FR-050-AC-3 | A reported count 16 percent above the estimate sets `estimate_exceeded`; 15 percent above does not; both cases keep the estimate and the reported count. | Test |
| FR-050-AC-4 | A response missing `prompt_eval_count` or `eval_count` yields `InvalidAnswer` and no usage values are fabricated. | Test |
| FR-050-AC-5 | A non-ASCII input is estimated from its UTF-8 byte length, and the request body carries the input bytes unchanged. | Test |
