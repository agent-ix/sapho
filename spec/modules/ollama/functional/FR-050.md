# FR-050: Count prompt size in tokens and report inputs that do not fit

## Description

The Ollama adapter SHALL return `TooLarge` with its numbers for every input whose prompt does not fit the binding's context, using the server's own token count as the authority, a lower-bound estimate only to skip requests that cannot fit, and no shortening of any prompt.

## Inputs

- The UTF-8 bytes of `system`, `prompt` and the serialized `format` schema of one request.
- The binding's `num_ctx`, `num_predict` and `max_bytes_per_token` (default 6.0).
- The server's context refusal, or the response's `prompt_eval_count` and `eval_count`, when present.

## Outputs

- `usage.estimated_input_tokens` on every request; `usage.input_tokens` and `usage.output_tokens` when the server reported them.
- A `below_estimate` flag when the reported count is lower than the estimate.
- `TooLarge` with `estimated_input_tokens`, `reported_input_tokens` (when the server counted the prompt), `context_tokens` (`num_ctx`) and `reserved_output_tokens` (`num_predict`).

## Behavior

Context limits are counted in the model's tokens, and only the server's tokenizer knows the count. Measured on Ollama 0.32.14 with `qwen3:30b`, bytes per token vary by a factor of five: English prose about 5.3, Rust code 3.5, Chinese text 4.1, identifiers 2.2, tables 1.3 and digit lists 1.0. No byte ratio is a safe upper bound on tokens, so the adapter does not rely on one. Instead it asks the server to refuse: with `truncate: false` the same server answers a prompt longer than `num_ctx` with HTTP 400, error type `exceed_context_size_error` and the exact `n_prompt_tokens`, where it would otherwise keep only part of the prompt and answer from the shortened text. The byte estimate divides by the largest measured bytes per token, so it is a lower bound on the token count: when even the lower bound does not fit, the request is pointless and is not sent.

- When a request is about to be sent, the adapter SHALL compute `estimated_input_tokens` as the combined UTF-8 byte length of `system`, `prompt` and the serialized schema divided by `max_bytes_per_token`, rounded up.
- If `estimated_input_tokens + num_predict` exceeds `num_ctx`, then the adapter SHALL return `TooLarge` without sending a request.
- If the server answers HTTP 400 with error type `exceed_context_size_error`, then the adapter SHALL return `TooLarge` with `reported_input_tokens` set to the server's `n_prompt_tokens`.
- If a response reports `prompt_eval_count + num_predict` above `num_ctx`, then the adapter SHALL return `TooLarge` with the retained raw exchange and usage, because the prompt left too little room for the answer; this takes precedence over `output_truncated`.
- When a response reports `prompt_eval_count` below `estimated_input_tokens`, the adapter SHALL set `below_estimate` on the response's usage, evidence that `max_bytes_per_token` is too low for this text; both numbers are always kept.
- If a response lacks `prompt_eval_count` or `eval_count`, then the adapter SHALL return the answer with that count absent from usage, `below_estimate` unset and no post-call check; a missing count is never an error and never causes a retry.
- The adapter SHALL NOT shorten, compress or re-encode any part of a request to make it fit.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-050-AC-1 | With `num_ctx` 1000, `num_predict` 200 and `max_bytes_per_token` 6.0, an input of 4,806 bytes in total (estimate 801) is refused with `TooLarge` carrying estimate 801, context 1000 and reserved output 200, and the loopback server records zero requests; an input of 4,800 bytes (estimate 800) is sent. | Test |
| FR-050-AC-2 | A scripted HTTP 400 whose body carries error type `exceed_context_size_error` and `n_prompt_tokens` 4112 yields `TooLarge` with reported count 4112; a 400 of another type yields `BackendFailed`. | Test |
| FR-050-AC-3 | A response reporting `prompt_eval_count` 900 with `num_ctx` 1000, `num_predict` 200 and `done_reason: length` yields `TooLarge` with reported count 900, not `output_truncated`, with raw exchange and usage retained, and the caller can continue with its next item. | Test |
| FR-050-AC-4 | A reported count below the estimate sets `below_estimate`; one at or above it does not; both cases keep the estimate and the reported count. | Test |
| FR-050-AC-5 | A response missing `prompt_eval_count`, and one missing `eval_count`, each return the schema-valid answer with that usage count absent and no error; repeating the call gives the same result. | Test |
| FR-050-AC-6 | A non-ASCII input is estimated from its UTF-8 byte length, and the request body carries the input bytes unchanged. | Test |
