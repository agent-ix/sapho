# FR-052: Record model identity, usage and raw bodies

## Description

The Ollama adapter SHALL attach the reported model name, the reported usage and the exact request and response bytes to every completed exchange.

## Inputs

- The model availability response from `POST <base>/api/show` for the binding's model.
- Each response's `model`, `prompt_eval_count`, `eval_count`, `total_duration`, `load_duration`, `prompt_eval_duration` and `eval_duration`.

## Outputs

- `model`: the name the inference response reported.
- `usage`: `input_tokens` from `prompt_eval_count`, `output_tokens` from `eval_count`, elapsed milliseconds from `total_duration`, and the server's load, prompt and generation durations.
- `raw`: the request body exactly as sent and the response body exactly as received, as a RawExchange ([FR-048](../../core/functional/FR-048.md)); never HTTP headers or URLs.

## Behavior

A label is only as traceable as its exchange. The raw bytes let anyone check what was sent and returned. Ollama's generate and embed replies report a model name but do not attest which weights answered. A model availability check cannot establish that identity: another writer could retag the model before inference and change it back afterward. Sapho therefore makes no answering-weight identity claim from this adapter. An operator who needs run-level source attribution must control model writes to a dedicated instance for the entire run and retain the operating evidence outside the exchange ([procedure](../../../../docs/ollama-provenance.md)).

- When a generate or embed request is about to be sent, the adapter SHALL check that the server knows the binding's model.
- If the server does not know the binding's model, then the adapter SHALL refuse with `Config` and reason `model_not_installed`, sending no generate or embed request.
- If the name reported by a generate response differs from the binding's model, then the adapter SHALL return `ModelMismatch` with reason `name_mismatch` and the retained raw exchange.
- The adapter SHALL return the raw request and response bodies on every exchange whose response has a success status, on success and inside every error raised after such a response arrived, for extraction in the ExtractResponse or ExtractError and for questions in the ModelResponse or SaphoError ([FR-006](../../core/functional/FR-006-define-replaceable-model-backend.md)). Two cases carry no raw exchange and only the elapsed time as usage: a non-success status, which is `BackendFailed` or, for a recognised size refusal, `TooLarge` ([FR-051](FR-051.md)), and a success status whose body is not valid UTF-8, which is `malformed_response` because the body cannot be held as text ([FR-048](../../core/functional/FR-048.md)).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-052-AC-1 | Against a loopback server, a successful extraction carries the response model name, `input_tokens` and `output_tokens` equal to the reported counts, elapsed milliseconds from `total_duration`, and the three server durations. | Test |
| FR-052-AC-2 | The returned raw request body equals the body the server received, and the raw response body equals the body it sent. | Test |
| FR-052-AC-3 | A model the server does not know is refused with `Config` and `model_not_installed`, and the server records no generate request. | Test |
| FR-052-AC-4 | A response naming a different model yields `ModelMismatch` with `name_mismatch` and the raw exchange; a changed model description alone is not treated as evidence of the answering weights. | Test |
| FR-052-AC-5 | Two bindings for different tags retain their distinct response model names, without inferring source equivalence from the model descriptions. | Test |
| FR-052-AC-6 | Model availability checks use the configured server URL, headers and request bounds; an unknown model yields `Config` and `model_not_installed` before inference. | Test |
| FR-052-AC-7 | When a scripted external writer retags a model between availability check and inference, the exchange retains only the response model name and raw bodies. Documentation states that those fields cannot attest answering weights and describes the run-level model-write boundary. | Test, Inspection |

## Dependencies
