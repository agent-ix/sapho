# FR-052: Record model identity, usage and raw bodies

## Description

The Ollama adapter SHALL attach the reported model name, the weights digest observed immediately before the request, the reported usage and the exact request and response bytes to every completed exchange.

## Inputs

- The server's model description from `POST <base>/api/show` for the binding's model.
- Each response's `model`, `prompt_eval_count`, `eval_count`, `total_duration`, `load_duration`, `prompt_eval_duration` and `eval_duration`.

## Outputs

- `model`: the name the server reported and the pre-request weights digest `sha256:<hex>`.
- `usage`: `input_tokens` from `prompt_eval_count`, `output_tokens` from `eval_count`, elapsed milliseconds from `total_duration`, and the server's load, prompt and generation durations.
- `raw`: the request body exactly as sent and the response body exactly as received, as a RawExchange ([FR-048](../../core/functional/FR-048.md)); never HTTP headers or URLs.

## Behavior

A label is only as traceable as its exchange. The recorded digest identifies the weights named by `/api/show` immediately before the request; the raw bytes let anyone check what was sent and returned. A model tag alone does not identify weights, because one set of weights can be served under several tags with different parameters (on a local server, `qwen3:30b`, `qwen3:30b-opencode` and `qwen3:30b-opencode-32k` all load the weights blob `sha256:58574f2e94b9…`). Ollama's generate and embed replies report a model name, not the digest of the weights that answered. Therefore the recorded digest is evidence of answering weights only when the operator controls all model writes to the server throughout the exchange. Sapho cannot enforce that server-side condition. Reading `/api/show` again after the call cannot establish it, because another writer could change the tag and change it back.

- When a generate or embed request is about to be sent, the adapter SHALL first read the model description and take the weights digest from the blob named in its `FROM` line.
- `Server::weights_digest` SHALL expose an unpinned lookup of the current weights digest through the configured server URL, headers and request bounds. A later lookup reports the current digest after the model changes. Generate and embed requests retain their own per-binding pin.
- If the server does not know the binding's model, then the adapter SHALL refuse with `Config` and reason `model_not_installed`, sending no generate or embed request.
- If the pre-request weights digest differs from the one the binding resolved first, then the adapter SHALL return `ModelMismatch` with reason `weights_changed`, sending no generate or embed request. This detects changes between calls; it does not detect an external retag between `/api/show` and generate or embed.
- If the name reported by a generate response differs from the binding's model, then the adapter SHALL return `ModelMismatch` with reason `name_mismatch` and the retained raw exchange.
- The adapter SHALL return the raw request and response bodies on every exchange whose response has a success status, on success and inside every error raised after such a response arrived, for extraction in the ExtractResponse or ExtractError and for questions in the ModelResponse or SaphoError ([FR-006](../../core/functional/FR-006-define-replaceable-model-backend.md)). Two cases carry no raw exchange and only the elapsed time as usage: a non-success status, which is `BackendFailed` or, for a recognised size refusal, `TooLarge` ([FR-051](FR-051.md)), and a success status whose body is not valid UTF-8, which is `malformed_response` because the body cannot be held as text ([FR-048](../../core/functional/FR-048.md)).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-052-AC-1 | Against a loopback server, a successful extraction carries the weights digest from the description's `FROM` line, `input_tokens` and `output_tokens` equal to the reported counts, elapsed milliseconds from `total_duration`, and the three server durations. | Test |
| FR-052-AC-2 | The returned raw request body equals the body the server received, and the raw response body equals the body it sent. | Test |
| FR-052-AC-3 | A model the server does not know is refused with `Config` and `model_not_installed`, and the server records no generate request. | Test |
| FR-052-AC-4 | When the scripted description changes its `FROM` blob between two calls, the second call returns `ModelMismatch` with `weights_changed` and no generate request is recorded for it; a response naming a different model yields `ModelMismatch` with `name_mismatch` and the raw exchange. | Test |
| FR-052-AC-5 | Two bindings for different tags whose descriptions name the same `FROM` blob report the same weights digest. | Test |
| FR-052-AC-6 | A public `Server` lookup posts the named model through configured headers and returns a changed digest on a second call without pinning; an unknown model yields `Config` and `model_not_installed`. | Test |
| FR-052-AC-7 | When a scripted external writer retags the model after `/api/show` reports digest A and before generate returns a response with the same model name, the exchange retains A as a pre-request observation; it does not claim that A answered. Documentation requires exclusive model-write control before treating this digest as answering-weights provenance and states that a second `/api/show` cannot prove it. | Test, Inspection |
