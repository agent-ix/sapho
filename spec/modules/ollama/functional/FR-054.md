# FR-054: Answer typed questions from answer-token log-probabilities

## Description

When a graph asks typed questions through an Ollama binding, the Ollama ModelBackend SHALL answer all questions of one ModelRequest in one generate request whose answer is constrained to the questions' allowed values, with each answer's probabilities derived from the log-probabilities the server reports for the answer tokens.

## Inputs

- One ModelRequest: a Record state and ordered Boolean, Choice and Score questions.
- An Ollama binding with `think: false`, `num_ctx`, `num_predict`, bytes-per-token ratio, timeout and ceilings.

## Outputs

- A ModelResponse with the reported model name, the weights digest ([FR-052](FR-052.md)), one Answer per question and usage.
- Typed errors as for extraction, with `TooLarge` details carried as named error context fields `estimated_input_tokens`, `reported_input_tokens`, `context_tokens` and `reserved_output_tokens`.

## Behavior

Sapho answers carry probabilities, not just a choice. Constraining the answer with a JSON Schema enum makes the model pick one allowed value, and the server's log-probabilities at the token where that value starts show how much weight the model gave each allowed value. Measured on Ollama 0.32.14 with `qwen3:30b`: a request with `logprobs: true` returns, for every generated token, its own log-probability and up to `top_logprobs` alternatives (the server refuses values above 20). The alternatives are the model's distribution before the schema constraint is applied, so they can include values the schema forbids (for example `Yes` next to the allowed `yes`) and can omit allowed values entirely (a Choice label was generated at log-probability −8.3 while the 20 listed alternatives were all other words).

- The adapter SHALL send the generate request shape of [FR-049](FR-049.md) with `think: false`, `logprobs: true` and `top_logprobs: 20`, where:
  - `system` is a fixed text: "Answer every question about the input. Reply with JSON only." followed, for each question in order, by its ID and instructions and then, for Boolean, the meanings of `yes` and `no`; for Choice, each option label with its description; for Score, each level index with its description;
  - `prompt` is the request's Record state serialized as canonical JSON (sorted keys, no insignificant whitespace);
  - `format` is a JSON Schema object with one required string member per question ID, in question order and with no other members: Boolean questions allow `yes` and `no`, Choice questions allow the option labels, and Score questions allow the level indices written as decimal strings.
- When a binding with `think: true` is used for questions, the adapter SHALL refuse it with `Config` and reason `think_unsupported_for_questions`, because on the measured server thinking moves the constrained answer into `thinking` and the answer tokens' log-probabilities no longer belong to an answer.
- The adapter SHALL apply the token counting and `TooLarge` rules of [FR-050](FR-050.md) to the request.
- If the response has no `logprobs`, then the adapter SHALL return `Config` with reason `logprobs_unavailable`; there is no answer without probabilities.
- If the concatenated bytes of the `logprobs` tokens differ from the bytes of `response`, then the adapter SHALL return `InvalidAnswer` with reason `logprobs_mismatch`.
- For each question, the answer position SHALL be the generated token that contains the first byte of that member's value inside the response JSON. An alternative listed at that position is attributed to an allowed value when its bytes, from the value's first byte on, are a nonempty prefix of that value and of no other allowed value of the question. The generated token is always attributed to the selected value.
- If the generated token at an answer position is a prefix of more than one allowed value, then the adapter SHALL return `InvalidAnswer` with reason `ambiguous_answer_token` for that question; label sets whose values begin with distinct tokens avoid it.
- The mass of an allowed value SHALL be the sum of exp(log-probability) of the tokens attributed to it. The mass of an allowed value with no attributed token is unknown; the adapter SHALL bound it by `b`, the smaller of the lowest listed alternative's probability and the selected value's mass, because greedy constrained decoding at temperature 0 selects the allowed value with the highest mass.
- A Boolean answer's probability SHALL be m(yes) / (m(yes) + m(no)), with `b` standing in for a value that has no attributed token; the substitute pulls the probability toward 0.5, so an incomplete listing never makes an answer look more certain than the listed evidence shows.
- A Choice answer SHALL carry the selected label, `probabilities` for the labels with attributed mass, each m(v) / Z with Z the sum of attributed masses plus `b` for every unattributed label, and `confidence` equal to the selected label's probability; the distribution is Complete when every label has attributed mass and Partial otherwise.
- A Score answer SHALL carry `probabilities` per level computed as for Choice, `expected` equal to the probability-weighted mean of the levels with attributed mass divided by their total probability, and `confidence` equal to the selected level's probability.
- The adapter SHALL keep the raw request and response bytes, including every listed alternative, so each probability can be recomputed from the record.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-054-AC-1 | A capturing loopback server receives one request per ModelRequest with `think: false`, `logprobs: true`, `top_logprobs: 20`, the fixed system text, the canonical state as prompt, and a `format` schema whose members and enums match a mixed Boolean, Choice and Score question block in order. | Test |
| FR-054-AC-2 | With scripted log-probabilities −2.228 for `yes` and −5.759 for `no` at the answer position, the Boolean probability is 0.9715 within 1e-4; with `no` absent and the lowest listed alternative at −9.68, the probability uses that bound. | Test |
| FR-054-AC-3 | A Choice answer whose labels are all listed yields a Complete distribution summing to 1; one with an unlisted label yields a Partial distribution and a confidence equal to the selected label's probability under the bound. | Test |
| FR-054-AC-4 | A response without `logprobs` yields `Config` with `logprobs_unavailable`; token bytes that do not concatenate to `response` yield `InvalidAnswer` with `logprobs_mismatch`; a generated token that prefixes two labels yields `InvalidAnswer` with `ambiguous_answer_token`; none of these produces an answer. | Test |
| FR-054-AC-5 | A question binding with `think: true` is refused with `Config` and `think_unsupported_for_questions` before any request is sent. | Test |
| FR-054-AC-6 | An oversized state yields `TooLarge` with the four numeric context fields readable without parsing the message, and no request is sent. | Test |
| FR-054-AC-7 | The returned ModelResponse validates under core answer validation for Strict and Approximate policies and carries the weights digest. | Test |
