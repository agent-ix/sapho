# US-012: Extract one structured record per item with a local model

## Story

**As a** dataset author
**I want** to send each item to a locally served model once and get back a record that matches my schema
**So that** I can label many items cheaply while knowing exactly which model produced each answer and why an item was skipped.

## Acceptance Examples (Illustrative)

- Given a running server with the model installed, when I extract a record for one item, then I receive a schema-valid value, token counts, timing, the response model name and the raw exchange.
- Given an item whose prompt exceeds the configured context, when I extract it, then I receive a too-large refusal and nothing about the item is cut to fit.
- Given yes/no and pick-one questions about an item, when I ask them, then one call answers all of them with a probability for each answer.
- Given two callers in one process, when both extract at once, then the server receives one request at a time.

## Constraints (Contextual)

The server is installed and started by the host. Domain instructions and schemas come from the author's application.

## Priority and Risk (Informative)

High priority: dataset labelling depends on it. The main risks are miscounted context, silent truncation and state leaking between calls.
