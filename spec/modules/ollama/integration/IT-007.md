# IT-007: Extract through a loopback Ollama server

## Objective

Verify the production Ollama HTTP adapter end to end through the core Extractor port, with no model installed: request shape, schema checking, token accounting, serialization and recorded identity.

## Target Integration

Core Extractor call and ModelBackend call → `sapho-ollama` adapter → ephemeral loopback HTTP server that imitates `/api/show` and `/api/generate` and records every request it receives.

## Preconditions

An ephemeral loopback listener and synthetic schemas and inputs. No real model, network or credential.

## Inputs

A small JSON Schema, three short inputs, one input sized beyond the configured context, scripted responses: one valid, one schema-violating, one with an oversized `prompt_eval_count`.

## Test Procedure

1. Extract the first input.
   - IT-007-SC-01: the server records one generate request with the exact member set, and the caller receives a schema-valid value with digest, usage and raw bytes equal to the exchanged bytes.
2. Extract with a scripted schema-violating response.
   - IT-007-SC-02: the caller receives `InvalidAnswer` with the violation pointer and the raw exchange.
3. Extract the oversized input.
   - IT-007-SC-03: the caller receives `TooLarge` and the server records no request for it.
4. Extract with a scripted oversized `prompt_eval_count`.
   - IT-007-SC-04: the caller receives `TooLarge` with raw exchange and usage retained.
5. Issue two extractions concurrently.
   - IT-007-SC-05: the server never observes two requests in flight.
6. Ask a Boolean and a Choice question through the ModelBackend with scripted log-probabilities.
   - IT-007-SC-06: one request is recorded and the validated Answers carry the probabilities computed from the scripted log-probabilities.

## Expected Results

Each step matches its success criterion, the server's request log shows no conversation state, and no step depends on a live model.
