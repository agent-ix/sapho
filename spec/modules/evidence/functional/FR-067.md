# FR-067: Report labelled metrics by declared slice and window

## Description

When a caller requests a slice report for a selected Dataset split, the evidence calculator SHALL partition selected cases by a declared typed input path and report each slice's existing per-output coverage and metrics with explicit differences from the overall result.

## Inputs

The existing validated Dataset, selected split, output schemas, case outcomes, a validated path consisting of an input name followed by zero or more Record field names, and a positive minimum selected-case count. An optional caller-supplied map of selected case IDs to one of two distinct window names enables reference/current window comparison; the Dataset supplies no timestamp.

## Outputs

A versioned report with the declared selector, split, minimum count, overall per-output measurement, ordered slice entries, and optional ordered reference/current window measurements partitioned by the same slices. Each entry gives selected-case count, `too_small`, ordinary scored/unscored/failed/self-source coverage, Boolean agreement or Probability Brier/ECE/risk-coverage when available, and signed numeric deltas. A distinct `missing` slice is explicit in the output type.

## Behavior

The calculator SHALL resolve the path against each selected case's typed Inputs without changing the Dataset JSON schema, deserialization or `Dataset::validate` behavior.

When the path is absent or resolves to `Optional(None)`, the calculator SHALL assign that case to the distinct `missing` slice.

When the path resolves to Text or `Optional(Some(Text))`, the calculator SHALL use the exact nonblank text as the slice value, preserving case and whitespace without normalization.

If a present path resolves to another value type or blank text, the calculator SHALL refuse the report with the case ID and path rather than silently coerce it.

The calculator SHALL treat a literal slice value equal to `missing` as a value, distinct from the missing-key variant.

The calculator SHALL mark a slice `too_small` when its selected-case count is less than the declared minimum, while retaining its counts, available metrics and deltas.

The calculator SHALL calculate each slice and the overall result from the same selected case IDs, output schemas, outcomes, self-source exclusions and scoring rules as [FR-036](FR-036.md).

When [FR-065](FR-065.md) and [FR-066](FR-066.md) are available, the calculator SHALL reuse their ECE and risk-coverage definitions on each subset.

While the shared calculators are unavailable, the report SHALL mark those fields `not_computed` rather than implement a second estimator.

For a metric present on both sides, the calculator SHALL report the signed delta as `slice_metric - overall_metric`, separately by output and metric. For each risk-coverage threshold, it SHALL report signed coverage and risk deltas only when both values exist. Absent metrics SHALL have absent deltas with a reason.

When windows are requested, the calculator SHALL require exactly two distinct names and one declared window assignment for every selected case ID, with no unknown or duplicate assignments.

It SHALL compare each window's metrics to the other by `current - reference`.

For each slice present in either window, it SHALL report both window counts and available metrics, and the per-slice `current - reference` deltas. An absent slice in one window SHALL have count zero and absent metrics and deltas with a `missing_window_slice` reason.

It SHALL not infer a timestamp or window from Dataset order, case ID or recording order.

The calculator SHALL order the missing slice first when present, then value slices by exact UTF-8 lexicographic order.

It SHALL order named outputs by name, risk rows by increasing threshold, and windows as reference then current.

The calculator SHALL accumulate case-derived floating metrics in ascending case-ID order and recording confidence sums in ascending numeric-confidence order before serialization, so permutations of input insertion order yield identical numbers.

The calculator SHALL make no model call, filesystem read or clock call.

The CLI host MAY load existing Dataset and outcome artifacts before invoking the pure calculator.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-067-AC-1 | IT-011's slice A has Boolean agreement `1.0` over 2 scored cases and B has `0.5` over 2; overall is `0.75` over 4, and signed agreement deltas are `+0.25` and `-0.25` respectively. | Test |
| FR-067-AC-2 | With minimum count 3, both two-case slices are `too_small` while their counts, metrics and deltas remain visible; with minimum 2 they are not flagged. | Test |
| FR-067-AC-3 | A case with an absent path appears under the explicit missing slice; a literal Text `missing` remains a separate slice. No selected case disappears, and blank or wrong-typed present values refuse with case ID and path. | Test |
| FR-067-AC-4 | Two declared windows produce overall and per-slice/per-output `current - reference` deltas from supplied case-ID membership; a slice absent in one window has count zero and an absent delta; absent, duplicate or unknown membership refuses, and the Dataset needs no timestamp field. | Test |
| FR-067-AC-5 | Reversing case and outcome insertion order yields byte-identical serialized report order; repeated reporting makes zero model, filesystem and clock calls. | Test |
| FR-067-AC-6 | Probability slice ECE and risk rows equal the shared FR-065/066 calculators on the identical scored case IDs when available; otherwise those fields say `not_computed`, and missing/unsupported metrics have absent deltas. | Test |
| FR-067-AC-7 | Existing Dataset JSON round trips and validation decisions are unchanged, and `sapho-evidence` retains only `sapho-core` as a workspace-crate dependency. | Test |

## Dependencies

[FR-036](FR-036.md) owns measurement semantics. [FR-065](FR-065.md) and [FR-066](FR-066.md) are the shared calibration definitions proposed in SAPHO-21; this independent spec branch does not copy their implementation. The CLI owns input and output I/O.
