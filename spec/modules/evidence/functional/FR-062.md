# FR-062: Compute an attributable model roster

## Description

The evidence tools SHALL compute model profiles from selected case outcomes and model-call observations, with explicit attribution and denominator rules.

## Inputs

An existing validated Dataset, selected split, graph identity, Sapho version, decision outcomes, trace lineage, model-call observations and a declared mapping from each profiled graph output to one binding and question type. The mapping names no metric value.

## Outputs

A versioned roster artifact with dataset ID, split, graph identity and Sapho version; sorted entries keyed by binding ID and reported actual model ID (or an explicit unknown-actual-model bucket); optional provider descriptor; call, usage and latency summaries; and per-output, per-label-kind scored coverage and metrics. An unattributed-case list carries case ID, output and reason.

## Behavior

The roster SHALL count one call for each attempted model-call observation.

The roster SHALL keep failed or response-less attempts in an unknown-actual-model bucket rather than assign the requested model as actual.

A binding whose backend returns more than one actual model ID SHALL have separate entries whose call counts sum to its attempted calls.

The roster SHALL total input/output tokens and optional billing units only for responses that report them.

The roster SHALL expose the contributing count for each total and mean; missing usage is absent, not zero.

Latency mean, p50 and p95 SHALL use all elapsed live attempts within an entry, sorted by duration with nearest-rank percentiles.

A replay-only entry SHALL have absent latency fields and duration count zero.

When live and replay observations are mixed, the roster calculator SHALL refuse them rather than present partial latency as complete.

The roster calculator SHALL attribute an output to its declared binding only when the selected case's contributing trace lineage contains exactly one successful model response from that binding and no successful response from another binding.

Otherwise, the roster calculator SHALL report the case as unattributed and exclude it from that binding/output metric denominator.

Each attributed output SHALL be scored with the same selected case IDs, Boolean labels, self-source exclusions and denominators as `measure`, partitioned by declared label kind.

Boolean agreement and Probability Brier SHALL equal a per-kind `measure` over that same attributable case set.

When the shared SAPHO-21 metric is available, the roster SHALL reuse it for ECE.

Until then, the roster SHALL report ECE as absent with a `not_computed` reason.

The existing Dataset JSON shape, deserialization and `Dataset::validate` behavior SHALL remain unchanged.

Provider metadata is a host descriptor; if absent, the roster SHALL leave provider absent and still include the custom binding.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-062-AC-1 | Two successful bindings yield two roster entries; each binding's summed entry call count equals its attempted model nodes in Trace, and failed calls with no response remain in the unknown-actual-model bucket. | Test |
| FR-062-AC-2 | Known Usage reports exact totals, contributing counts and means; a missing Usage response does not add zero to the mean denominator. | Test |
| FR-062-AC-3 | Injected live durations give hand-counted mean, p50 and p95; replay-only yields absent fields, and mixed live/replay observations are refused. | Test |
| FR-062-AC-4 | For two label kinds and two mapped outputs, each binding/output/kind's counts, agreement and Brier equal per-kind `measure` on the identical attributable case IDs; an output with multiple contributing bindings is reported unattributed. | Test |
| FR-062-AC-5 | ECE is `not_computed` before the shared SAPHO-21 metric exists; once present, its value matches that metric on the same case IDs and label kind. | Test |
| FR-062-AC-6 | A custom ModelBackend with no stock adapter and no provider descriptor still appears under its binding and actual reported model; Dataset serde and validation remain backward compatible. | Test |
