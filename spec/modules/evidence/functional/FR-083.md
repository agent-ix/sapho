# FR-083: Fit a deterministic development calibration map and score it

## Description

When curated development predictions and Boolean labels are supplied for one raw Probability output, the pure evidence calculator SHALL fit a reproducible monotone calibration map and score raw and calibrated quantities separately.

## Inputs

The existing validated Dataset, explicitly selected split, raw output name, checked case outcomes, a parallel pure attribution map keyed by case ID with each contributing `(BackendId, ModelIdentity)` extracted by the host from completed trace responses, the raw graph's `graph_semantic_identity`, and caller case/byte ceilings. Fit accepts only `development`. It uses cases in that split with a Boolean label for the selected output and raw Probability result; self-source, failed, missing or type-mismatched selected labels are refusals rather than training rows. Other output labels and held-out cases do not enter the fit. The pure evidence API sees core identity values only; it does not import runtime Trace.

## Outputs

A validated [FR-081](../../core/functional/FR-081.md) CalibrationMap with deterministic knots, dataset ID, development-case content and fit-observation digests, raw graph digest, output, contributing binding, reported actual model, method and scored case count; or a typed refusal. `measure` adds per-output calibrated Brier/ECE beside existing raw Probability Brier/ECE, with separate scored denominators and no heterogeneous averaging.

## Behavior

The fitter SHALL refuse any split other than development before using predictions or labels. It SHALL require at least 20 fully scored eligible development cases, at least two positive and two negative labels, and at least two distinct raw Probability values. It SHALL refuse a selected output with any unscored, failed, type-mismatched or self-source-labelled eligible case rather than silently dropping it. It SHALL cap distinct raw values/knots at 4096 and use the existing caller case/artifact ceilings. Empty or over-limit results have no map.

The fitter SHALL sort observations by raw Probability, then case ID as a deterministic tie-break. It SHALL group equal raw values and retain integer positive/total counts. It SHALL apply weighted pool-adjacent-violators (PAVA): scan groups left to right, repeatedly merge adjacent blocks only when the left positive/total rate is strictly greater than the right rate; compare rates by checked integer cross multiplication, not floating order. Every distinct raw value receives its final block's `positive/total` rate. The knots are the distinct raw values in ascending order with those nondecreasing rates. The apply operation uses the interpolation/extrapolation of [FR-082](../../graph/functional/FR-082.md); no smoothing, random seed, per-slice fit or model training is implied.

The fitter SHALL compute `fit_cases_digest` over canonical JSON of dataset ID, raw output name and all selected development cases with that output label, sorted by case ID, including each case ID, typed Inputs, Boolean label and full label provenance. It SHALL prefix the hash input with UTF-8 `sapho.dataset.development.v1\n` and encode the digest as `dataset-development-v1:sha256:` plus lowercase hex SHA-256. Canonical JSON follows the named-map, array, numeric and string rules of draft FR-063; held-out case content and source path are excluded. A change in a selected label/input/provenance changes this identity. The map's `case_count` equals the number of scored rows used by PAVA.

For each scored fit case, the fitter SHALL require exactly one pure attribution pair on the declared contributing BackendId and require the same nonblank reported actual model name across all cases. The CLI host extracts a pair only from a completed ModelResponse whose ModelRequest carries that BackendId. Zero/multiple trace responses for that binding, multiple contributing Ask nodes, a different reported model name, or a raw output whose graph dependency closure does not contain exactly that one Ask are typed refusals before the pure fitter is invoked; unrelated shadow Asks outside the raw output closure do not count. The fitter SHALL compute `fit_observation_digest` from canonical JSON of the sorted `(case_id, raw Probability, Boolean label, contributing BackendId, reported actual model)` rows, prefixed by UTF-8 `sapho.calibration.observations.v1\n`. This digest binds the actual fitted predictions as well as the Dataset, and changes when a model's predictions change even under an unchanged graph, Dataset and reported name. The map stores that binding and reported model name, not a provider endpoint or credential. A reported name is the only model identity in the current public ModelResponse; the map makes no weights-identity claim.

The measurement calculator SHALL recognize CalibratedProbability as its own metric kind and compute Brier against the same Boolean labels using `(p-y)^2`. It SHALL pass calibrated values through the one shared ECE implementation of draft FR-065, with predicted true at `p>=0.5`, confidence `max(p,1-p)` and the same decile boundaries and self-source/coverage rules. Raw Probability keeps its existing Brier and gains that same shared ECE. `measure`'s public call signature, Dataset JSON/serde/validate, per-output coverage counts and exit policy remain unchanged. A held-out `measure` is permitted and reports both named outputs without fitting on held-out labels. `sapho-evidence` adds no workspace-crate dependency beyond `sapho-core`; it never imports Quoin.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-083-AC-1 | Twenty development rows, ten at raw 0.05 with 2 true labels and ten at raw 0.95 with 8 true labels, fit knots `(0.05,0.2),(0.95,0.8)` and `case_count=20` byte-identically across shuffled outcome iteration; map identity fields are exact. | Test (IT-017) |
| FR-083-AC-2 | A later low-rate group triggers PAVA pooling to nondecreasing block rates; equal raw values group first, interpolation is monotone, and fit bytes do not depend on hash-map iteration or input file formatting. | Test (IT-017) |
| FR-083-AC-3 | Held-out fit, fewer than 20 rows, fewer than two labels of either class, one distinct raw value, unscored/failed/self-source selected label or more than 4096 knots refuses without a map. | Test (IT-017) |
| FR-083-AC-4 | On the 20-row fixture, raw ECE is 0.15 and calibrated ECE is 0 within `1e-9`, an improvement of at least 0.1; raw and calibrated Brier/ECE use separate named outputs and identical scored case IDs/denominators. | Test (IT-017) |
| FR-083-AC-5 | Held-out `measure` scores raw and calibrated named outputs side by side without fitting; both ECE paths use the shared FR-065 decile implementation and its Quoin parity fixture, while Dataset serde/validate and `measure` signature remain stable. | Test (IT-017) |
| FR-083-AC-6 | Fit on the same graph/Dataset under a changed reported model name refuses mixed-model rows or yields a different map ID for a uniform new model; changed raw probabilities under the same reported name change `fit_observation_digest`; ambiguous contributing binding refuses. | Test (IT-017) |
