# FR-059: Compare shadow observations with decision predictions

## Description

The evidence tools SHALL compare each shadow observation with its mapped decision output on the same selected case IDs and curated labels, without duplicating labels in Dataset.

## Inputs

An existing validated Dataset, selected split, ordinary decision outcomes, and a separate keyed collection of shadow observations. A comparison request declares the output, shadow ID, metric, positive minimum scored count and nonnegative minimum improvement margin before scoring.

## Outputs

A side-by-side report per decision output, shadow ID, split and label kind, with selected, scored, unscored and failed counts for both roles, case IDs, metrics, declared margin and `beat_champion` as true, false or not-computed. The report retains the dataset ID and does not claim promotion.

## Behavior

The comparison SHALL reuse each case's existing label under the mapped decision output name.

The evidence tools SHALL retain the Dataset serde and `Dataset::validate` interface and behavior.

It SHALL score Boolean agreement and Probability Brier using the same denominators and self-source exclusions as [FR-036](FR-036.md).

When the shared SAPHO-21 ECE metric is available in ordinary `measure`, the comparison SHALL report that same ECE value for each Probability role on the matched case set and label kind.

When the shared ECE metric is unavailable or a Probability role has zero scored cases, the comparison SHALL report ECE as `not_computed` with a reason, never zero.

Metrics SHALL be separated by label-provenance kind and never average kinds together.

A shadow failure or missing observation SHALL count as unscored or failed for that role without erasing the decision metric.

`beat_champion` SHALL be true only when both selected-metric values are computed on the same scored case-ID set, both meet the declared minimum count, and the improvement is strictly positive and at least the declared margin. Improvement is challenger minus champion for agreement and champion minus challenger for Brier or ECE. A zero-margin tie is false; an exact positive-margin boundary is true.

The comparison SHALL mark development results `development` and `not_promotable`.

The comparison SHALL mark held-out results `held_out`.

Neither result SHALL authorize promotion by itself.

A comparison with a missing selected metric, unequal scored case sets, or an unmet margin SHALL return false or not-computed with the reason.

When the shared SAPHO-21 metric is unavailable, an ECE comparison SHALL return `not_computed`.

An ECE comparison without the shared metric SHALL never report `beat_champion: true`.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-059-AC-1 | One Dataset label per output and case yields side-by-side champion and shadow agreement and Brier on the same case IDs; no duplicate label key is required. | Test |
| FR-059-AC-2 | Reports separate label kinds, each role's denominator and case IDs; before shared SAPHO-21 ECE exists or with zero scored cases, ECE is `not_computed` with a reason, and selecting it cannot report a win. Once shared ECE exists, role values equal ordinary `measure` on the same case sets. | Test |
| FR-059-AC-3 | On a held-out fixture, a zero-margin tie reports false, a strictly positive zero-margin gain reports true, and an exact positive-margin boundary reports true; below-margin gain, missing metrics, unequal scored case sets or insufficient count cannot report true. | Test |
| FR-059-AC-4 | The same comparison on development cases is marked `not_promotable` even if the challenger wins. | Test |
| FR-059-AC-5 | Existing Dataset JSON deserializes and `Dataset::validate` returns the same result without new required fields. | Test |

## Dependencies

[FR-036](FR-036.md) supplies labelled measurement semantics; [FR-058](../../runtime/functional/FR-058.md) supplies shadow observations. ECE comparison becomes computable only after SAPHO-21 supplies the shared metric; this requirement does not create a second ECE implementation or change ordinary `measure` before SAPHO-21 lands.
