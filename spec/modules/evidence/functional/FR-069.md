# FR-069: Pre-register a held-out promotion gate

## Description

When held-out promotion measurement is requested, the Sapho host SHALL bind a declared gate file and its thresholds to the exact Dataset content, held-out split and semantic graph identity in an exclusive registration artifact before evaluating any case.

## Inputs

A bounded UTF-8 JSON gate file, existing validated Dataset, compiled GraphSpec, an exclusive registration destination and existing artifact ceilings. The gate file has a version, dataset `SourceId`, canonical Dataset content digest, literal split `held_out`, `graph_semantic_identity` from [FR-063](../../graph/functional/FR-063.md), and a nonempty named-output map. Each output has six mandatory bars: exclusive minimum margin over the best constant predictor, inclusive maximum ECE, inclusive minimum true-class recall, inclusive minimum false-class recall, inclusive maximum repetition disagreement, and a positive minimum scored count. The two recall floors must be greater than zero. No backend or model name is a gate field.

## Outputs

A registration artifact containing the validated gate snapshot, `gate_bytes_digest`, `gate_semantic_identity`, dataset ID and content digest, split and graph semantic identity, or a structured refusal. The host writes it with create-new semantics before evaluating any case.

## Behavior

The host SHALL reject unknown gate fields, duplicate output names, nonfinite or out-of-range bars, missing bars and an empty output map.

The host SHALL require the gate's named-output set to equal the compiled graph's complete public output-name set before registration or any case evaluation. It SHALL refuse an omitted or extra output rather than issue a whole-graph GO for a subset.

The host SHALL require the exact `held_out` split.

It SHALL refuse a development gate or development measurement as nonpromotable.

The host SHALL compute `gate_bytes_digest` as lowercase SHA-256 of the exact gate file bytes, including whitespace, and `gate_semantic_identity` as `gate-v1:sha256:` plus SHA-256 of UTF-8 `sapho.gate.v1\n` followed by canonical JSON of the validated typed gate. Canonical JSON recursively sorts named maps by Unicode code point, preserves array order, renders finite numbers in shortest round-trippable decimal form (`1`, `1.0` and `1e0` identically, negative zero as zero), uses stable JSON escaping and has no insignificant whitespace.

The host SHALL compute the Dataset content digest as `dataset-v1:sha256:` plus SHA-256 of UTF-8 `sapho.dataset.v1\n` followed by canonical JSON of the validated Dataset, including case IDs, splits, inputs, labels and provenance. That serialization applies the same map, numeric and string rules as the gate identity and preserves the Dataset's case and source-array order.

It SHALL retain the existing Dataset JSON shape, serde and `Dataset::validate` behavior.

The host SHALL compare the gate's dataset ID/content digest and graph semantic identity to the supplied Dataset and graph before writing registration or running a case.

The host SHALL write the complete validated gate snapshot and both gate identities to a new registration path before any held-out evaluation begins.

An existing path or write failure SHALL refuse without measuring a case.

The host SHALL refuse a later evaluation if the gate file's current raw digest differs from the registration's `gate_bytes_digest`, or if the registration's bound dataset, split or graph identity differs from the measurement. It SHALL never relabel an earlier result with an edited gate digest.

The registration artifact SHALL not claim an externally trusted creation time; the command's write-before-evaluation order and immutable snapshot define its pre-registration boundary.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-069-AC-1 | A valid gate is registered by exclusive write before the first synthetic case evaluation; receipt contains the full bar snapshot, both gate identities, Dataset ID/content digest, `held_out` and graph semantic identity. | Test |
| FR-069-AC-2 | Editing only gate whitespace changes `gate_bytes_digest` but preserves `gate_semantic_identity`; editing one bar changes both. Evaluating an earlier receipt against either edited file refuses before measurement. | Test |
| FR-069-AC-3 | Dataset label/input changes under the same SourceId, a different selected split, or a different graph literal each cause identity mismatch and no case evaluation. Existing `GraphArtifact.source` remains unchanged. | Test |
| FR-069-AC-4 | Development split, malformed/unknown gate fields, absent or invalid bars, existing receipt destination and write failure refuse before evaluation and leave prior artifacts intact. | Test |
| FR-069-AC-5 | Gate schema and registration contain no model/backend name, and Dataset JSON round-trip and validation decisions are unchanged. | Test |
| FR-069-AC-6 | A two-output graph with only one output named in the gate, or an extra gate output absent from the graph, refuses registration before any case evaluation; both graph outputs must have bars. | Test |

## Dependencies

[FR-036](FR-036.md) owns Dataset validation and label semantics. [FR-063](../../graph/functional/FR-063.md) defines the versioned semantic graph identity in SAPHO-25; an implementation may not substitute the path/raw-byte `GraphArtifact.source` value. Registration is a host I/O action; pure evidence calculations keep only `sapho-core` as a workspace-crate dependency.
