# FR-070: Evaluate every pre-registered promotion bar

## Description

When a held-out measurement and its repeated case outcomes are bound to a registered gate, the pure evidence calculator SHALL evaluate every declared output bar and return GO only if every bar passes with complete evidence.

## Inputs

The validated gate snapshot and identities, held-out Dataset and primary measurement, the graph semantic identity, and at least two additional independent repetitions' case outcomes for every graph output. The primary measurement is the first run in the disagreement population. All additional runs use the same selected case IDs, labels, graph identity and output schema. The gate contains thresholds but no model names or values learned from the held-out results.

## Outputs

A deterministic report with gate byte digest and semantic identity; measurement Dataset ID/content digest, split and graph semantic identity; per-output selected, labelled and scored counts; best constant predictor value; and every bar's observed value, threshold, comparator and `pass`, `fail` or `not_computed` status with reason. Overall verdict is GO or NO-GO.

## Behavior

The calculator SHALL require the gate output names to equal the measured graph output names before computing a whole-graph verdict.

For every graph output, the calculator SHALL require a declared Boolean label for every selected held-out case and a scored prediction for every such case in the primary and additional runs. A missing/unscored/failed or self-source-excluded case SHALL make the report NO-GO with incomplete evidence.

For each gated output, the calculator SHALL derive a Boolean prediction directly from a Boolean value, or from Probability `p` using `p >= 0.5`. Degree, Number and other types SHALL not be coerced into a prediction.

The calculator SHALL compute agreement as correct predictions divided by the gated output's scored count and the constant-label baseline as `max(true_label_count,false_label_count)/scored_count` over those identical scored case IDs. The margin is measured agreement minus that baseline.

The margin bar SHALL pass only when its value is strictly greater than the registered nonnegative minimum margin, so a tie fails even at a zero threshold.

The calculator SHALL compute true-class recall as correct true predictions divided by true-labelled cases, and false-class recall as correct false predictions divided by false-labelled cases. If a class has no labels, its recall is absent and its bar is `not_computed`.

For a Probability output, the calculator SHALL reuse [FR-065](FR-065.md)'s ECE on those same scored case IDs.

For a Boolean output or an unavailable shared metric, it SHALL mark ECE `not_computed`.

It SHALL not introduce another estimator or infer confidence from a Boolean.

For each graph output, the calculator SHALL define repetition disagreement as the fraction of selected case IDs whose Boolean predictions are not identical across the primary run and all additional independent runs. If fewer than two complete additional runs are present, the bar SHALL be `not_computed`. The primary prediction SHALL participate even when the additional runs agree with each other.

The calculator SHALL compare ECE and repetition disagreement with inclusive ceilings, recalls with inclusive positive floors, and scored count with an inclusive positive minimum.

The calculator SHALL mark an absent observed value `not_computed` with a reason.

It SHALL not substitute zero or mark it passed.

The calculator SHALL make overall GO only when all six mandatory bars for every named output pass.

Any fail or not-computed bar SHALL produce NO-GO.

The report SHALL retain every bar rather than stop at the first failure.

The calculator SHALL reject a measurement whose dataset ID/content digest, selected split or graph semantic identity differs from the registration.

It SHALL never evaluate a development split as promotable.

The calculator SHALL make no backend call, filesystem write or deployment action; host orchestration owns those boundaries.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-070-AC-1 | A synthetic Probability output tied with its best constant predictor has margin zero and fails a zero exclusive margin bar; all six bar rows and denominators appear, and verdict is NO-GO. | Test |
| FR-070-AC-2 | An always-false output with at least one true label has true recall zero and fails a positive true-recall floor, even if aggregate agreement is high. | Test |
| FR-070-AC-3 | Absent ECE, missing class, fewer than two complete repetitions or no scored cases yield `not_computed` bars and NO-GO, never an invented zero or GO. | Test |
| FR-070-AC-4 | The primary run and two additional repetitions with one changed Boolean prediction among four selected cases yield disagreement `0.25`; an inclusive ceiling `0.25` passes and a lower ceiling fails. | Test |
| FR-070-AC-5 | A complete synthetic Probability fixture satisfying every bar produces GO; changing one bar or one case outcome makes the affected row fail without hiding other rows. | Test |
| FR-070-AC-6 | A mismatched Dataset ID/content, split or graph semantic identity refuses evaluation; the report binds gate and measurement identities and no model name is required. | Test |
| FR-070-AC-7 | On four cases, the primary differs on one prediction from two identical additional runs: disagreement is `0.25`, so a zero ceiling fails and cannot yield GO. A two-output graph whose second output fails a bar reports both outputs and whole-graph NO-GO. | Test |
