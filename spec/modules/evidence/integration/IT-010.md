# IT-010: Verify probability calibration and risk coverage

## Objective

Verify that the public evidence measurement contract produces the hand-computed ECE and risk-coverage table for the same labelled cases, with independent Quoin definition parity and no Dataset interchange change.

## Target Integration

The pure `sapho-evidence` public API, `sapho-core` typed Probability values, existing `measure` host path and a test-only Quoin reference calculation. Sapho production code does not import Quoin, a runtime, a CLI or a private EARS dataset.

## Preconditions

A validated synthetic Dataset has ten development cases, each with one `support` Boolean label and an independent declared source. Each completed outcome has a typed `support` Probability and no responding model equal to the label source. A separate held-out case is available to check split isolation.

## Inputs

The ordered `(p,label)` rows are `(0.05,false)`, `(0.15,false)`, `(0.25,true)`, `(0.35,false)`, `(0.45,true)`, `(0.55,true)`, `(0.65,true)`, `(0.75,false)`, `(0.9,true)`, `(1.0,false)`. Predicted `true` uses `p>=0.5`; confidence uses `max(p,1-p)`. Their `(confidence,correct)` pairs are `(0.95,true)`, `(0.85,true)`, `(0.75,false)`, `(0.65,true)`, `(0.55,false)`, `(0.55,true)`, `(0.65,true)`, `(0.75,false)`, `(0.9,true)`, `(1.0,false)`.

## Test Procedure

1. Measure the ten development cases through the public evidence API and independently pass the listed confidence/correctness pairs to Quoin's `expected_calibration_error` test reference.
   - IT-010-SC-01: both ECE values equal `0.33` within `1e-9`; bucket 9 has count 3, correct 2 and mean confidence `0.95`. Bucket 8 has count 1, correct 1 and mean confidence `0.85`.
2. Inspect the default threshold table.
   - IT-010-SC-02: thresholds `[0.5,0.6,0.7,0.8,0.9,0.95]` have `(answered,correct,total)` rows `[(10,6,10),(8,5,10),(6,3,10),(4,3,10),(3,2,10),(2,1,10)]`; coverage, accuracy and risk equal the stated fractions.
3. Run valid and invalid threshold overrides, including a threshold above every scored confidence in a separate fixture.
   - IT-010-SC-03: inclusive boundaries and absent accuracy/risk for zero answered are visible; invalid threshold lists refuse before scoring.
4. Measure zero-score Probability, Degree and Number outputs, self-source labels and a held-out case while selecting development.
   - IT-010-SC-04: ECE is absent and the risk table empty for zero-score Probability; unsupported types get neither metric; exclusions and split isolation retain existing counts.
5. Round-trip the existing Dataset JSON and inspect crate dependencies and the unchanged original `measure` signature.
   - IT-010-SC-05: serde and validation results match the prior contract, and `sapho-evidence` has only `sapho-core` as a workspace-crate dependency.

## Expected Results

All success criteria pass. Reported ECE and risk-coverage values are based on identical scored Probability observations; no empty result is presented as zero error or zero risk.
