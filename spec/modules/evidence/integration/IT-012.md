# IT-012: Verify a bound held-out gate and process verdict

## Objective

Verify that a registered gate judges only its bound held-out Dataset and graph, reports every bar, and returns distinct complete NO-GO and incomplete-evidence exit codes.

## Target Integration

The public `sapho-evidence` gate calculator, `sapho-cli` registration and gate commands, typed graph and Dataset identities, and scripted public ModelBackend/replay doubles. All fixtures are synthetic and require no network, EARS private data or deployment.

## Preconditions

The gate JSON declares `held_out`, exact Dataset ID/content digest and graph semantic identity. An exclusive registration destination and report destination are available. All case labels have non-model provenance in the basic fixtures; selected output is typed Probability. The host records whether any case evaluation begins before receipt creation.

## Inputs

A four-case tie fixture has labels `[false,false,false,true]` and predictions `[false,false,false,false]`, so agreement and best constant agreement are both `3/4`, margin zero and true recall zero. An eight-case GO fixture has four true and four false labels; probabilities are four `0.8` for true cases, three `0.2` for false cases, and one `0.6` for a false case. It has agreement `7/8`, constant baseline `1/2`, margin `3/8`, true recall `1`, false recall `3/4`, and ECE `1/4`. Two identical complete repetitions have disagreement zero. Register bars margin `>0.2`, ECE `<=0.3`, both recalls `>=0.5`, disagreement `<=0.1` and scored count `>=8` for the GO fixture.

## Test Procedure

1. Register a gate before evaluating any held-out case; inspect the artifact and mutate only whitespace, then one bar, in separate gate copies.
   - IT-012-SC-01: the receipt precedes the first evaluation, binds byte and semantic gate digests plus Dataset ID/content, held-out split and graph semantic identity; whitespace changes only the byte digest and either edit makes the earlier receipt unusable.
2. Evaluate the four-case tie fixture against a zero exclusive margin threshold and positive true-recall floor.
   - IT-012-SC-02: margin `0` and true recall `0` fail, every other bar remains reported, verdict is NO-GO and complete evidence exits 1.
3. Evaluate the eight-case GO fixture, then change one threshold or outcome.
   - IT-012-SC-03: six bars pass with the stated arithmetic and exit 0; the changed bar fails without hiding the other five, producing NO-GO exit 1.
4. Remove Probability confidence, one class, or enough repetitions; also supply two complete repetitions differing on one of four selected cases.
   - IT-012-SC-04: unavailable bars are `not_computed` and NO-GO; the four-case disagreement is `1/4`, passing a `0.25` inclusive ceiling and failing a lower ceiling.
5. Fail or omit one selected label in a repetition while another bar fails, then request development and mismatched gate/Dataset/graph identities.
   - IT-012-SC-05: incomplete evidence exits 2 with partial bar evidence; invalid split or identities refuse before evaluation with exit 2, and ordinary `measure` still exits 2 for unscored selected labels.
6. Repeat with a custom backend and exact replay, and inspect the gate schema, report and Dataset interchange.
   - IT-012-SC-06: no gate field requires a model name, no deployment occurs, Dataset serde/validate remains unchanged, and the public evidence crate retains only `sapho-core` as a workspace-crate dependency.

## Expected Results

All steps pass. Each report identifies the exact registered gate and measurement population, complete failures are nonzero, absent values cannot pass, and synthetic results make no claim about real EARS held-out promotion.
