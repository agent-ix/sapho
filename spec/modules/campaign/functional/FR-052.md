# FR-052: Operate campaigns through CLI and dashboard

## Description

The CLI SHALL expose campaign operations through ix-cli-kit with a separate attached Ratatui dashboard.

## Behavior

Explicit versioned policy and bounded artifacts. Default serial execution, no automatic retries, no shell stages. Storage work is synchronous outside Tokio worker tasks; no lock spans await. Unknown fields and unsupported versions refuse. Existing provider confidence semantics are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|---|---|---|
| FR-052-AC-1 | init/import/run/status/tui/pause/resume/retry/export/migrate/doctor use shared application services and typed output. | Test |
| FR-052-AC-2 | Controls apply once at safe stage boundaries; pause guards a control revision and retry guards the target attempt, independent of unrelated progress events. | Test |
| FR-052-AC-3 | Dashboard supports resize, scrolling, inspection and guarded controls; detach restores the terminal and does not stop headless work. | Test |
| FR-052-AC-4 | Standalone graph campaigns work with explicit Ollama, supported configured backends or exact replay, without coding agents or automatic downloads. | Test |

## Domain inspection extension

A domain host may supply bounded, read-only text panels for the currently selected
attempt. The callback runs before rendering, outside any async execution or writer
transaction. The TUI owns navigation, wrapping and scrolling; domain sources and
interpretations remain downstream. Left/right select panels and up/down select
attempts. Attempt metadata remains an always-available first panel. At most16
panels,4MiB per body and256bytes per title are accepted; oversized input is refused
explicitly. Closing inspection cannot stop headless inference.

| ID | Criteria | Verification |
|---|---|---|
| FR-052-AC-5 | Host panels render at narrow terminal sizes with scrolling and selection; unknown domains require no upstream dependency. Oversized panel collections are refused before rendering. | Test |

## Structured dashboard integration

A read-only `dashboard` command SHALL expose the versioned bounded projection
defined in [Dashboard API](../../../../../docs/campaign-dashboard-api.md).
Machine integrations consume structured metric units/meaning/authority,
snapshot sequence and selected-attempt identity/hash fields; they SHALL NOT
depend on rendering text or direct database access. Domain data remains
downstream. Projection SHALL perform no dispatch, controls or writer mutation.

| ID | Criteria | Verification |
|---|---|---|
| FR-052-AC-6 | Versioned bounded dashboard JSON preserves one durable snapshot and exact selected attempt, rejects unknown/oversized selections, and excludes private payloads and retry reasons from its default feed. | Test |

## Dependencies

Core typed data, native graph/runtime and recording contracts. Campaign storage and TUI are optional host dependencies; domain consumers depend downstream.
