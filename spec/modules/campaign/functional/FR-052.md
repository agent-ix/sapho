# FR-052: Operate campaigns through CLI and dashboard

## Description

The CLI SHALL expose campaign operations through ix-cli-kit with a separate attached Ratatui dashboard.

## Behavior

Explicit versioned policy and bounded artifacts. Default serial execution, no automatic retries, no shell stages. Storage work is synchronous outside Tokio worker tasks; no lock spans await. Unknown fields and unsupported versions refuse. Existing provider confidence semantics are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|---|---|---|
| FR-052-AC-1 | init/import/run/status/tui/pause/resume/retry/export/doctor use shared application services and typed output. | Test |
| FR-052-AC-2 | Controls apply once at safe stage boundaries; pause guards a control revision and retry guards the target attempt, independent of unrelated progress events. | Test |
| FR-052-AC-3 | Dashboard supports resize, scrolling, inspection and guarded controls; detach restores the terminal and does not stop headless work. | Test |
| FR-052-AC-4 | Standalone graph campaigns work with explicit Ollama, supported configured backends or exact replay, without coding agents or automatic downloads. | Test |

## Dependencies

Core typed data, native graph/runtime and recording contracts. Campaign storage and TUI are optional host dependencies; domain consumers depend downstream.
