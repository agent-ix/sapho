# FR-050: Execute recoverable bounded stage attempts

## Description

The campaign runner SHALL persist each stage request before dispatch and retain its distinct outcome.

## Behavior

Explicit versioned policy and bounded artifacts. Default serial execution, no automatic retries, no shell stages. Storage work is synchronous outside Tokio worker tasks; no lock spans await. Unknown fields and unsupported versions refuse. Existing provider confidence semantics are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|---|---|---|
| FR-050-AC-1 | Graph/input/policy/backend identities and positive bounds are validated before committing dispatch intent. | Test |
| FR-050-AC-2 | Crash after dispatch retains an indeterminate attempt without redispatch; explicit retry names a parent and nonempty reason for primary and auxiliary stages. | Test |
| FR-050-AC-3 | Completed results pending domain sealing resume sealing without inference; failed serialization retains captured evidence and a bounded failure receipt. | Test |
| FR-050-AC-4 | Execution completion, domain acceptance and campaign completion are separate; failures remain in counts and exports. | Test |
| FR-050-AC-5 | Every wrapped backend invocation retains bounded typed request/response references, monotonic timing, supplied usage and distinct return/failure/cancellation; invocation does not imply transport dispatch or correctness. | Test |

## Dependencies

Core typed data, native graph/runtime and recording contracts. Campaign storage and TUI are optional host dependencies; domain consumers depend downstream.

## Adapter Transition Contract

Compiled adapters project dispatch and execution outcomes in the same transactions
as generic attempt transitions. A refused projection rolls back both effects.
The synchronous execution host receives the genuine persisted attempt ID for
source-free monitoring and returns independently captured artifacts. Successful
semantic sealing remains a separate atomic domain/completion transaction.
