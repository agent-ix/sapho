# FR-051: Embed domain adapters without domain dependencies

## Description

The campaign library SHALL expose a compiled adapter interface for admission, stage preparation, execution, validation and sealing.

## Behavior

Explicit versioned policy and bounded artifacts. Default serial execution, no automatic retries, no shell stages. Storage work is synchronous outside Tokio worker tasks; no lock spans await. Unknown fields and unsupported versions refuse. Existing provider confidence semantics are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|---|---|---|
| FR-051-AC-1 | The stock adapter executes native YAML/JSON graphs over typed Sapho Inputs without Quire or EARS dependencies. | Test |
| FR-051-AC-2 | An adapter receives bounded execution context and emits versioned artifacts and typed domain metrics; core never interprets EARS labels or quotas. | Test |
| FR-051-AC-3 | EARS consumers retain native Quire evaluators, source restrictions and isolated source-first projections; backend recording and persistence are shared. | Test |
| FR-051-AC-4 | Existing synthetic native EARS evaluation replays identically after adaptation. | Test |

## Dependencies

Core typed data, native graph/runtime and recording contracts. Campaign storage and TUI are optional host dependencies; domain consumers depend downstream.
