# FR-049: Persist fenced campaign evidence

## Description

The campaign store SHALL persist immutable evidence and append-only events under one held writer lock.

## Behavior

Explicit versioned policy and bounded artifacts. Default serial execution, no automatic retries, no shell stages. Storage work is synchronous outside Tokio worker tasks; no lock spans await. Unknown fields and unsupported versions refuse. Existing provider confidence semantics are unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|---|---|---|
| FR-049-AC-1 | Concurrent writer opens refuse while snapshot readers remain available. | Test |
| FR-049-AC-2 | Blob hashes are validated with bounded regular-file reads; corrupt, symlink or oversized evidence refuses before use. | Test |
| FR-049-AC-3 | Blob bytes are synced before a transaction references them; domain sealing and its completion event commit atomically. | Test |
| FR-049-AC-4 | Explicit migration writes a new verified state directory, preserves existing evidence and attempt lineage, and leaves the source intact. | Test |

## Dependencies

Core typed data, native graph/runtime and recording contracts. Campaign storage and TUI are optional host dependencies; domain consumers depend downstream.
