# IT-013: Capture multiple configured System One services and replay offline

## Objective

Verify that a stock CLI graph can call two independent System One contract services and add a third through configuration, while host-only endpoint/secret references stay outside graph and recording artifacts and exact replay remains offline.

## Target Integration

The stock CLI binding loader, host service configuration loader, existing bounded CLM/System One transport, `sapho-systemone` codec, core BackendRegistry, recording decorator and ReplayBackend. Ephemeral loopback HTTP servers replace real models; a fake OS secret store records lookups without exposing values.

## Preconditions

Build the existing `clm` feature. Three fake listeners serve `/v1/systemone` on distinct loopback ports and return typed responses with distinguishable actual model IDs. A synthetic graph has ask nodes for `fast_a` and `fast_b`; a later graph edit adds `fast_c`. The binding file declares `provider: systemone`, explicit model and DistributionPolicy for each required BackendId. A separate host service file maps each ID to base URL and optional OS-store credential key.

## Inputs

Two-port and three-port loopback configurations, a credential sentinel known only to the fake secret store, an unused service entry with a sentinel key, an invalid remote HTTP URL, malformed host/binding/graph provider fields, bounded limit overrides, and a recorded two-binding exchange set.

## Test Procedure

1. Execute the two-ask graph live and inspect each fake server's request capture.
   - IT-013-SC-01: `fast_a` reaches only port A and `fast_b` only port B using `/v1/systemone`; each returns its distinct validated answer and its per-service model request identity.
2. Record the run, remove the service file and secret-store access, then replay.
   - IT-013-SC-02: the recording has both BackendIds and no endpoint, credential key or sentinel; replay yields identical outputs and a changed BackendId/request gives ReplayMiss without transport or secret lookup.
3. Add `fast_c` through graph, bindings and host service file edits only; rerun live with a third fake listener.
   - IT-013-SC-03: port C captures only `fast_c` using the same adapter implementation, with no new service-specific code or adapter crate.
4. Supply credential/endpoint fields in binding and graph provider positions, and a plaintext secret field in host config; test invalid URL and limits.
   - IT-013-SC-04: forbidden fields and remote HTTP/userinfo/query/fragment or zero limits refuse before transport; loopback HTTP and remote HTTPS pass URL validation; argv and artifacts contain no secret or service URL.
5. Exercise two services under different scripted delay, size and concurrency limits, with an unused service configuration entry.
   - IT-013-SC-05: each adapter enforces its own deadline, request/response ceilings and in-flight maximum; unused entry causes no secret lookup or transport construction.
6. Run existing Jev and CLM fixtures, and inspect Dataset and custom-host contracts.
   - IT-013-SC-06: legacy endpoint/credential/default-model/feature and replay behavior is unchanged, a custom ModelBackend still binds, and Dataset serde/validate remains stable with no EARS source copied.

## Expected Results

Every step passes with synthetic services only. Host configuration remains separate from declarative graph and credential-free bindings; replay uses recorded identity without a live endpoint; no model-quality or deployment result is asserted.
