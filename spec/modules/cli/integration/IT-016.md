# IT-016: Generate a bounded full grid and tune its explicit candidates

## Objective

Prove deterministic, bounded candidate generation from typed literal IDs, no-overwrite publication, unchanged explicit-candidate tuning and exact replay on unchanged model requests.

## Target Integration

The stock `sapho sweep`, `validate`, `tune` and `replay` CLI paths; GraphSpec parse/compile; filesystem publication; existing Dataset serde/validate and Recording/ReplayBackend interfaces. All fixtures are synthetic and offline.

## Preconditions

A base graph has a downstream Probability cutoff literal with Datum ID `cutoff`, a downstream `List(Number)` weights literal with ID `weights` and stable weight item IDs/sources, one Ask whose question/state do not depend on those literals, and a labelled development/held-out Dataset with one exact Recording. Equivalent handwritten candidate graphs are fixed fixture files. A separate request-affecting literal fixture changes Ask state for the replay-refusal case.

## Inputs

Cutoff grid `[0.6,0.7,0.8]`; the 3×2 grid pairing it with weight vectors `[[0.25,0.75],[0.5,0.5]]`; invalid later-coordinate Probability 1.2, malformed/length-mismatched weights, missing/ambiguous/duplicate IDs, unsupported literal type, 4×4 and 5×4 count grids, existing destination paths and injected write failures.

## Test Procedure

1. IT-016-SC-01: Run `sapho sweep` over only `cutoff`. Assert exactly three candidate files plus manifest, indices 0000–0002 and cutoff values 0.6/0.7/0.8. Compile every candidate with stock `sapho validate`; compare typed GraphSpec trees with the base and assert only that literal Value differs. Compare base/grid file bytes before and after.
2. IT-016-SC-02: Run the 3×2 grid twice into distinct new directories. Assert six candidates ordered `(0.6,w0),(0.6,w1),(0.7,w0),(0.7,w1),(0.8,w0),(0.8,w1)`, identical candidate and manifest bytes across runs, matching manifest coordinate/digest/filename entries, and unchanged outer/inner literal IDs, weight item order and SourceRefs.
3. IT-016-SC-03: Put an invalid value only in the final grid coordinate, then separately try unknown/ambiguous/duplicate literal IDs, wrong type/list length, zero/too many axes or values, and a product exceeding the selected ceiling. Assert refusal before the destination exists and no base/grid mutation. Test default 16 accepts 4×4 and rejects 5×4; explicit 20 accepts 5×4; explicit ceiling 257 refuses. A request to edit Questions or an unsupported literal type refuses.
4. IT-016-SC-04: Point `--output-dir` at an existing empty directory and then at a directory containing a sentinel candidate filename. Assert both refuse without changing any existing bytes. Inject a write error after one candidate is created; assert no manifest, no overwrite and cleanup limited to sweep-created files.
5. IT-016-SC-05: Run unchanged `sapho tune` with generated candidates in manifest order and with equivalent handwritten graphs in the same semantic order. Assert equal development metrics, rank positions and input-order tie-break, allowing path-derived candidate IDs to differ. Assert held-out cases cause zero backend calls; over-16 sweeps require explicit `--max-candidates` in both commands.
6. IT-016-SC-06: Replay all downstream-only candidates against the one Recording. Assert no ReplayMiss and byte-identical model request identities despite differing downstream outputs. Change a literal feeding Ask state in a separate fixture and assert exact ReplayMiss, with no approximate match or rerecording.

## Expected Results

Every step asserts concrete files, typed graph differences, digests, order, errors, call counts or replay keys. The generator runs no graph, and tune remains development-only. Dataset JSON/serde/validate and EARS export contracts remain stable.
