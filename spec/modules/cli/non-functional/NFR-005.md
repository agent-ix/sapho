# NFR-005: Bounded explicit CLI and acquisition work

## Statement

The Sapho command host SHALL enforce finite acquisition, parsing, execution and artifact ceilings without silently truncating successful inputs or evidence.

## Scope

Graph input remains capped at 1 MiB before parsing; a YAML/JSON document has at most 128 structural levels and one YAML document. YAML duplicates/merge keys/aliases/custom tags are refused, true/false are the only implicit Boolean forms, and include/property/robotics extensions are disabled. Parser exhaustion is LimitExceeded; malformed or unsupported syntax is Config. Compilation retains the existing 4096-node, 32 typed-level and 16 subgraph-depth limits. JSON decoding rejects duplicate object keys before they can be collapsed.

The CLI defaults to 1 MiB per input/file, 4 MiB cumulative acquisition, 1024 selected files/cases, 10000 visited entries, 16 tuning candidates and 30 seconds acquisition. Caller flags may reduce these positive ceilings; a larger requested ceiling is an explicit documented invocation, not a hidden retry. Datasets of about fifteen thousand cases are evaluated with documented raised ceilings, never with raised defaults ([FR-056](../functional/FR-056.md)). Run defaults are 4096 node instances, 16384 collection items, 128 model requests, concurrency 4, 8 MiB cumulative accounted data and 60 seconds. Input/recording/report artifacts have finite declared byte ceilings; the default artifact ceiling is 8 MiB. Selected data are never cropped to fit. Git stderr is bounded separately and is not interpreted as a successful empty selection.

Named CLI inputs SHALL be regular files; Unix stdin SHALL use bounded readiness polling without altering shared descriptor flags. A named FIFO/device SHALL be refused rather than waiting for an unbounded open. JSON selection SHALL honor both its per-file and cumulative byte ceilings and its acquisition deadline.

All CLI file/process acquisition and persistence runs outside Tokio workers. Git 2.34+ is checked explicitly; owned child processes are killed and reaped on deadline/output refusal. No implicit live model retry, model training, script evaluation, hook installation, publication, overwrite or fallback occurs. Credentials remain in host SDK/environment state and never in binding/graph/evidence fields. Private application content may be present in explicit state/evidence, so users choose local destinations. Provider/selector failures are reported with typed categories, not message parsing.

## Verification

Exercise ceilings and exclusive-write behavior through public APIs and CLI subprocesses. Observe counters/process completion rather than clock-based speed assertions. At final handoff run both existing default/all-feature lanes, strict lint, API docs, supply-chain checks, spec validation and scoped Rust/code/gap review.
