# FR-084: Write a development calibration literal from measured predictions

## Description

When a caller requests an explicit calibration fit, the Sapho CLI SHALL run only development cases of the raw graph and write a versioned typed map literal for later graph use.

## Inputs

`sapho fit-calibration <raw-graph> --dataset <dataset.json> --output-name <raw-output> --binding <BackendId> --split development --output <new-map.json>` with the existing explicit replay or live backend binding options, RunLimits and dataset/artifact byte ceilings. `--split held_out` is a typed refusal. The raw graph exposes the named output as Probability and contains no calibration map being fitted in this invocation.

## Outputs

A new JSON file containing one complete `Binding::Literal` with `value_type: {kind: calibration_map}` and a Datum whose `value` is the validated versioned map, or a structured refusal. The literal is embedded explicitly in a later graph; the CLI does not rewrite the raw graph or its questions.

## Behavior

The host SHALL load and validate the existing Dataset and raw graph, obtain the raw graph's versioned semantic identity from draft FR-063, select only development cases, and execute only those cases with the existing exact replay or live backend path. It SHALL verify that the selected raw output's dependency closure contains exactly one Ask node with the declared BackendId, and that each scored case's trace contains exactly one completed response for that binding. It SHALL pass checked outcomes and a pure per-case `(BackendId, ModelIdentity)` attribution map to the fitter of [FR-083](../../evidence/functional/FR-083.md); `sapho-evidence` does not import runtime Trace. Dataset validation inspects the complete input artifact for schema integrity; fit and model execution use no held-out case, label or prediction. The host SHALL refuse an unavailable or non-Probability output, an empty development selection, a fit error and an existing destination before writing. It SHALL write the completed literal exclusively under the existing artifact ceiling, without overwriting graph, Dataset, recording or map files; repeated invocations with byte-identical inputs and outcomes produce byte-identical map files. No endpoint, credential, case input, label or raw recording body enters the map.

The host SHALL keep `measure` split selection explicit: a later graph exposing both raw and CalibratedProbability outputs can be measured on development or held_out, while fitting stays development-only. The map's `fit_graph_semantic_identity` refers to the raw fitting graph, and the later graph's own semantic identity includes the embedded literal. The ordinary `GraphArtifact.source` path/raw-byte identity and ordinary measure source fields stay unchanged. CLI fitting adds no loop controller, threshold sweep, model training or per-slice map behavior.

For every executed `calibrate` node in stock CLI `run`, `replay` or `measure`, the host SHALL enforce a run-scoped identity check at the runtime node boundary, after the node's inputs and contributing Ask response are resolved but before the calibrated result is published to any dependent node. This applies even when the calibrated value is converted with `calibrated_as_probability`, consumed by a guard or router, or absent from public graph outputs. Skipped `calibrate` nodes have no map use to check. The check examines the node's raw-probability dependency closure and completed trace in the same execution scope, including Map items, against the resolved map's `fit_binding` and `fit_actual_model`. Exactly one contributing response with the same binding and reported actual model is a `reported_name_match`, shown with map ID, node ID, case/item ID where applicable, binding and reported model in an additive `calibration_identity` report field even when no CalibratedProbability output is exposed. This status explicitly says weights identity is unavailable in the current ModelResponse contract. A different reported name or binding, zero/multiple contributing responses or ambiguous dependency closure SHALL produce typed `ModelMismatch` with map ID, expected/observed binding/model and affected node/case/item, before any dependent guard, router or Ask can execute; the raw response evidence remains in the partial failure trace. Independent graph work already dispatched appears in that trace if present. No graph operation uses a hard-coded model name or consults provider configuration. The numeric `calibrate` operation remains pure; the stock CLI configures the separate runtime boundary check, while a direct Rust Engine consumer can compute a calibrated number but its type alone does not certify fit provenance.

For development `measure` on the same fit case content, the host SHALL also recompute `fit_observation_digest` from raw output values and trace attribution. A digest mismatch SHALL produce `ModelMismatch` even when the reported model name is unchanged. This cohort-level digest comparison occurs after those cases execute; any downstream calls dispatched during cohort execution remain in the partial trace on refusal, and no successful calibrated measurement is presented. For held-out or different development case content, the fit observation digest is not comparable; the report SHALL retain the explicit `reported_name_match` status without claiming weights equivalence. The host performs these checks outside the unchanged pure `measure` function, keeping its public signature and Dataset interchange stable.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-084-AC-1 | Two fits on the same synthetic development graph/Dataset/recording into distinct new paths write byte-identical map literals with exact dataset ID/content digest, split, raw graph digest, output, method and case count. | Test (IT-017) |
| FR-084-AC-2 | `--split held_out`, a non-Probability output, missing development cases, fit refusal and existing destination refuse before a map file is written; zero held-out cases are evaluated during fitting. | Test (IT-017) |
| FR-084-AC-3 | Embedding the literal in a calibrated graph changes semantic graph identity, passes `sapho validate`/`inspect`, and replays the original Ask recording when model requests are unchanged. | Test (IT-017) |
| FR-084-AC-4 | Development and held-out `measure` reports expose raw and calibrated Brier/ECE side by side without altering Dataset interchange, original source fields or replay behavior. | Test (IT-017) |
| FR-084-AC-5 | Same graph and Dataset with a different actual reported model under the same binding yields ModelMismatch in stock run/replay/measure before calibrated success; a name match reports `reported_name_match` without weights claim, and changed development raw predictions under the same name fail the fit-observation digest check. | Test (IT-017) |
| FR-084-AC-6 | A calibrated value converted to Probability and used only by a guard/router, with no calibrated public output, still checks the executing map; a changed reported model causes ModelMismatch before the dependent guarded Ask dispatches, with raw response evidence in the partial trace. | Test (IT-017) |
