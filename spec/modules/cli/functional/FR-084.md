# FR-084: Write a development calibration literal from measured predictions

## Description

When a caller requests an explicit calibration fit, the Sapho CLI SHALL run only development cases of the raw graph and write a versioned typed map literal for later graph use.

## Inputs

`sapho fit-calibration <raw-graph> --dataset <dataset.json> --output-name <raw-output> --split development --output <new-map.json>` with the existing explicit replay or live backend binding options, RunLimits and dataset/artifact byte ceilings. `--split held_out` is a typed refusal. The raw graph exposes the named output as Probability and contains no calibration map being fitted in this invocation.

## Outputs

A new JSON file containing one complete `Binding::Literal` with `value_type: {kind: calibration_map}` and a Datum whose `value` is the validated versioned map, or a structured refusal. The literal is embedded explicitly in a later graph; the CLI does not rewrite the raw graph or its questions.

## Behavior

The host SHALL load and validate the existing Dataset and raw graph, obtain the raw graph's versioned semantic identity from draft FR-063, select only development cases, and execute only those cases with the existing exact replay or live backend path. It SHALL pass checked outcomes to the pure fitter of [FR-083](../../evidence/functional/FR-083.md). Dataset validation inspects the complete input artifact for schema integrity; fit and model execution use no held-out case, label or prediction. The host SHALL refuse an unavailable or non-Probability output, an empty development selection, a fit error and an existing destination before writing. It SHALL write the completed literal exclusively under the existing artifact ceiling, without overwriting graph, Dataset, recording or map files; repeated invocations with byte-identical inputs and outcomes produce byte-identical map files. No endpoint, credential, case input, label or raw recording body enters the map.

The host SHALL keep `measure` split selection explicit: a later graph exposing both raw and CalibratedProbability outputs can be measured on development or held_out, while fitting stays development-only. The map's `fit_graph_semantic_identity` refers to the raw fitting graph, and the later graph's own semantic identity includes the embedded literal. The ordinary `GraphArtifact.source` path/raw-byte identity and ordinary measure source fields stay unchanged. CLI fitting adds no loop controller, threshold sweep, model training or per-slice map behavior.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-084-AC-1 | Two fits on the same synthetic development graph/Dataset/recording into distinct new paths write byte-identical map literals with exact dataset ID/content digest, split, raw graph digest, output, method and case count. | Test (IT-017) |
| FR-084-AC-2 | `--split held_out`, a non-Probability output, missing development cases, fit refusal and existing destination refuse before a map file is written; zero held-out cases are evaluated during fitting. | Test (IT-017) |
| FR-084-AC-3 | Embedding the literal in a calibrated graph changes semantic graph identity, passes `sapho validate`/`inspect`, and replays the original Ask recording when model requests are unchanged. | Test (IT-017) |
| FR-084-AC-4 | Development and held-out `measure` reports expose raw and calibrated Brier/ECE side by side without altering Dataset interchange, original source fields or replay behavior. | Test (IT-017) |
