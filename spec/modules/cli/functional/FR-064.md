# FR-064: Write a model roster from a measured split

## Description

The Sapho CLI SHALL write a bounded model roster from one explicitly selected Dataset split and declared output-to-binding mappings.

## Inputs

A graph, Dataset path, `development` or `held_out` split, live bindings or exact replay recording, explicit output-to-binding/question-type mappings, existing run and artifact ceilings, and a new roster destination path. A separate literal-projection action selects existing roster entries and assigns graph field names; it accepts no profile metric values.

## Outputs

A versioned JSON roster containing dataset ID, split, canonical graph identity, Sapho version, ordered profiles, absent-metric reasons and unattributed cases; optionally a generated typed Record literal for selected entries. Existing paths are not overwritten.

## Behavior

The CLI SHALL validate the Dataset with the existing `Dataset::validate` interface before making model calls.

The CLI SHALL run only cases in the requested split.

The CLI SHALL attach live timing observations only around live ModelBackend calls.

The CLI SHALL pass the resulting evidence to [FR-062](../../evidence/functional/FR-062.md).

A held-out roster SHALL say `held_out`.

A development roster SHALL say `development`.

The CLI SHALL derive provider descriptors from stock binding metadata when present.

The public host API SHALL accept an optional descriptor for a custom ModelBackend without requiring a stock adapter.

If an output mapping is absent or attribution is ambiguous, the CLI SHALL retain explicit unscored/unattributed evidence instead of assigning the output to a model by guess.

A replay-only roster SHALL omit latency values with a `replay_only` reason.

The CLI SHALL construct no live transport or read any credential in replay-only mode.

The CLI SHALL write a completed artifact exclusively under the existing byte ceiling.

When a mapping is malformed, selected cases are absent, the split is invalid, I/O fails or the destination exists, the CLI SHALL refuse without overwriting any prior file.

Ordinary `measure` SHALL expose per-label-kind views using the same case sets and formulas while retaining its existing top-level fields and Dataset interface.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-064-AC-1 | A live two-binding synthetic fixture writes one roster containing both bindings, actual reported models, dataset ID, split, graph identity and Sapho version; call counts agree with trace attempts. | Test |
| FR-064-AC-2 | The same fixture in replay-only mode writes no latency numbers, makes no live request and reads no credential; a held-out invocation marks the roster `held_out`. | Test |
| FR-064-AC-3 | Per-output/per-kind roster metrics equal ordinary `measure`'s per-kind views on the same attributed cases and reflect unscored or ambiguous cases separately. | Test |
| FR-064-AC-4 | A bindings-free custom host with its own ModelBackend produces an entry without a stock provider name; a supplied provider descriptor is retained without entering graph, recording or credential fields. | Test |
| FR-064-AC-5 | Existing destination, malformed mapping, absent selected cases and artifact-ceiling excess refuse without overwriting a file or evaluating an unselected split. | Test |
| FR-064-AC-6 | Literal projection selects two measured entries into a typed Record accepted by `sapho validate`; it refuses a caller-supplied metric value. | Test |
