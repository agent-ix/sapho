# FR-035: Record and replay CLI evaluations

## Description

The Sapho CLI SHALL capture model exchanges and replay them through the existing exact recording boundary.

## Inputs

The explicit typed inputs, options and limits named in Behavior. External files and JSON/YAML are validated before evaluation.

## Outputs

The declared typed result, or a structured refusal. Execution failures retain available partial evidence; absence of a result is never interpreted as a passing evaluation.

## Behavior

record invokes run with an explicit recording destination, retaining successful validated raw exchanges plus the normal complete/partial execution evidence. replay accepts a graph, inputs and recording, reconstructs bindings from recorded identities or explicit matching binding metadata, and supplies only ReplayBackend. Binding inference requires a unique (model, expected_model, DistributionPolicy) tuple for each BackendId across the recording. Conflicting tuples refuse with RecordingMismatch; a required name absent from an empty/partial recording requires explicit binding metadata. Explicit metadata must match recorded identities for that name. A missing required binding refuses with UnknownBackend. Supplied metadata binds ReplayBackend only and never constructs a live transport. It never reads credentials or falls back to live inference. No-model graphs replay with an empty recording. Graph/native logic executes again, so threshold-only changes reuse exchanges when the requests remain identical. Output/trace/recording destinations use exclusive writes, never overwrite existing paths and propagate write errors; raw HTTP bodies and credentials are not new fields. A recording is not a label set: a model answer becomes a label only in a dataset whose provenance declares kind `model` and its source ([FR-036](../../evidence/functional/FR-036.md)).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-035-AC-1 | Recording a scripted multi-layer backend then replaying reproduces outputs and preserves raw responses/policy-sensitive request identities. | Test (TC-035) |
| FR-035-AC-2 | Changed state, ordered questions or binding identity yields ReplayMiss without invoking a live backend. | Test (TC-035) |
| FR-035-AC-3 | Existing artifact paths are preserved; failed runs retain their partial trace and completed successful exchanges when explicit capture was requested. | Test (TC-035) |
