# FR-072: Resolve named System One services from host configuration

## Description

When a live binding declares provider `systemone`, the CLI host SHALL resolve that binding's endpoint and optional credential reference from a separate host service configuration, allowing distinct System One contract services in one process.

## Inputs

A credential-free YAML/JSON bindings document, a bounded JSON host service configuration selected by a `--service-config` path or `SAPHO_SERVICE_CONFIG` path environment value, required compiled binding IDs, and the `agent-ix/sapho` OS secret store. The path argument and environment value contain only a file path, never an endpoint or credential reference. Each host service entry is keyed by exact BackendId and contains `base_url`, optional `credential_key` naming an OS-store secret, and optional `limits` with all four fields `timeout_ms`, `request_bytes`, `response_bytes` and `in_flight`. A `systemone` binding requires an explicit nonempty model, expected model if requested, and DistributionPolicy; it contains no endpoint or credential field.

## Outputs

A live BackendRegistry with one bounded System One backend per required generic binding, or a structured refusal before asynchronous graph evaluation. Service URLs and credential references remain host-only and are omitted from graphs, binding metadata, recordings, run reports, error messages and process arguments.

## Behavior

The host SHALL parse the service configuration under the existing 1 MiB artifact ceiling and reject duplicate IDs, unknown fields, blank or invalid credential keys, and plaintext `credential`, `api_key`, `token` or `authorization` fields.

The host SHALL require exactly one service entry for each required `systemone` BackendId.

An unrequired service entry SHALL cause no transport construction or secret lookup.

The host SHALL reject an endpoint or credential field in a binding document or provider configuration field in a graph ask/node definition. Ordinary graph data literals are never interpreted as host credentials or endpoints.

The host SHALL resolve a present `credential_key` only from the OS secret store under scope `agent-ix/sapho` before async evaluation; absence means an unauthenticated service, and secret-store errors are typed refusals. Generic bindings SHALL not inherit `CLM_API_KEY`, `TYPESAFE_API_KEY` or another binding's key.

The host SHALL pass each resolved base URL, optional redacted secret and per-service Limits to the existing `sapho-clm` System One HTTP implementation; no new adapter crate or wire translator is introduced.

The host SHALL use the adapter defaults of 30-second deadline, 1 MiB request, 8 MiB response and four in-flight calls when a service has no `limits` object.

For a service with `limits`, the host SHALL require integer `timeout_ms` in `[1,30000]`, `request_bytes` in `[1,1048576]`, `response_bytes` in `[1,8388608]` and `in_flight` in `[1,4]` before constructing transport. These are hard stock-host maxima, including when the underlying CLM adapter would accept a larger nonzero value. Each service has its own valid limit values.

A limit refusal SHALL identify the binding without revealing URL or secret.

The host SHALL require HTTPS for a non-loopback URL, using the existing CLM URL validation.

It SHALL allow HTTP for loopback URLs under that same validation. Userinfo, query, fragment, redirect and retry remain refused or disabled as in [FR-044](../../clm/functional/FR-044.md).

The host SHALL prepare only required live bindings. Validation, inspection, replay and replay-backed measure/tune SHALL not load the service configuration, resolve its secrets or construct a live transport.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-072-AC-1 | One bindings file with `fast_a` and `fast_b` as `systemone` and one host service file mapping them to two distinct loopback ports sends each ask to its configured port, verified by independent captures. | Test |
| FR-072-AC-2 | A third required service name appears only in graph, binding and host-configuration files and uses the generic adapter path without a third-service-specific provider variant, adapter crate or hard-coded name. | Test |
| FR-072-AC-3 | Binding or graph provider fields named endpoint/credential/api_key are refused; the host file rejects plaintext secret and unknown fields, while a valid OS-store key reference resolves only for its required binding and no secret or URL appears in argv, binding or recording bytes. | Test |
| FR-072-AC-4 | Remote HTTP, URL userinfo/query/fragment, zero limits and unavailable/invalid credential references refuse before sending; loopback HTTP and remote HTTPS remain accepted under the existing adapter rule. | Test |
| FR-072-AC-5 | Scripted stalled/oversize/concurrent calls retain the configured per-service deadline, request/response ceilings and in-flight limits; one service's limits do not alter another's. | Test |
| FR-072-AC-6 | An unused service entry makes no transport or secret lookup; offline commands never read service configuration or credentials, and `systemone` with omitted model refuses while existing CLM omitted-model default remains available. | Test |
| FR-072-AC-7 | Zero and above-maximum values for each of `timeout_ms`, `request_bytes`, `response_bytes` and `in_flight` refuse before transport, while exact maxima pass host validation; reducing one binding's limit leaves another binding's default or override unchanged. | Test |

## Dependencies

[FR-034](FR-034.md) owns CLI host execution. [FR-044](../../clm/functional/FR-044.md) owns the bounded HTTP adapter and remote HTTPS rule. [FR-045](FR-045.md) owns legacy Jev/CLM credential precedence; generic service credentials use an explicit per-binding OS-store key and do not alter it. The shared `sapho-systemone` codec remains the only wire translator.
