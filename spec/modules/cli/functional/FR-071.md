# FR-071: Run and report a held-out promotion gate

## Description

When the CLI evaluates a pre-registered gate, it SHALL retain the full measurement and bar report and return a process status that distinguishes a complete NO-GO from incomplete or refused evidence.

## Inputs

An existing exclusive registration artifact, the unchanged gate file, graph, validated Dataset, held-out split, explicit backend or exact replay bindings, independent repetition requests and existing run/artifact ceilings. Output destinations are exclusive.

## Outputs

A bounded typed JSON report with gate and measurement identities, every output/bar result, overall GO/NO-GO, the underlying measurement coverage and a process exit code. No deployment or model alias is selected.

## Behavior

The CLI SHALL verify registration and current gate bytes, Dataset content, split, semantic graph identity and exact gate-to-graph output-name equality before starting any primary or repeated case evaluation.

The CLI SHALL run only the held-out cases named by the validated Dataset and preserve the existing `measure` coverage, self-source, error and replay behavior.

The CLI SHALL write a complete report exclusively under the existing artifact byte ceiling, including every evaluated and not-computed bar, even when the verdict is NO-GO.

When every selected label and required repetition is scored without failure and all bars pass, the CLI SHALL report GO and exit 0 (`completed`).

When measurement coverage is complete but one or more bars fail or are not computed, the CLI SHALL report NO-GO and exit 1 (`finding`). This includes an unavailable ECE on a complete Boolean-only output.

When a selected label or required repetition is unscored/failed, or registration/configuration/identity validation refuses, the CLI SHALL report NO-GO or structured refusal and exit 2 (`refused`). Exit 2 takes precedence over bar failure, retaining available partial evidence.

When the selected split is development, the CLI SHALL refuse as nonpromotable with exit 2 before any evaluation.

The CLI SHALL preserve ordinary `measure` exit policy: its own unscored/failed selected labels still exit 2, while the new gate command uses 1 for a complete bar failure and 2 for incomplete/refused evidence.

The CLI SHALL NOT deploy, mutate a graph, choose a model name or mark a promotion accepted in a tracker.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-071-AC-1 | A complete tied-baseline or below-bar synthetic held-out measurement returns NO-GO code 1 with every bar row; a complete all-bars-pass fixture returns GO code 0. | Test |
| FR-071-AC-2 | If one selected label is unscored or a repetition fails while another bar also fails, the report is NO-GO with partial evidence and exit 2, matching ordinary `measure`'s incomplete-coverage code. | Test |
| FR-071-AC-3 | A development split, edited gate bytes, identity or output-set mismatch, or existing report destination refuses with code 2 before case evaluation and does not overwrite prior artifacts. | Test |
| FR-071-AC-4 | Gate output contains gate byte/semantic digests and measurement Dataset ID/content, held-out split and graph semantic identity; ordinary `measure` fields and exit codes remain unchanged. | Test |
| FR-071-AC-5 | A synthetic graph with a custom backend and no model-name gate field evaluates identically through live and exact replay evidence; no deployment or private EARS Dataset is required. | Test |
