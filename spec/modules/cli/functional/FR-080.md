# FR-080: Publish sweep candidates without overwriting artifacts

## Description

When a literal grid has passed complete validation, the CLI SHALL write candidate graphs and a deterministic manifest only to a newly created destination directory.

## Inputs

The validated, bounded candidate JSON byte buffers and `--output-dir` path from [FR-079](FR-079.md). The caller chooses the destination; it must not exist when publication begins and must not be the base graph path or its ancestor.

## Outputs

Exactly `candidate-0000.json` through `candidate-NNNN.json` in Cartesian order and `sweep-manifest.json`, or a structured no-overwrite refusal. The manifest has `format: "sapho-sweep-v1"`, SHA-256 digests of the exact base and grid input bytes, and ordered entries with index, candidate filename, ordered axis ID/value coordinates and SHA-256 digest of the emitted candidate file bytes. The manifest is separate from GraphSpec; generated files contain no non-schema metadata. Digests identify exact bytes, not SAPHO-25's canonical graph identity or the existing path-plus-raw-byte GraphArtifact.source.

## Behavior

The command SHALL derive filenames solely from zero-based Cartesian indices, padded to four decimal digits.

Candidate JSON serialization SHALL be deterministic for the same parsed base, grid and generator format version: object fields follow the declared GraphSpec/Value serialization order, BTreeMap keys follow lexical order, arrays preserve declared order, and finite numbers use the pinned JSON serializer's representation. The `sapho-sweep-v1` manifest describes this serializer contract; no cross-version YAML/JSON semantic-digest equivalence is claimed.

The manifest SHALL map every filename to exactly one grid point.

Output order SHALL be usable directly as the explicit `tune --candidate` order.

The command SHALL finish all parsing, type checking, candidate compilation, serialization and byte-ceiling checks before attempting to create the output directory.

It SHALL create that directory exclusively, refusing any existing directory or file, even if empty.

Inside it, candidate files and manifest SHALL use exclusive new-file creation; manifest is written last.

A collision SHALL never truncate or replace an existing path. If a write error occurs after directory creation, the command SHALL remove only files it created and remove the directory if then empty.

It SHALL report the failure rather than present a partial manifest.

It SHALL never mutate the base graph, grid, recording, labels or any existing tune candidate.

The command SHALL perform no graph evaluation. Passing generated candidates to ordinary `tune` SHALL preserve FR-037 development-only selection, scoring, ranking and explicit candidate order. When only downstream decision literals change and model requests are byte-identical, each candidate SHALL replay against the same recording without ReplayMiss; a grid that changes a request-affecting literal remains subject to exact replay refusal and is not silently repaired. Generation reads no Dataset, and tune evaluates and scores development cases only; held-out cases cause no model calls.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-080-AC-1 | Two generation runs from identical base/grid bytes in distinct new directories emit byte-identical candidate files and manifest; names/index/coordinates/digests match the declared order. | Test (IT-016) |
| FR-080-AC-2 | An existing destination file or directory, including an empty directory, refuses before candidate write and remains byte-identical; the base graph and grid remain byte-identical after success and refusal. | Test (IT-016) |
| FR-080-AC-3 | `tune` over generated candidates in manifest order and over equivalent handwritten graphs gives identical development metrics, rank positions and input-order tie-break (path-derived candidate IDs can differ); held-out cases receive zero calls. | Test (IT-016) |
| FR-080-AC-4 | Downstream-only cutoff/weight candidates replay against one recording with no ReplayMiss and identical model request evidence; a request-affecting literal change still gets exact ReplayMiss. | Test (IT-016) |
| FR-080-AC-5 | An injected file-write failure leaves no manifest or overwritten pre-existing file and reports a structured error; any cleanup touches only sweep-created files. | Test (IT-016) |

## Dependencies

[FR-079](FR-079.md) validates the full grid before publication. [FR-035](FR-035.md) owns exact replay and [FR-037](../../evidence/functional/FR-037.md) owns explicit development-only tuning. Dataset JSON/serde/validate and EARS export remain unchanged.
