# FR-046: Use shared CLI foundations

## Description

The Sapho CLI SHALL use ix-cli-kit for applicable stream, exit-code, configuration precedence and version mechanisms while preserving its observable contracts.

## Inputs

Checked core requests or host-selected configuration; untrusted bytes are bounded and validated.

## Outputs

Typed responses or a structured refusal; private contents are excluded from diagnostics.

## Behavior

Shared stream writers emit existing typed JSON envelopes to stdout and diagnostics to stderr. Bounded core serialization remains responsible for artifact ceilings; shared JSON is not used to change float/order/size semantics. Existing ExitStatus variants and serialized spellings remain; codes delegate to shared constants/outcomes for 0 completed, 1 finding and 2 refusal. Refusal still retains existing structured/partial evidence envelopes, so the CLI does not adopt the shared carries_payload predicate. Argument errors stay code 2. Every error object the CLI writes, on stderr or inside a refusal envelope, holds exactly the error code, its reason when present, its content-free message and its named context fields (such as the numbers of `TooLarge`); a SaphoError's raw exchange and usage are omitted from it, while trace evidence keeps raw exchanges as [FR-017](../../runtime/functional/FR-017-produce-execution-evidence.md) states. Clap continues owning arguments. Version remains sapho plus package version, verified against the built executable through shared version agreement. Existing constrained YAML/JSON parser and explicit artifact paths stay owning implementations; shared config precedence is applied to host endpoint/environment selection. Depend directly on ix-cli-kit; no copied implementation or new compatibility layer.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-046-AC-1 | Process success/finding/refusal and argument failures preserve codes 0/1/2, JSON envelope spellings and stdout/stderr separation through shared stream/exit mechanisms. | Test |
| FR-046-AC-2 | Version reports the manifest package version verified by shared version agreement and host endpoint precedence selects explicit > environment > default. | Test |
| FR-046-AC-3 | A command refused with a SaphoError that carries a raw exchange with a planted sentinel body and usage writes an error object whose members are exactly code, reason, message and context fields, and neither stdout nor stderr of the refusal's error object contains the sentinel. | Test |
