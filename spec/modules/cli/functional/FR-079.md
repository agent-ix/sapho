# FR-079: Expand a declared literal grid into validated candidate graphs

## Description

When a caller supplies a base graph and explicit grid, the separate `sapho sweep` CLI command SHALL generate the complete Cartesian set of graphs by replacing only selected literal values.

## Inputs

`sapho sweep <base.yaml|base.json> --grid <grid.json> --output-dir <new-directory> [--max-candidates N]`. The strict JSON grid has exactly an `axes` array of 1–8 entries; each entry has exactly `id` (a literal Datum ID) and nonempty `values`. Each axis has at most 16 values. A Probability literal axis uses finite JSON numbers in `[0,1]`; a `List(Number)` literal axis uses nonempty arrays of finite JSON numbers with exactly the base list's length. The list's Datum item IDs, order and SourceRefs come from the base. Example: `{"axes":[{"id":"cutoff","values":[0.6,0.7,0.8]},{"id":"weights","values":[[0.25,0.75],[0.5,0.5]]}]}`.

## Outputs

One valid JSON GraphSpec candidate per grid point and a versioned manifest, all inside the new output directory; or a structured refusal with no generated candidate files on validation or destination-collision errors. No dataset, model binding, recording or held-out split is an input to this command.

## Behavior

The command SHALL read base and grid under separate 1 MiB input ceilings, parse the base with the existing strict YAML/JSON loader and compile it using stock CLI graph validation.

It SHALL find literal Bindings in root and named subgraph nodes, guards and outputs by exact Datum ID.

Every axis ID SHALL name exactly one literal occurrence in the entire GraphSpec; unknown, repeated or ambiguous IDs refuse.

Axis IDs themselves SHALL be unique.

The target literal's declared ValueType SHALL be exactly Probability or List(Number).

Its current Datum value SHALL validate against that type.

A weight-list replacement SHALL change only each item's numeric Value, preserving the outer literal Datum ID, inner item IDs/order, SourceRefs and declared ValueType.

A Probability replacement SHALL change only the probability Value. No operation, question wording, prompt, input type, binding identity, graph topology or other literal metadata is rewritten.

The command SHALL compute the full Cartesian product with checked multiplication. The maximum count is 16 by default, matching `tune`'s default; an explicit `--max-candidates` from 1 through 256 permits a larger generation, and a larger tune still requires its own explicit `--max-candidates`. Zero, overflow, a product over the selected ceiling or a requested ceiling over 256 refuses before any filesystem write. Cartesian enumeration follows last-axis-minor order: for each value of the first axis in declared order, enumerate every combination of later axes; adjacent candidates change the last axis until its values are exhausted. Values retain declared order, including numerically equal values. Candidate index is zero-based in that order. No random, adaptive or partial search is performed.

The command SHALL materialize, serialize and validate every candidate through the same stock graph parser/compiler as `sapho validate`, checking the entire grid for invalid values and graph compile errors prior to destination creation. Each candidate JSON is capped at 1 MiB and all candidate plus manifest bytes at 32 MiB; these checks also precede any write.

Typed GraphSpec comparison between base and candidate SHALL differ only at the selected literal Values. The generated graph has no extra metadata fields and can be passed unchanged as an explicit `--candidate` path to [FR-037](../../evidence/functional/FR-037.md).

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-079-AC-1 | A base with Probability literal ID `cutoff` and grid values 0.6, 0.7, 0.8 produces three valid candidates in that order; typed GraphSpec comparison shows only the target Value changed, and the base bytes stay identical. | Test (IT-016) |
| FR-079-AC-2 | A 3×2 cutoff/weight-list grid produces six candidates in first-axis-slowest order; each candidate preserves weight item IDs/order/sources and has a manifest entry identifying its exact coordinate. | Test (IT-016) |
| FR-079-AC-3 | Probability 1.2 in a later grid point, a nonfinite/malformed weight, unknown/ambiguous/duplicate target ID, wrong list length, too many axes/values or product above the selected ceiling refuses before destination creation. | Test (IT-016) |
| FR-079-AC-4 | Default ceiling 16 accepts a 4×4 grid and refuses a 5×4 grid; explicit ceiling 20 accepts 5×4, while a requested ceiling of 257 and any product over the selected ceiling refuse. | Test (IT-016) |
| FR-079-AC-5 | Generated candidates pass stock `sapho validate`; a grid that would edit Questions or an unsupported literal type refuses, and the command has no dataset or held-out evaluation path. | Test (IT-016) |
