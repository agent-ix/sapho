# FR-060: Invoke and report shadow comparisons

## Description

The Sapho CLI SHALL include declared shadow observations in run, record, replay and measure reports while preserving the decision command's exit policy.

## Inputs

The existing graph, bindings, dataset and recording arguments; measure additionally accepts an explicit shadow comparison selection, metric and minimum improvement margin.

## Outputs

The existing decision report plus separate shadow observations or side-by-side comparison. Shadow artifacts use the existing exclusive-write and byte-ceiling rules.

## Behavior

`run`, `record` and `replay` SHALL report shadow outcomes separately from decision outputs. A shadow failure SHALL leave a successful decision's exit status at 0, or at 1 when the existing selected finding is true. `measure` SHALL accept a shadow ID, mapped decision output, metric and margin and pass the selected split's observations to [FR-059](../../evidence/functional/FR-059.md). It SHALL form ordinary CaseOutcome model identities from decision-phase responses only; it passes shadow model identities in a separate observation collection for role-specific self-source handling. It SHALL report incomplete shadow coverage explicitly without treating that absence as a failed decision measurement. A shadow comparison SHALL never replace the normal measure result or turn a development comparison into a promotion verdict. Existing command invocation and machine-output fields SHALL remain accepted for graphs without shadows. No command SHALL duplicate or modify Dataset labels to make a comparison.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-060-AC-1 | `record` then offline `replay` with a successful shadow yields the same decision outputs and shadow observation, with no live request during replay. | Test |
| FR-060-AC-2 | A shadow timeout or ReplayMiss leaves the existing decision exit code unchanged and emits the shadow's typed failure in the report. | Test |
| FR-060-AC-3 | `measure --split held_out` reports the declared margin and role metrics side by side; `--split development` marks the comparison not promotable. | Test |
| FR-060-AC-4 | A graph with no shadows retains its existing invocation, output schema and exit policy; existing artifact paths are not overwritten. | Test |
| FR-060-AC-5 | A shadow model matching a case label's model source does not enter the ordinary `measure` CaseOutcome model list or alter the serialized ordinary `Measurement` value or exit status; the separate comparison reports shadow self-source exclusion. Graph identity and run-document bytes may differ. | Test |
