# IT-018: Exercise Decisions wire, transport and replay without a live account

## Objective

Prove official Decisions JSON mapping, typed refusal/usage, bounded bearer HTTP, required-only CLI preparation and offline exact replay through public Sapho contracts.

## Target Integration

`sapho-decisions` ModelBackend using a scripted Transport and ephemeral loopback capture server; core `validate_response`, runtime Ask/Trace, recording/replay, and stock CLI provider/credential seams. Tests run without the OpenAI service, live API key or model installation.

## Preconditions

A graph has one Ask with explicit backend `judge`, model `gpt-6-luna`, a Record state, and three ordered questions: Boolean `relevant` with yes/no criteria, Choice `route` with labels `true` and `billing`, and Score `severity` with three descriptions. The synthetic response reports model `gpt-6-luna`, predicate 0.8, choice `billing` with confidence 0.4 and probabilities 0.1/0.9, score 1.1 with confidence 0.55 and level probabilities 0.1/0.7/0.2, input_tokens 42, output_tokens 0, cache/reasoning details 0 and total_tokens 42. No fixture asserts model quality or calibration.

## Inputs

The three-question request and synthetic success body; ordinary and image-envelope states; one-field malformed wire mutations; injected credential/store snapshots; bounded fake transport and loopback HTTP capture; exact Recording fixtures.

## Test Procedure

1. IT-018-SC-01: Encode the three questions through the real codec and capture the POST JSON. Assert exact `model`, ordinary Record compact-JSON text input, ordered named predicate/choice/score, Boolean criterion wording, typed string choice values, indexed score labels, no source sidecars/DistributionPolicy/secret, and one request only. Decode the synthetic response and assert exact numeric values, actual model, core usage with no billing units or digest, and core validation under Strict policy.
2. IT-018-SC-02: Supply the explicit `decisions_input` envelope with text and two small valid data URLs. Assert one `role:user` message, ordered `input_text` and two `input_image` parts, no URL fetch and exact replay. Empty images use string input. Malformed envelope, invalid base64/MIME, hosted HTTP(S) URL, file ID, more than eight images, empty/mismatched questions, more than 32 choices/levels/questions and wrong model refuse before transport.
3. IT-018-SC-03: For each answer variant mutate only one field: refusal in the middle, reorder, missing/extra/duplicate/null name, wrong kind, boolean choice value `true`, incomplete/duplicate/extra choice or score mass entries, mismatched score index/label, out-of-range/nonfinite number, missing/negative usage, unknown field and duplicate JSON key. Assert `MissingAnswer` or `InvalidAnswer` with stable reason/question context, no partial Answers, safe printable diagnostics, and bounded in-memory raw exchange on successful HTTP bodies. Test Strict versus Approximate complete-mass policy through unchanged provider bytes and core validation.
4. IT-018-SC-04: Inject a fake credential store/environment and capture precedence and key/scope for a required live binding. Assert no secret access for unused binding, `validate`, `inspect`, `replay`, replay-backed `measure`/`tune`, or a build lacking the provider feature. Assert absent/blank/key-invalid credential, omitted/wrong model and endpoint/credential fields in metadata refuse before HTTP. Capture one successful response then replay with feature/key/network absent, preserving exact request, answers, model, usage and raw bodies; mismatched explicit replay metadata refuses.
5. IT-018-SC-05: Use an ephemeral loopback HTTP server and injectable clock/transport to check the `/v1/decisions` path, bearer and JSON headers, no redirect/retry, request/response exact and over-ceiling bytes, false Content-Length, zero/exact-max/above-max limits, four permits, waiting/sending/body stalls and cancellation. Assert no more than four in-flight calls and a freed slot after cancellation. Use status fixtures 400/401/403/422/429/500, including a 429 quota-shaped body, plus malformed success and transport error; assert exact ErrorCodes and no sentinel key, input, body, header or URL in error serialization/Display/Debug or non-success raw evidence.
6. IT-018-SC-06: Inspect only official guide/reference citations and the date in FR-047/SR-066, the dedicated Decisions provider registry path, and absence of any Responses/Chat substitution. Keep a separate live check pending until an authorized account has quota/access; do not mark synthetic tests as a live inference receipt.

## Expected Results

Each scenario has exact JSON, typed-value, error-code, call-count, time/byte-ceiling or replay evidence. Existing Dataset JSON/serde/validate and EARS export remain unchanged. FR-047/085/086/087 AC IDs are attached to the eventual runnable tests with `Trace:` tags.
