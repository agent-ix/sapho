# FR-086: Bound authenticated Decisions HTTP calls

## Description

When a host configures a live Decisions backend, the adapter SHALL send one bounded bearer-authenticated request to the official endpoint and classify transport failures without exposing private content.

## Inputs

A checked FR-085 request, nonempty redacted bearer `SecretValue`, and finite `Limits`. Defaults and maximum accepted overrides are 30 seconds total, 1 MiB serialized request, 8 MiB response and four simultaneous calls per adapter; all minima are one. The production endpoint is fixed to `https://api.openai.com/v1/decisions`. A test-only injected native `Transport` or loopback capture server exercises codec and HTTP without a live account; the CLI has no endpoint override.

## Outputs

A bounded complete HTTP success body for FR-085 decoding, or a structured `SaphoError` with stable ErrorCode, HTTP status where available and no request, response, key, headers or URL in printable diagnostics.

## Behavior

The adapter SHALL require HTTPS certificate validation and `Authorization: Bearer <secret>` plus `Content-Type: application/json`, without serializing the secret into ModelRequest, BindingConfig, Recording or argv. It SHALL reject absent/blank/header-invalid credentials and zero/above-maximum limits before transport. It SHALL disable redirects and automatic retries, issue one POST attempt, and apply the total deadline to permit wait, connect, send, streamed response and decode. A semaphore enforces per-adapter in-flight calls; cancellation releases a permit. Request serialization checks the byte ceiling before send. Success body collection enforces the response ceiling independent of Content-Length; non-success bodies are discarded without decoding or recording because they can echo sensitive input. The native transport seam remains injectable while the real serializer/decoder and limits execute.

HTTP 401/403 SHALL map to `Unauthorized`, 429 to `RateLimited`, 400/422 to `ServiceValidation`, timeout to `DeadlineExceeded`, request/response overflow to `LimitExceeded`, and all other HTTP/transport failures to `BackendFailed`; malformed UTF-8/JSON or invalid success schema maps to `InvalidAnswer`. A 429 with `insufficient_quota` remains `RateLimited` with status only in diagnostics, with no claim that live acceptance passed. A success response retains exact UTF-8 request/response bodies as RawExchange for recording and partial Trace; headers and URL never enter RawExchange. Credential and account access errors do not trigger a Responses or Chat fallback.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-086-AC-1 | A loopback capture seam observes exactly one POST to `/v1/decisions` with JSON content type and bearer authorization; redirects, retries and alternate API paths are absent. | Test (IT-018) |
| FR-086-AC-2 | Missing/invalid credential and zero/above-cap limit values refuse before send; exact maximum values are accepted and per-adapter concurrency never exceeds four. | Test (IT-018) |
| FR-086-AC-3 | Request/response byte boundaries, Content-Length lies, stalled permit/send/body and cancellation enforce the configured deadline/ceilings and release capacity. | Test (IT-018) |
| FR-086-AC-4 | 401/403/429/400/422/5xx, malformed success and transport failures map to the named codes; error formatting excludes sentinel key, input, body, header and URL; non-success bodies never enter raw evidence. | Test (IT-018) |
| FR-086-AC-5 | Successful response retains bounded raw UTF-8 request/response bodies without auth headers and replays offline with the same typed result. | Test (IT-018) |
