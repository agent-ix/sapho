# FR-085: Translate typed questions to the verified Decisions wire contract

## Description

When a checked `ModelRequest` uses the Decisions binding, the adapter SHALL serialize the official Decisions request and decode its typed response without changing the core question or answer meanings.

## Inputs

A core `ModelRequest` with requested model exactly `gpt-6-luna`, nonempty ordered questions, Record state and explicit `DistributionPolicy`. One request maps to one Decisions call. At most 32 questions, 32 choices or score levels per question and 8 inline images are a Sapho subset of the larger beta contract; serialized request bytes remain within FR-086.

## Outputs

A core `ModelResponse` with actual returned model, one answer per requested ID, available usage and raw UTF-8 request/response bodies, or a typed `SaphoError` retaining safe in-memory exchange evidence on a successful HTTP response.

## Behavior

The adapter SHALL send JSON object `{"model":"gpt-6-luna","input":...,"questions":[...]}` to the official endpoint. It omits `safety_identifier` because ModelRequest has no verified end-user identity, along with source sidecars, graph IDs, credentials and DistributionPolicy. The top-level Record key `decisions_input` is reserved as the sole envelope trigger: if it is absent, `input` is the deterministic compact JSON string of `state.to_plain_json()`, with object keys sorted and list order preserved. If it is present, the only accepted state is a Record with exactly that one field, whose value is a Record with exactly `text: Text` and `images: List(Text)`. Any additional top-level field, `decisions_input: Text`, missing/wrong inner field or wrong inner type refuses `InvalidValue` with `reason=invalid_decisions_input_envelope` before transport; it never falls back to ordinary JSON text. This rule preserves the existing mapping of every Record without the reserved key and makes a preexisting use of that key an explicit refusal rather than a silent reinterpretation.

A valid envelope maps to one user message with ordered `input_text` followed by `input_image` parts. Each image text is a syntactically valid base64 `data:image/png`, `jpeg`, `webp` or `gif` URL; it is checked without network fetch. An empty image list maps to a plain `input` string equal to text. The adapter does not accept hosted image URLs or file IDs. This conservative image subset resolves the current official guide/reference conflict documented in SR-066.

Each Boolean question SHALL map to `type:"predicate"`, `name` equal to its core ID, and exact instructions formed as `instructions + "\nTrue criterion: " + yes + "\nFalse criterion: " + no`. A Choice maps to `type:"choice"`, ordered string-valued `choices` with `value` equal to each core label and `description` equal to each description. A Score maps to `type:"score"`, ordered `levels` with `label` equal to the decimal zero-based index and `description` equal to the core level text. Choice labels remain strings even if they spell `true` or `false`. The adapter rejects empty IDs, instructions/criteria/descriptions, duplicate choice labels, unsupported model, excessive cardinality or serialized bytes before the transport seam. It never changes the existing core Question serde.

The decoder SHALL require a JSON object with reported `model`, `answers` array and `usage`; answer array length and order equal the submitted question array and every answer echoes the matching nonnull unique name and expected type. Predicate `probability` maps unchanged to `Answer::Boolean`. Choice `choice`, `confidence` and the `probabilities` array map unchanged to selected string, confidence and a complete label-probability map. Score `score`, `confidence` and the `probabilities` array map unchanged to expected number, confidence and a complete index-keyed probability map; each returned numeric `value` and `label` match the requested zero-based level and label, with no duplicates. Every probability/confidence is finite in [0,1]; score is finite and within the level index range. The adapter checks wire shape, complete option membership and duplicate JSON object keys, but retains reported numeric values without normalization, confidence recomputation or score recomputation. Core `validate_response` then applies the supplied DistributionPolicy to distribution mass and checks requested/actual model identity. Unknown top-level or answer fields and wrong typed choice values refuse as `InvalidAnswer`.

A per-question `type:"refusal"` SHALL stop the whole core Ask with `InvalidAnswer` and context `reason=provider_refusal` plus only the affected question ID; no partial `Answers` is fabricated, including when other questions were answered. A missing answer SHALL refuse as `MissingAnswer`; extra, unnamed, duplicate or wrong-kind answers refuse as `InvalidAnswer`. The refusal or invalid successful body retains bounded raw exchange in-memory for partial Trace, never in serialized error diagnostics. Core `Usage` receives the reported nonnegative `input_tokens` and `output_tokens`; `billing_units` is None. Nested cache/reasoning counts and `total_tokens` are validated as nonnegative and retained in raw evidence, without manufacturing fields in core Usage. Invalid/missing usage refuses `InvalidAnswer`. The adapter does not claim a weights digest because the response supplies none.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-085-AC-1 | A three-question synthetic request sends exact model, input, ordered predicate/choice/score fields and IDs; Boolean yes/no criteria, string choice values, score index labels and source exclusion are byte-inspectable. | Test (IT-018) |
| FR-085-AC-2 | Ordinary nested Record state maps to stable compact JSON text; the explicit text/image envelope maps to one user message with ordered parts and inline data URLs, while malformed envelope, hosted URL and file ID refuse before transport. | Test (IT-018) |
| FR-085-AC-3 | Synthetic predicate, choice and score answers map exact provider probabilities, selected value, separate confidence, fractional score, reported model and usage into core without normalization or invented billing/weights identity. | Test (IT-018) |
| FR-085-AC-4 | Refusal, reordered/missing/duplicate/wrong-kind/null-name answers, boolean-valued choice, duplicate/missing/extra probability entries, score index/label mismatch, nonfinite/out-of-range numeric fields and invalid usage refuse with typed errors and retained safe raw evidence. | Test (IT-018) |
| FR-085-AC-5 | Strict and Approximate policies apply only at core validation, preserve the same raw provider distribution and yield unchanged exact replay identities; oversized cardinality or wrong model sends nothing. | Test (IT-018) |
| FR-085-AC-6 | An ordinary Record without `decisions_input` keeps the prior compact-JSON input; a Record with that key plus another field, or that key holding Text, refuses `InvalidValue` before transport rather than silently serializing or entering image mode. | Test (IT-018) |
