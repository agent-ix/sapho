# FR-041: Select typed values from structured data

## Description

The Sapho JSON selector SHALL project a declared JSON pointer and decode it against an explicit value schema.

## Inputs

The explicit typed inputs, options and limits named in Behavior. External files and JSON/YAML are validated before evaluation.

## Outputs

The declared typed result, or a structured refusal. Execution failures retain available partial evidence; absence of a result is never interpreted as a passing evaluation.

## Behavior

json takes a bounded JSON file or supplied bytes, RFC 6901 pointer (empty pointer selects the root), declared ValueType, identity prefix and output port. Pointer tokens decode ~0 and ~1; invalid escapes, absent keys, invalid array indices and type mismatch are distinct refusals. Decoding uses the shared pure schema-directed converter, preserves deterministic list occurrence identities and records the retained document as the source; it does not claim precise original spans for escaped/parsed subvalues. Duplicate JSON keys are refused before projection. It emits an Inputs document that can be piped into run --typed-input, including empty typed lists. Graph bindings/filter/map remain the in-graph selection mechanism; this selector performs no inference.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-041-AC-1 | An escaped pointer selects the correct record/list and produces the declared typed values, IDs and whole-document source attribution. | Test (TC-041) |
| FR-041-AC-2 | Missing paths, invalid escapes/indices, duplicate keys and wrong types are distinguishable refusals. | Test (TC-041) |
| FR-041-AC-3 | A selected empty list pipes into a matching graph and consumes no model calls; limits apply before whole-document parsing. | Test (TC-041) |
