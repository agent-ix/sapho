# FR-040: Select explicit Git changes

## Description

The Sapho Git selector SHALL gather complete patches for an explicit change selection.

## Inputs

The explicit typed inputs, options and limits named in Behavior. External files and JSON/YAML are validated before evaluation.

## Outputs

The declared typed result, or a structured refusal. Execution failures retain available partial evidence; absence of a result is never interpreted as a passing evaluation.

## Behavior

git takes an explicit repository root and mode working_tree, staged or revisions with explicit base/head. working_tree compares tracked working/index state with HEAD; staged compares index with HEAD; revisions resolves both supplied commit references and compares those commits. Untracked files are not implied. Git 2.34 or later is required, checked by git --version; missing/older Git and invalid/unborn revisions are explicit errors. Commands run through argument vectors without a shell, with external diff/textconv disabled, bounded output/stderr, deadline and process cleanup. Rename detection is disabled so a rename is explicit deletion/addition. Changed paths use NUL-delimited metadata and deterministic lexical ordering; each unit contains path, full unified diff text and change status. Binary changes, submodule changes or unsupported non-text path encodings refuse acquisition. No source/output contains a cropped patch. Include/exclude path globs and the same count/byte limits as files apply. Attribution identifies exact retained patch bytes and resolved comparison identities.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-040-AC-1 | A temporary repository produces correct staged, tracked working-tree and explicit revision patches with paths/status and deterministic identity. | Test (TC-040) |
| FR-040-AC-2 | Invalid references, binary/submodule changes and unavailable Git produce distinct refusals; untracked files are not silently treated as diffs. | Test (TC-040) |
| FR-040-AC-3 | Paths beginning with punctuation are safe argument data; deadline/output limits terminate and reap the owned Git child with no partial-context success. | Test (TC-040) |
