# FR-063: Consume measured roster profiles as typed graph literals

## Description

The graph tools SHALL accept a generated roster profile projection as a checked Record literal whose fields can feed ordinary typed operations.

## Inputs

A versioned roster artifact and an explicit ordered selection of roster entries, each given a valid graph field name by the author. The roster writer supplies the selected entries as a typed Datum Record and matching ValueType Record; graph configuration embeds that generated literal through the existing Binding::Literal form.

## Outputs

A typed literal with fixed field schemas for selected profiles, or a structured refusal for unknown entries, duplicate field names or values that fail the graph's type and size ceilings. A versioned canonical graph identity includes the complete parsed GraphSpec, including the literal.

## Behavior

The roster projection SHALL expose numeric call and metric fields, optional latency and usage fields, and text identity/provenance fields with exact ValueType schemas.

The projection SHALL use absent Optional values for uncomputed metrics, including replay-only latency and ECE before SAPHO-21, rather than a numeric zero.

The graph compiler SHALL validate the generated Record with the same rules as any other typed literal.

The graph compiler SHALL accept bindings that project two selected numeric fields from the Record into an ordinary compare operation.

The roster's `graph_semantic_identity` SHALL be `graph-v1:sha256:` followed by the lowercase hex SHA-256 of the UTF-8 bytes `sapho.graph.v1\n` followed by canonical JSON of the parsed, typed GraphSpec. This versioned identity is distinct from `GraphArtifact.source`, whose existing value is derived from the source path and SHA-256 of raw file bytes. Existing `GraphArtifact.source` values and ordinary `measure` report source fields SHALL remain unchanged.

Canonical JSON SHALL serialize typed GraphSpec fields and all literal values and declared types with no insignificant whitespace and stable JSON escaping.

It SHALL recursively sort named/object map keys by Unicode code point, preserve the order of arrays and graph sequences (including nodes and questions), and normalize finite numeric values to their shortest round-trippable decimal form, with integral forms such as `1`, `1.0` and `1e0` rendered identically and negative zero rendered as zero.

The identity calculator SHALL refuse nonfinite numbers.

Canonical JSON SHALL exclude source path, YAML/JSON formatting and serialization-only defaults that have no typed GraphSpec value.

The literal projection SHALL whitelist only the bounded provider name and adapter name from [FR-061](../../runtime/functional/FR-061.md).

It SHALL refuse unvalidated provider data and contain no endpoint, credential or free-form host metadata.

The roster writer SHALL not accept caller-supplied profile metric values.

Graph authors can embed a measured snapshot; the compiler does not certify that a copied literal was measured.

Changing a roster literal value SHALL change graph identity even when model requests remain unchanged.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-063-AC-1 | A generated Record with two named roster entries passes `sapho validate`; two numeric profile fields feed an ordinary compare operation with the expected Boolean result. | Test |
| FR-063-AC-2 | Changing only one roster literal metric changes `graph_semantic_identity`; equivalent YAML/JSON GraphSpec content, reordered named maps and equivalent numeric spellings yield the same identity, while reordered graph sequences change it. | Test |
| FR-063-AC-3 | Unknown roster entry, duplicate graph field name, malformed Optional, mismatched ValueType and graph limit excess are refused before graph execution. | Test |
| FR-063-AC-4 | Replay-only latency and unavailable ECE project as absent Optionals, never as Number zero; no credential or endpoint enters the literal. | Test |
| FR-063-AC-5 | The same typed graph loaded from distinct paths or source formatting has the same `graph_semantic_identity` while its existing `GraphArtifact.source` remains path/raw-byte dependent and ordinary `measure` source fields remain unchanged. | Test |

## Dependencies

[FR-007](FR-007-load-declarative-graph-configuration.md) and [FR-008](FR-008-compile-checked-acyclic-graph.md) own parsing and checked literals. [FR-062](../../evidence/functional/FR-062.md) owns the measured profile values. The semantic graph identity digest binds a roster measurement to the exact graph content it describes; the existing source identity continues to describe the loaded file.
