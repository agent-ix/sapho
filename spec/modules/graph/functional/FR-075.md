# FR-075: Declare repeated samples on an ask node

## Description

When an Ask operation declares a sample count, the graph compiler SHALL expose a statically typed repeated result without treating sample indices as state or mapped input.

## Inputs

An Ask operation with `backend` and optional positive integer `samples`, defaulting to one; the existing Record `state` and ordered Questions inputs. The maximum count is 2^32, so the largest zero-based sample index fits `u32`; RunLimits normally imposes a smaller executable ceiling.

## Outputs

For one sample, the existing `answers: Answers` and `model: Text` ports. For more than one sample, `answers: List<Answers>`, `models: List<Text>`, and `disagreement: Degree` ports. Both lists have exactly `k` Datum items in ascending sample-index order. At index `i`, each item's ItemId is the canonical decimal string for `i`: ASCII digits, no sign and no leading zero except `"0"` itself. The answer and model items with the same ID describe the same response. The repeated ports replace the singular ports for that node and are checked at compile time.

## Behavior

The compiler SHALL reject zero, noninteger or unrepresentable counts and refuse a graph binding to a port absent for its declared count. It SHALL preserve the one-sample operation's existing serialized form when `samples` is omitted or one; any explicit one is normalized to omission on serialization. A repeated Ask is one graph node that sends the same Record and Questions for all samples. Using Map over indexed inputs is not equivalent because indices would change the model state and provider request identity. Explicitly mapped work remains separate from repeated Ask semantics.

Each answer/model item SHALL inherit the same sorted, deduplicated SourceRef union from the Ask's state and questions inputs, using the existing Datum source inheritance rule. The ItemId is sample identity, not a SourceId; it SHALL NOT be inserted into the provider state or source set. The enclosing output Datum keeps its existing node-port identity and inherited sources. Typed JSON export/import SHALL retain item IDs, order, values and SourceRefs exactly; plain JSON arrays retain order but do not claim to carry Datum identities.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-075-AC-1 | YAML and JSON with `samples: 3` compile to ordered repeated answer/model lists and Degree disagreement; a singular-port binding refuses at compile time. | Test (IT-014) |
| FR-075-AC-2 | Omitted and explicit `samples: 1` compile to the existing singular ports and serialize to the legacy Ask form; zero, fraction, overflow and unknown Ask fields refuse. | Test (IT-014) |
| FR-075-AC-3 | Three samples use identical state and ordered questions; no sample index enters the Ask's model state or provider payload. | Test (IT-014) |
| FR-075-AC-4 | k=3 yields answer and model ItemIds exactly `"0"`, `"1"`, `"2"` in that order; corresponding IDs carry one response's answer and actual model, with identical inherited SourceRefs, and typed JSON round-trip retains IDs/order/sources. | Test (IT-014) |
