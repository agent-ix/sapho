# FR-082: Apply a typed calibration map explicitly in a graph

## Description

When a graph requests calibration, the compiler and runtime SHALL apply a checked map to a raw Probability through an explicit operation and expose a distinctly typed result.

## Inputs

`calibrate` has `value: Probability` and `map: CalibrationMap` inputs and no operation parameters. `calibrated_as_probability` has `value: CalibratedProbability` and no operation parameters. Both expose `result` ports.

## Outputs

`calibrate.result: CalibratedProbability`; `calibrated_as_probability.result: Probability`, carrying the same unit-range number. Errors retain the existing partial node trace. The calibrated output Datum inherits both resolved inputs' SourceRefs under the ordinary node-output rule.

## Behavior

The compiler SHALL reject CalibratedProbability at an ordinary raw Probability port, including `compare`, `degree`, `calibrate` input and a raw-Probability typed literal. It SHALL reject Probability at a CalibratedProbability port. `calibrated_as_probability` is the only built-in conversion to a raw Probability port; it copies the scalar explicitly, without claiming to invert calibration or restore the original raw model value. A direct CalibratedProbability graph output retains its distinct type for inspection and scoring. A visible conversion node is required before existing Probability comparisons or degree conversion.

The runtime SHALL validate the map and input, return the table's calibrated value exactly at a raw knot, use the first/last calibrated knot value for inputs below/above the observed raw range, and linearly interpolate between adjacent raw knots with `y0 + (p-x0)*(y1-y0)/(x1-x0)` otherwise. It SHALL bound floating output to `[0,1]` after finite calculation. The resulting function is nondecreasing because knot values are nondecreasing. Raw input outside `[0,1]` refuses through core Probability validation; malformed map literals refuse before runtime evaluation.

Embedding or changing the map literal SHALL change the graph's versioned semantic identity under draft FR-063 (SAPHO-25 PR #33). The map's `fit_graph_semantic_identity` continues to identify the raw source graph, so the calibrated graph has a different digest without changing the recorded model request when only downstream map/application nodes were added. Exact replay of the original Ask then succeeds; the graph does not rerecord, refit or reinterpret provider probabilities.

`calibrate` SHALL remain a pure numeric operation: it reads only Probability and CalibrationMap inputs, not backend configuration, model names or trace.

The stock CLI performs the separate FR-084 post-run identity check. A custom Rust host that presents the result as fitted calibration SHALL compare the map's binding and reported model with the contributing trace evidence; `CalibratedProbability` alone does not certify that match.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-082-AC-1 | A two-knot map `(0.05,0.2),(0.95,0.8)` returns 0.2 and 0.8 exactly at knots, 0.5 at raw 0.5, and constant 0.2/0.8 outside the knot range; outputs are monotone. | Test (IT-017) |
| FR-082-AC-2 | `sapho inspect` reports `calibrated_probability`; direct connections to raw Probability/Number/Degree ports refuse, while `calibrated_as_probability` explicitly permits an existing Probability comparison. | Test (IT-017) |
| FR-082-AC-3 | Changing only the typed map literal changes `graph_semantic_identity`; both calibrated graphs replay the same recorded Ask request/response without ReplayMiss and produce different calibrated values. | Test (IT-017) |
| FR-082-AC-4 | Out-of-range raw input, invalid map type or malformed map literal refuses with a structured error and partial trace; source attribution follows the two inputs. | Test (IT-017) |
