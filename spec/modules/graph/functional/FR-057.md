# FR-057: Declare isolated shadow asks and observations

## Description

The graph compiler SHALL accept explicitly declared shadow asks as observation work that cannot supply a decision output or a decision-node operand.

## Inputs

A GraphSpec with an `ask`-compatible `shadow_ask` node, its named backend, `state` and `questions` bindings, and one or more observation declarations. Each observation names a decision output label, a question ID, a projection kind (`boolean` or `probability`), and the outcome labels used by the existing probability projection. Boolean projection also declares a finite threshold in [0, 1]. Its predicted value is true exactly when projected P(true) is greater than or equal to that threshold; Probability projection retains P(true).

## Outputs

A compiled decision graph and a separate, ordered shadow-work plan; malformed connections return a structured compile refusal.

## Behavior

The `shadow_ask` SHALL accept the same typed `state` and `questions` inputs as `ask`.

The `shadow_ask` SHALL use its own declared backend and questions.

It receives the same graph input item; the request need not be byte-identical to the champion's request.

A shadow observation SHALL name an existing decision output so both predictions use that output's one curated label for a case.

The compiler SHALL reject duplicate shadow IDs, duplicate observation names within a shadow, unknown decision outputs, invalid thresholds, incompatible projected value types, and any decision binding or guard that depends on a shadow node.

The compiler SHALL allow shadow `state`, `questions` and guard bindings only from graph inputs, typed literals, or producer nodes whose transitive dependencies contain no ordinary `ask` or `shadow_ask` node.

The compiler SHALL allow an ask-free producer to feed both champion and shadow paths.

When a shadow binding reads champion answers, a decision output, or any value derived from an ask, the compiler SHALL refuse the graph before inference with a typed error naming the shadow node and offending producer.

A shadow node SHALL expose no graph output port; its projected values belong only to the observation report.

Existing `ask` graphs retain their serialized shape and compile behavior.

## Acceptance Criteria

| ID | Criteria | Verification |
|----|----------|--------------|
| FR-057-AC-1 | A graph with one champion `ask` and one shadow ask compiles; inspection identifies the shadow backend and its observation-to-decision-output mapping without changing the decision output signature. | Test |
| FR-057-AC-2 | A decision output or decision-node operand bound to a shadow node is refused at compile time with a typed error naming the shadow node. | Test |
| FR-057-AC-3 | Unknown output names, duplicate observation names, invalid thresholds and a projection type incompatible with the mapped decision output are refused before inference; a question ID absent from dynamically supplied Questions fails only that shadow observation at runtime. | Test |
| FR-057-AC-4 | Replacing the shadow backend and champion backend in graph and binding configuration requires no provider-specific graph operation or source change. | Test |
| FR-057-AC-5 | Shadow state/questions/guard bindings from graph inputs, literals and a shared ask-free producer compile; a direct or transitive binding from champion Answers or another ask is refused before inference, naming the shadow and producer. | Test |
